# 라이브 멀티뷰

## 소유권

| 파일                | 책임                                                            |
| ------------------- | --------------------------------------------------------------- |
| `model.js`          | 채널 URL·구성·분할 트리·자유 창·목표 딜레이·가용 탐색 범위 계산 |
| `view.js`           | DOM 생성과 조작 바인딩 도우미                                   |
| `playback.js`       | 메인/보조 플레이어·미디어 이벤트·HLS·딜레이/화질 저장 큐        |
| `layoutControls.js` | 배치·드래그·리사이즈·포인터/키보드 수명                         |
| `settingsPanel.js`  | 설정 패널·닉네임 검색·목록 조작·focus 복원                      |
| `runtime.js`        | 옵션·라우트·mount와 각 모듈의 조립                              |

메인 영상·채팅·방송 정보는 치지직 라우터와 원본 플레이어가 소유해요. 메인 DOM을 다른 부모로 옮겨 별도 앱처럼 만들지 않아요. 이 모듈은 채팅 멀티뷰·메인 자동 화질·시청 기록 저장을 새로 구현하는 장소가 아니에요.

## 미디어·설정 경계

- 기본 옵션은 꺼짐이며 사용자가 켜고 저장할 때 필요한 CDN 선택 권한을 처리해요. 현재 메인 포함 6개·중복 채널 방지와 올바른 HTTPS live URL 검증을 유지해요.
- 메인 변경은 치지직 이동을 통해 큰 영상·URL·제목·채팅을 같은 방송으로 맞춰요. 보조 영상만 바꾼 상태를 메인 변경 완료로 표시하지 않아요.
- 보조 HLS는 패키지의 라이브러리와 검증된 실제 LLHLS/HLS 소스를 사용해요. 원격 실행 코드·iframe·새 창을 재생 실패 대체로 추가하지 않아요. worker 비활성 설정을 임의로 바꾸지 않아요.
- 네이티브 메인과 보조 HLS의 시간축을 같은 값으로 단정하지 않아요. 메인의 0초 목표는 네이티브 기본 라이브 위치라 켜기·소스 교체 때 메인 재생 위치를 옮기지 않아요(양수 저장 딜레이 복원은 유지). 현재 측정 딜레이·저장한 목표·적용 상태를 분리하고, 관측 전·오래된 표본·오류를 0초로 표시하지 않아요.
- 딜레이 적용은 탐색이 끝난 첫 완료 이벤트(`seeked`·탐색 중이 아닌 `timeupdate`)에서 판정해요. 지금 위치에서 실제 도착 뒤 재생이 나아갔을 수 있는 진행 범위를 빼 도착 위치의 범위를 되짚고, 범위 전체가 목표 ±0.75초 안이면 '적용 완료', 전체가 밖이면 '적용 불가', 걸치면 '적용 확인 불가'로 남겨요. 확인 불가에서도 다시 탐색하지 않아요. 탐색 대기 시간은 재생 진행이나 허용 오차로 세지 않아요. 탐색 중에는 100ms 간격으로 `seeking`을 지켜보고, 제때(직전 관찰에서 250ms 안) 실행된 관찰로만 재생 재개 시각의 하한을 올려요. 관찰은 판정·탐색 교체·영상 교체 때 스스로 멈춰요.
- 진행 범위는 알림으로 확인한 이력만 쓰고, 판정 때의 재생 상태·배속을 과거 구간에 소급하지 않아요. 완료 이벤트의 `timeStamp`는 탐색 요청 이후이고 현재보다 앞설 때만 완료 시각으로 써요. 탐색 중 받은 `ratechange`가 있거나 배속을 모르는 구간의 최대 진행은 Chrome 최대 배속(16)으로 잡고, 탐색 중 받은 `play`는 그 구간을 재생했을 수 있다는 근거로 써요. 유한한 0 이상의 배속은 그대로 써서 0 배속은 재생 중이어도 진행이 0이에요. NaN·음수·Infinity는 1배속으로 가정하지 않고 모르는 배속으로 봐요. 최소 진행은 완료 시각을 쓸 수 있고, 완료 뒤 변경이 없다고 확인됐고, 판정 때 재생 중이며 재생 데이터가 있고 배속을 알 때만 완료 뒤 경과×배속으로 잡아요. 그 밖에는 0이에요.
- 완료 뒤 어떤 변경이 있었든 결론이 같으면 바로 확정해요. 아니면 판정을 보류하고, 판정 시각 뒤에 만든 미디어 알림이 오거나 100ms 타이머가 지나면 확정해요. 그 사이 `pause`·`play`·`ratechange`·`waiting`이 오면 최소 진행을 0으로 넓히고, `seeking`(다른 탐색)이 오면 그 자리에서 확정한 뒤 '재생 위치 변경'으로 표시해요. 보류한 판정은 같은 플레이어·같은 video의 현재 탐색일 때만 확정하고, 딜레이 변경·영상 교체·`emptied`로 탐색이 바뀌면 버려요.
- 근거와 미실측 전제: 2026-10-30 Chrome 155 보조 HLS 실측(정체·배속은 측정 코드가 주입)에서 페이지가 1.2초 멈춘 동안 `seeking`·`currentTime`은 목표에 머물렀지만 재생은 이어졌고, 한 요소의 미디어 알림은 만든 순서대로 전달됐으며 `timeStamp`는 알림을 만든 시각이었어요. 0 배속은 받아들여 `paused=false`에서도 위치가 그대로였고, 16 초과·음수는 `NotSupportedError`였어요. 100ms 타이머가 그보다 먼저 큐에 들어간 미디어 알림을 앞지르지 않는다는 점, 숨은 탭·재버퍼링·0.75초를 넘는 자연 탐색과 0 배속 수정 뒤 코드의 Chrome 실행은 미실측이에요. 확인 불가 상태 문구('적용 확인 불가 · 다시 적용 가능')는 아직 결정 대기예요.
- 가용 탐색 범위 밖 목표를 성공처럼 표시하거나, 사용자의 pause를 무시하고 재생하지 않아요. 관측 변동을 새 목표에 누적하거나 반복 저장하지 않아요.
- 보조 화질은 실제 제공 level만 고르고, 저장한 해상도가 없으면 현재 자동 선택 계약을 따라요. 저장 실패와 재생 적용 실패를 구분해요.
- 채널별 딜레이·보조 화질은 확장 local, 구성·볼륨·배치·자유 창은 탭 sessionStorage예요. 한 탭의 구성 선택을 다른 탭의 구성으로 덮지 않아요.
- 옵션 OFF·라우트 이탈·플레이어 교체 시 이전 HLS·요청·미디어 이벤트·포인터 자원을 정리해요. 늦은 fetch·선택·저장 응답이 다음 플레이어를 갱신하지 못하게 해요.

## UI와 조작

자유 창은 포인터와 키보드로 이동·크기 조절할 수 있어야 해요. 취소 조작·focus·앞뒤 순서·화면 경계를 유지하고, 전체화면 동안의 임시 배치와 저장된 자유 배치를 구분해요. drop 대상을 입력칸·편집 영역·설정창까지 넓히지 않아요. 자유 배치의 페이지 전체 놓기는 다른 기능이 먼저 받은(`defaultPrevented`) 놓기와 다른 확장 기능의 놓기 대상(팔로잉 폴더의 `data-bcff-list`·`data-bcff-new-zone`, 채팅 멀티뷰 패널)을 받지 않고 그 이벤트 전파도 막지 않아요. 이 표식이 바뀌면 `runtime.js`의 `OTHER_DROP_TARGETS`도 함께 바꿔요. 저장한 자유 창은 사용자가 만든 겹침까지 그대로 두고, 자유 창이 없는 방송(목록에 없는 방송으로 이동해 메인 자리를 내준 이전 메인 등)만 다른 자유 창이 덮지 않은 배치 칸에 놓아요.

닉네임 검색은 입력 변경·닫기·라우트 변경·비활성화 때 중단해요. 결과는 검증한 채널 정보로 표시하며 검색어·결과를 영구 저장하지 않아요. 설정 패널을 닫거나 새로고침했다고 원래 채팅·팔로잉 컨트롤을 재부모화하지 않아요.

## 검증

`tests/live-multiview.test.js`에서 채널·구성·저장·범위·광고·버퍼·메인 변경·리사이즈·자유 배치·취소·측정 대기·화질과 딜레이 탐색 판정(도착 범위, 판정 보류와 확정, 완료 대기 중 일시정지·배속 변경·다른 탐색, 0 배속·쓸 수 없는 배속)을 확인해요. `tests/content-route-utils.test.js`와 `tests/extension-pages.test.js`에서 공용 메인 판별이 보조 영상을 제외하는지도 확인해요. 테스트 라우터·가짜 미디어 객체의 성공은 실제 Chrome의 채팅 전환·디코딩 성공이 아니므로 브라우저 검증을 분리해요.
