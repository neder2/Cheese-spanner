# 채널 다시보기 검색 데이터

## 책임

`model.js`는 영상·댓글 정규화, 제목·댓글 검색 일치, 실제 제공된 시청 진행률 계산을 소유해요. `repository.js`는 채널 인덱스·댓글 조회·캐시·요청 세대·스케줄을 소유해요. 상위 `videoSearch.js`가 옵션·검색 입력·원본 카드·결과 DOM·focus와 위치를 관리해요.

repository에 DOM이나 네이티브 스타일을 넣지 않아요. model은 현재 검색 UI의 상태·네트워크·저장소를 소유하지 않아요. 댓글 쓰기·반응 API, 시청 기록 영구 저장은 이 모듈의 책임이 아니에요.

## 유지할 조건

- 페이지 상한 안의 검색과 전체 조회 완료를 구분해요. 실패한 인덱스 일부를 완성 캐시로 저장하지 않고 다음 검색에서 회복할 수 있어야 해요.
- 채널별 캐시의 상한·유효기간과 repository 인스턴스 간 독립성을 유지해요. 입력·채널·옵션 변경 뒤 늦은 응답이 새 인덱스나 진행 상태를 덮지 않게 해요.
- 댓글 조회는 설정된 영상 수·페이지·대기·동시성 범위를 지켜요. 정리 뒤 늦은 댓글 응답이 비운 필드를 다시 채우지 않아야 해요.
- 여러 줄 댓글의 검색 의미를 보존해요. 댓글 API의 알려진 필드를 읽고, 임의로 모든 중첩 문자열을 댓글로 수집하는 폴백을 추가하지 않아요.
- 진행률은 관측된 영상 길이와 재생 진행 값으로 계산해요. 불명확한 숫자 필드·일반 offset을 다른 목적의 값과 혼동해 가짜 진행률로 만들지 않아요.
- 로딩·완료·오류 callback은 현재 요청의 상태만 알리고 같은 작업을 화면과 repository 양쪽에서 예약하지 않아요.

## 검증

`tests/refactoring-data-modules.test.js`에서 여러 줄 검색·실제 진행률·독립 캐시·취소·댓글 초기화를 확인해요. `tests/navigation-data.test.js`는 인덱스 유효기간과 네이티브 색 동기화, `tests/extension-pages.test.js`는 댓글 deviceId·가짜 폴백 방지·조회 실패 후 복구를 보호해요. UI 수명·중복 예약은 `tests/dom-scheduling.test.js`도 확인해요.
