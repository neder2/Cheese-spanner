# 방송 목록 데이터·탐색

## 책임

`filterModel.js`는 단위·프리셋·포함 범위와 정확한 카테고리 제외 판정을 소유하고 UI 상태·설정을 자체로 저장하지 않아요. `repository.js`는 목록 커서·메타데이터·팔로워·카테고리 이름 요청과 bounded 캐시를 소유해요. `searchController.js`는 추가 탐색의 실행·대기·취소를 조정해요. DOM 카드와 toolbar·제외 선택 UI는 상위 `categoryTools.js`가 소유해요. 지속 선택의 검증·실제 저장은 공용 categoryExclusions와 서비스 워커의 전용 큐가 맡아요.

여기에 DOM 조작·네이티브 카드 복제·옵션 폼을 넣지 않아요. 상위 화면에서도 별도 페이지 조회·캐시·반복 타이머를 만들어 같은 일을 중복 소유하지 않아요.

## 유지할 조건

- 전체 라이브·카테고리 라이브·영상·클립의 endpoint, 항목 ID와 커서 형태를 구분해요. 0인 커서값을 없는 값으로 버리지 않아요.
- 같은 진행 페이지는 요청을 공유해요. 동일한 경로로 reset했더라도 이전 세대 응답이 새 상태를 덮지 못하게 해요.
- 실패·타임아웃·상한 도달·완료 상태를 구분해요. 메타데이터 재시도는 기존 bounded backoff와 취소를 지키며 새 무제한 반복을 추가하지 않아요.
- 팔로워 0명과 미조회·조회 실패는 다르게 캐시해요. 상한·실패 캐시 만료를 유지해요. 채널 수는 경로 독립 자료여서 기존 bounded 캐시를 이동마다 무조건 지우는 것도 계약 변경이에요.
- 조회 batch·동시성·간격은 설정을 따르고, 화면 바깥 결과를 위해 무한 페이지 탐색하지 않아요. 로딩 중 새 요청은 동일 탐색을 다시 시작하지 않아요.
- 범위는 양끝 포함이며 드래그 방향에 따라 달라지지 않아요. 모델의 누락 숫자 처리와 화면의 ‘확인 중/조회 실패’ 표현은 구분해요.
- 전체 라이브 집계는 liveId로 중복을 제거하고 시청자 10명 이상이라는 현재 집계 범위를 표시해요. 사이트 전체의 완전한 총계로 바꾸지 않아요.
- `globalLiveCountEnabled`는 검색·필터와 독립이에요. 집계만 켜면 검색 UI·배지·카드 변경·태그 검색 숨김을 실행하지 않아요. 어느 한 기능을 끌 때 다른 소비자가 사용하는 페이지 요청은 보존해요.
- 전체 방송의 공유 페이지는 제한된 캐시를 사용하고, 집계로 읽은 연속 페이지도 검색 메타데이터에 한 번만 반영해요. 집계 캐시가 만료된 뒤 오래된 자료에 새 시각만 붙이지 않아요. 직접 제거된 toolbar는 복구하되 자체 삽입·옵션 OFF가 다시 예약을 만들지 않도록 확인해요.

- 전체 방송의 현재 목록 검색은 입력 초안과 적용 검색어를 분리해요. 적용 버튼·Enter에서만 갱신하고 IME 확정 Enter·반복 키·동일 값 재제출은 새 작업을 만들지 않아요. 지우기는 초안만 비우고 Escape는 적용값으로 되돌려요. 카테고리 경로의 기존 입력 검색과 숫자 필터·카테고리 이름 검색은 유지해요.

## 카테고리 제외

- 적용·조회·UI는 기존 `categoryToolsEnabled`가 켜진 `global-lives`에 한정해요. 인기·최신·추천의 현재 원본 카드에 적용하되 최신·추천에 인기 API 결과를 주입하지 않아요. 집계만 켠 상태나 다른 경로에서는 제외 목록·이름 검색을 요청하지 않아요.
- 최초 옵션 `getOptions` 완료 전에는 기본값이나 일반 옵션 변경 콜백만으로 제외 조회·구독·UI를 시작하지 않아요. DOM 준비와 옵션 준비를 구분하고 공용 진행 읽기를 공유해 중복 sync 조회를 만들지 않아요.
- 유형·ID의 정확한 쌍으로 판정해요. 이름·태그·제목의 부분 일치, ID 대소문자 변환과 확인되지 않은 소문자 유형 호환 분기를 추가하지 않아요. 원본 카드는 현재 카테고리 링크를 우선하고 링크 없음·충돌을 오래된 API 값으로 메우지 않아요. 추가 카드는 채널·liveId binding이 일치하는 메타데이터로 판정하고 템플릿의 옛 링크·이름을 남기지 않아요.
- 메타데이터 후보와 추가 카드 모두 비어 있지 않은 id·channelId 일치와 양의 안전 정수 liveId를 요구해요. 결측·0·음수·소수·안전 범위 초과 liveId는 제외 판정에서 통과시켜요. 원본 카드의 현재 유효 링크 판정은 API liveId 결측과 독립이에요.
- 시청자 필터의 기존 표시 보존 행에도 제외를 AND 조건으로 적용해요. 원본 href 변경·행 재사용·순회 중 정체성 변경을 마지막 표시 전에 다시 확인하며 확장 소유 변경은 반복 예약을 만들지 않아요. 제외한 후보의 불필요한 팔로워 조회도 막아요.
- 이름 검색은 keyword·size 50만 보내고 응답의 세 카테고리 필드를 검증해요. 검색어는 최대 100자, 결과는 최대 50개, 메모리 캐시는 최대 20개 검색어·5분이에요. 동일 입력의 진행 요청을 공유하되 취소·실패 결과가 캐시를 채우지 않아요. 검색 후보 상세의 정확한 유형·ID와 concurrentUserCount로 내림차순 정렬하고 확인된 0명 후보만 제외해요. 수치 미확인은 뒤에 남기며 기존 저장 선택은 보존해요. 상세 조회는 동시 4개·각 3초·전체 5초, 정상 수치 캐시는 200개·5분으로 제한해요. 상위 UI의 300ms 대기·한글 조합·닫기·SPA·OFF 취소는 선택 목록 삭제와 구분해요.
- 선택은 현재 소유 버튼의 `isTrusted` 클릭과 isolated 처리 함수의 카테고리 자료로만 개별 요청해요. 합성 키·클릭, 복제한 버튼과 바뀐 DOM 속성으로 저장 명령을 만들지 않아요. 콘텐츠 전체 배열 저장은 추가하지 않아요. 저장 성공·검증한 local 변경 이후 반영하고 늦은 revision과 실제 키 삭제 전 응답을 차단해요.
- 마지막 정상 상태는 오류 중 보존하지만 새 구독의 첫 정상 읽기·변경을 새 기준으로 받아 OFF 중 놓친 삭제·재생성도 복원해요. 구독 함수의 현재 소유를 확인하고 손상 변경 알림에서 이전 읽기·변경·대기를 무효화해 늦은 콜백이 오류·재시도를 지우지 못하게 해요. 빈 상태·검색 해제·오류 해제에서는 상태 문구도 실제로 비워요.
- `필터 초기화`는 숫자 조건만 해제하고 숫자가 없으면 비활성화해요. 제외 목록·메뉴 검색 캐시·집계 설정을 초기화에 묶지 않아요. OFF·이동·닫기는 UI·검색 예약을 정리하며 선택을 지우거나 늦은 변경 응답으로 옛 메뉴를 다시 만들지 않아요.

## 검증

`tests/category-tools-filter-model.test.js`는 단위·프리셋·범위, `tests/category-tools-repository.test.js`는 커서·공유·중복·캐시·상한·취소·재시도를 보호해요. `tests/category-tools-lifecycle.test.js`는 오래된 팔로워 결과가 재사용 카드에 붙지 않는지, 검색과 배지가 서로 지연시키지 않는지, disable·SPA가 예약을 끝내는지 확인해요. 통합 목록 동작은 `tests/extension-pages.test.js`, 중복 예약은 `tests/dom-scheduling.test.js`에서도 확인해요.

제외 변경은 `tests/category-exclusions-store.test.js`, `tests/category-tools-exclusions.test.js`와 filter-model·repository에서 두 탭의 개별 변경·지속 복원·상한·실패 보존·정확한 정체성·신뢰한 버튼·검색 취소를 확인해요. 공용 선행 로드를 바꾸면 lifecycle·extension-pages·refactoring-data-modules의 실제 로드도 맞춰요. 실제 Chrome의 이름 검색 요청·현재 카드 링크·SPA 발신 URL·기본 Enter/Space·두 테마·새로고침과 재시작은 자동 fixture와 별도로 확인해요.
