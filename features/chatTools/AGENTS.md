# 채팅 파싱·수집·패널

## 소유권

`parser.js`는 현재 DOM에서 작성자·본문·역할·원문 후보를 읽는 무상태 파서예요. `messageStore.js`는 행 binding, 메시지 정체성, 블라인드 원문 캐시, 수집·읽음·재사용 안정화를 소유해요. `panel.js`는 DOM·필터·선택·스크롤·노출 판정을 소유해요. 상위 `chatTools.js`가 옵션·채팅 루트 수명주기를 조립해요.

파서는 영구 행 ID나 수집 marker를 만들지 않아요. 패널은 store의 binding을 직접 고치지 않고 읽음·원본 이동 명령을 전달해요. 영구 본인 채팅·후원 저장, 타임스탬프의 MAIN React 조회, VOD 댓글은 이 모듈의 책임이 아니에요.

## 유지할 조건

- DOM 노드·닉네임·동일 본문만으로 새 메시지를 확정하지 않아요. ID·작성자·재사용 신호·mutation revision을 함께 사용해요.
- 혼합된 재사용 후보가 오래 남았더라도 같은 세대의 최종 상태가 일반 시청자면 잘못 수집한 후보를 철회할 수 있어야 해요. 대기시간 증가로 이를 대체하지 않아요.
- 같은 작성자의 실제 반복 메시지는 유지하고, 같은 메시지 재마운트는 중복 수집하지 않아요. 원본 이동은 실행 시 현재 binding을 확인해요.
- 블라인드 원문은 MAIN 브리지가 현재 행의 가장 가까운 `chatMessage`에서 읽은 값을 먼저 쓰고, 없으면 DOM 원문·캐시로 넘어가요. 응답 속성은 요청 전후로 지우고 DOM 원문 후보로 읽지 않아요.
- 원문 캐시는 메시지와 작성자가 일치하는 경우에만 사용해요. 새 ID·다른 작성자·이전 루트의 원문을 섞지 않아요. 캐시 상한과 reset을 유지해요.
- onChange 스냅샷은 DOM 참조 없는 수집 결과예요. 패널이 수정해 store 상태를 바꾸는 공유 객체를 만들지 않아요.
- 읽음은 현재 필터에서 실제 보이는 항목에만 적용해요. 닫힌 패널·숨은 탭·화면 밖은 미확인이에요. capacity 정리 시 사라진 메시지의 알림도 함께 정리해요.
- capacity로 목록에서 밀려난 메시지는 원본 행 binding과 별도 정체성 목록(최대 500개)에 남겨요. 같은 root 재그리기·목록 비움 뒤 재수신·root 교체에서 같은 백로그 행은 그 메시지에 다시 붙고 새 미확인 기록으로 돌아오지 않아요. 재마운트 후보를 보관 개수로 자르지 않아요. 채널 정리 때 함께 비워요.
- 본문 요소 안의 이미지(이모티콘)는 DOM 순서대로 `[이모티콘:이름]` 토큰으로 본문에 남겨요. 이름은 alt/title, 없으면 검증한 `https://*.pstatic.net` src의 파일 이름이고, 둘 다 없으면 `[이모티콘]`이에요. 파일 이름을 원문 코드 `{:이름:}`로 간주하지 않아요. 닉네임 영역 배지와 역할 단어 alt/title 이미지는 토큰으로 쓰지 않고, 닉네임·역할·숨은 원문 판정은 이미지 없는 `getVisibleText`를 써요.
- 표시 토큰은 이름을 줄여 서로 다른 이미지가 겹칠 수 있으므로, 행 정체성·binding·재마운트·재사용 비교는 `parsed.textKey`(토큰마다 원래 alt·title·src를 DOM 순서대로 포함, 이미지가 없으면 `text`와 같음)로 해요. `textKey`는 표시·복사·기록에 쓰지 않아요. 이름도 src도 없는 본문 이미지가 있는 새 운영자 행은 재사용 후보와 같은 안정화 확인을 거쳐 마지막 상태로 한 번만 기록해요.
- 재마운트 후보는 한 번의 재마운트 묶음 안에서만 쓰고 행의 문서 순서대로 소비해요. 묶음은 제거·추가 한 번, root 교체 한 번, 또는 목록 비움 한 번이에요. 비운 목록은 행별 제거 레코드로 여러 번 나뉘어 와도 같은 root에서 다음 첫 hydration(실제 행을 처리한 scan)까지 같은 묶음으로 이어 쓰고, 그 scan이 공용 후보를 비우므로 그 뒤의 비움은 새 묶음이에요. 비운 목록의 후보를 한 행이 가져가면 같은 묶음에서 그보다 앞선 후보는 다시 받은 백로그에 없는 것으로 보고 버려요. 이 앞뒤는 제거 레코드를 처리한 순서이고, 실제 치지직이 목록을 비울 때의 레코드 순서가 문서 순서(위→아래)라는 전제는 미실측이에요.
- 안정화를 기다리는 재마운트 행(이름·src가 아직 없는 본문 이미지 등)은 그 scan에서 자기에게 맞는 후보를 행·세대(transition)에 맡겨 최종 확인에서만 쓰고, 행 제거·root 변경·SPA·OFF로 transition이 취소되면 함께 버려요. 앞쪽 대기 행이 같은 묶음의 후보를 맡고 있으면 뒤 행은 동기 확정이든 먼저 안정화됐든 그 행이 확정되거나 취소될 때까지 후보를 가져가지 않아요. 본문 이미지의 `src`만 바뀌어도 이미 수집한 행과 직전 파싱이 역할 행이었던 행(binding 없는 안정화 대기 행 포함)은 다시 처리해요.
- 역할은 배지·확인된 역할 구조에서 판단해요. 본문·프로필 팝업·sr-only 설명의 역할 단어를 닉네임·본문·수집 근거에 섞지 않아요.
- 한 mutation 배치에서 변경 행을 모으고 최종 목록을 한 번 표시해요. 새 행마다 전체 목록을 다시 파싱하거나 확장 marker가 observer 루프를 만들지 않아요.

## 회귀

`tests/chat-tools-modules.test.js`는 parser 무상태, 스냅샷 소유권, reset·재사용·교체 수명과 capacity로 밀려난 백로그의 재그리기·목록 비움·root 교체, 실측 이모티콘 본문(이미지 전용·혼합·배지 제외)의 토큰과 재마운트·재사용 정체성, 같은 표시 토큰의 다른 이미지(같은 파일 이름의 다른 경로·같은 alt/title의 다른 src) 분리, 순서·개수, 닉네임 배지 변경 대조, 늦은 src 채움, 로딩 중 본문 이미지 행의 재마운트(root 교체·같은 root 교체·비움 뒤 재수신, 같은 내용 반복, 로딩 행과 완성 행 혼합, 역순 안정화, capacity 퇴출)에서 기록 수·recordId·읽음·원본 이동 대상 보존, 앞 대기 행 제거·다른 내용 안정화 대조, 행별로 비운 목록의 반복 메시지 분리와 같은 순서 재수신을 확인해요. `tests/chat-tools.test.js`는 혼합 재사용 철회, 원문 캐시, 반복 메시지, 읽음·필터·복사·원본 이동, 루트 재마운트·증분 처리·옵션 OFF와 늦은 이모티콘 src의 단일 기록, observer를 거친 src 단독 변경 재파싱, 로딩 이미지 행 재그리기의 읽음 기록 보존, 한 observer 배치에서 행별로 비운 id 없는 목록의 반복 공지 분리를 보호해요. `tests/chat-blind-source.test.js`는 MAIN 브리지 원문의 최초·사후 블라인드, NORMAL·상위 메시지 배제, 남은 응답 속성 무시, 늦은 브리지 준비, OFF 정리를 확인해요. fixture를 닫기 전에 observer와 예약 콜백을 정리해요.
