## 구현과 자동 검증

- 기존 카테고리 도구의 메타데이터 페이지 요청을 공유하고 페이지 병합 시 방송 ID를 중복 제거한다. 숫자 집계 자체는 이미지나 플레이어를 로드하지 않는다.
- 시청자 10명 이상인 방송의 `concurrentUserCount`를 방송 수와 함께 합산한다. 별도 API 요청은 추가하지 않는다. 중복 방송은 마지막 조회값으로 교체하며, 마지막 값이 10명 미만으로 내려가면 방송 수와 합계에서 모두 제외한다.
- 화면에 `시청자 10명 이상 · 방송 N개 · 시청자 합계 M명`을 표시한다. 합계는 방송별 동시 시청자 수의 합이며, 여러 방송을 동시에 보는 사람을 구분한 고유 인원 수가 아니다.
- 10명 미만인 방송 또는 목록 끝에 도달하면 집계를 완료한다. 반복 커서와 200페이지 제한은 끝나지 않는 조회를 실패 처리하기 위한 상한이다.
- 완료 결과 한 건을 5분간 재사용한다. 화면 체류 중 주기 갱신은 하지 않으며 페이지·옵션 수명주기에서 진행 중 메타데이터 요청을 취소한다.
- 테스트는 10명 포함·9명 제외, 중복 값 갱신과 기준 미달 제외, 요청 공유, 두 집계의 캐시 만료, 빈 목록의 합계 0, 실패, 취소 후 늦은 응답, 합계의 천 단위 구분 표시, 도구 영역 재마운트와 옵션 비활성화를 확인한다.
- 시청자 합계 추가 후 `npm.cmd run test:all` 607개, `npm.cmd run lint`, `npm.cmd run format:check`가 통과했다.

## 실제 화면 검증 한계

아래 내용은 방송 수를 처음 추가했을 때의 기록이다. 방송 수와 검색 도구의 후속 브라우저 검증은 `category-tools-loading-verification.md`에 기록되어 있으며, 시청자 합계 표시는 이번 변경 후 별도 확인이 필요하다.

시청자 합계 추가 시에는 현재 Chrome 탭의 기존 방송 수 표시만 확인했다. 사용자가 추후 직접 새로고침하기로 했으므로 새 합계의 실제 화면 표시는 미검증이며, 데이터 합산과 표시 문구·재마운트는 자동 테스트로 확인했다.

- Chrome의 전체 방송 탭에서 기존 `betterchzzk-category-tools` 검색·필터 영역이 라이브·동영상 탭 오른쪽에 있는 것을 확인했다.
- 브라우저 도구가 `chrome://extensions/` 접근을 정책상 차단했다. 확장 재로드를 우회하지 않았으며 페이지 새로고침만으로 새 집계 표시가 나타나지는 않았다.
- 변경 코드의 실제 주입, 라이트·다크 및 좁은 화면의 배치, 실제 브라우저 요청 횟수·콘솔 상태는 미검증이다.
- 직접 확인: 확장 관리에서 Better Chzzk를 새로고침한 뒤 전체 방송 페이지를 새로고침한다. 방송 목록 도구가 켜져 있으면 검색창 옆에 집계 결과가 표시되어야 한다. 마우스를 올려 시각을 확인하고, 다른 페이지 이동·복귀와 도구 옵션 끄기를 확인한다.
