# 자유 배치에서 방송 링크를 포인터 위치에 추가

- 날짜: 2026-09-15 (KST)
- 브랜치·작업 버전: `1.3.8`
- 요청: 기존 영상 밖에서도 방송을 추가하고, 기본 보조 화면 크기의 미리보기가 포인터를 따라 움직이게 하기.

## 원인과 변경

방송 추가 이벤트는 플레이어 부모에만 연결돼 있었다. 자유 배치에서 그 부모는 페이지 전체 크기지만 빈 영역은 포인터 입력을 통과시키므로 사이드바·채팅·본문에서 발생한 드래그 이벤트를 받지 못했다. 추가 안내는 부모 전체를 채우는 크기였다.

- 활성 멀티뷰의 드래그 이벤트를 페이지에서 받고, 분할 배치는 기존 플레이어 영역으로 제한한다.
- 자유 배치는 페이지 안에서 받되 입력칸·편집 영역·멀티뷰 설정창은 제외한다.
- 원래 플레이어 영역과 기본 분할 비율로 보조 창 크기를 계산한다. 미리보기 중심은 포인터를 따라가고, 가장자리에서는 창 전체가 화면 안에 남도록 위치를 제한한다.
- 드롭할 때 같은 좌표를 새 창에 저장하고 앞으로 가져온다. 기존 창 위치·크기·재생은 유지한다.
- 드래그 중 보호된 URL 데이터를 읽거나 방송 조회를 시작하지 않는다. 실제 드롭에서 URL을 검증하고 기존 추가 경로를 사용한다.

## 자동 검증

회귀 테스트는 기존 구현에서 페이지 빈 공간의 드래그를 받지 못해 실패했고, 수정 후 통과했다. 포인터 이동 중 동일 미리보기 재사용, 기존 크기 변경과 무관한 기본 크기, 드롭·새로고침 좌표 일치, 가장자리, 취소, 입력칸, 파일, 재사용된 링크, 플레이어 교체, 중복 방송, 모드 해제·기능 비활성화를 검사했다. 기존 분할 배치 드롭 검사도 유지했다.

- 멀티뷰 테스트: 97개 통과
- 전체 `test:all`: 777개 통과
- `lint`, `format:check`, `git diff --check`: 통과

## 로컬 Chrome 검증

대상: `http://127.0.0.1:18769/live/aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa`

실제 방송을 재생하지 않는 UI fixture에서 브라우저의 실제 링크 드래그를 사용했다. 페이지는 `2560×1245px`, 원래 플레이어는 `900×506.25px`, 기본 보조 창은 `300×168.75px`였다.

- 다크 모드: 사이드바 링크를 기존 영상·채팅 밖의 `(1700,800)`에 놓았다. 마지막 미리보기와 추가된 창 모두 `(1550,715.625,300,168.75)`였고, 드롭 후 안내가 제거됐다.
- 라이트 모드: 같은 링크를 화면 왼쪽 `(40,700)`에 놓았다. 미리보기와 추가된 창 모두 `(0,615.625,300,168.75)`로 경계 안에 배치됐다.
- 이동 중 여러 포인터 위치에서 미리보기 크기가 일정했고, 실제 추가 전까지 기존 방송 구성은 유지됐다.

브라우저 도구의 확장 관리 페이지 접근 제한으로 수정 후 실제 확장 재로드·치지직 주입 검증은 하지 못했다. 확장을 다시 로드하고 치지직 탭을 새로고침한 뒤 자유 배치를 켜서 사이드바 방송을 빈 곳과 화면 가장자리에 놓는 직접 확인이 남아 있다.
