# 치즈 스패너 과거 후원 가져오기 — 2026-09-19

- 한 번에 최대 12개월, 저장된 가져온 내역 전체 최대 3,000개다. 같은 월은 완전히 조회된 최신 스냅샷으로 교체한다. 가져온 후원 삭제와 전체 삭제를 지원한다.

## 실제 서비스 확인

현재 [네이버 게임 프로필](https://game.naver.com/profile#cash)의 [공개 웹 앱 소스](https://ssl.pstatic.net/static/nng/resource/p/static/js/index-qAxZRRfp.js)를 2026-09-19에 조회했다.

- 실제 화면 호출: `GET https://api.chzzk.naver.com/commercial/v1/product/purchase/history`.
- 쿼리: `page`는 0부터, 화면의 `size`는 10, `searchYear`, `searchMonth`로 기간을 지정한다. 화면은 `content.data`와 `content.totalPages`를 사용한다.
- 화면에서 확인한 필드: `purchaseDate`, `payAmount`, `channelId`, `channelName`, `donationType`, `donationSubType`, `donationText`. `discountedAmount`는 할인 전 수량 안내에 쓰고 실제 사용량은 `payAmount`다.
- `CHAT`, `VIDEO`, `MISSION`, `MISSION_PARTICIPATION`, `TTS` 표시 분기를 확인했다. 파티 후원은 별도 조회 경로이므로 이번 조회에 포함하지 않는다.
- 비로그인 GET의 실제 응답은 HTTP 401, `code: 401`, `권한이 없습니다.`였다. 치지직·네이버 게임 Origin에서 각각 해당 Origin과 credentials 허용 CORS 헤더를 확인했다.
- 실제 확장 service worker에서 현재 권한만으로 해당 API의 401 응답을 읽었다. 반면 `comm-api.game.naver.com` 로그인 상태 조회는 확장 Origin에서 CORS로 실패했다. 이에 이미 허용된 치지직 탭의 isolated context에서 기존 로그인 확인 URL을 읽는다. 새 호스트 권한·쿠키 권한·API 키를 추가하지 않았다.
- **로그인된 사용자의 실제 구매 내역 성공 응답, 고유 구매 ID와 방송 ID는 미검증이다.** 응답 필드 계약은 현재 웹 화면 코드에 근거하며, 실제 계정 내역을 추측한 fixture로 설명하지 않는다. 현재 확인하지 못한 ID를 만들거나 실시간 메시지 ID와 동일하다고 가정하지 않는다.

## 저장·취소·계정 경계

- `shared/donationHistory.js`는 기간·응답 검증, 전체 페이지 수집, 월별 스냅샷 정규화를 담당한다. `shared/donationHistoryImport.js`는 history 페이지의 전용 runtime port, 로그인 확인과 API 요청을 담당한다.
- 가져오기는 시작·완료 때 같은 계정인지 확인한다. 이미 저장된 계정과 다르면 먼저 가져온 기록을 삭제하도록 안내한다. 로그인 쿠키·토큰은 추출하거나 저장하지 않는다. 계정 해시 ID만 혼합 방지에 사용한다. 시크릿 창에서 일반 프로필의 계정으로 조회하지 않도록 일반 창에서만 실행한다.
- 조회는 순차 처리하며 요청당 10초, 전체 2분, 최대 300회 요청과 3,000개 응답 행으로 제한한다. 여러 페이지가 있는 월은 마지막에 첫 페이지를 다시 확인해 조회 도중 목록이 바뀌었으면 저장하지 않는다.
- 여러 창의 동시 가져오기는 하나로 제한한다. 취소·port 단절은 진행 중 fetch를 중단한다. 저장 단계는 화면에 표시하고 취소 버튼을 비활성화한다.
- 전체 조회가 완료되고 계정까지 확인된 뒤에만 background의 기존 `enqueueWatchHistoryMutation` 큐로 `replaceDonationMonths`를 실행한다. 콘텐츠 스크립트뿐 아니라 history 페이지도 이 스냅샷 mutation을 직접 제출할 수 없다.
- 기존 `betterChzzkLiveWatchHistory` 안의 `donationImport`에 계정·월별 행·조회 시각을 저장한다. 삭제 시각 barrier로 삭제 전 시작한 늦은 가져오기가 기록을 되살리지 않게 한다. 서로 다른 실제 구매가 같은 시각·금액·본문을 갖는다고 합치지 않는다. 반복 가져오기의 중복 방지는 월 전체 교체로 처리한다.
- 모든 본문은 텍스트로 렌더링한다. 개인정보 문서와 README에 조회 항목·범위·보관 상한·삭제·수동 실행 방법을 반영했다. 스토어 공개 문구에도 사용자가 과거 본인 일반 후원을 선택적으로 조회해 로컬 저장한다는 내용을 배포 전에 반영해야 한다.
