# 스트림 정보의 플레이어 설정 메뉴 진입

- 날짜: 2026-09-15 (KST)
- 작업 브랜치: `1.3.8`, 시작 HEAD: `659ad7ff5782bea66cf2ce1d395a80b41f1fd83b`
- 요청 범위: 톱니바퀴 설정 메뉴에서 스트림 정보를 열고 닫도록 변경하고, 스트림 정보 우클릭 메뉴와 메뉴 키·Shift+F10 연결을 제거한다.
- 기본 켜짐 설정과 패널을 열었을 때만 조회·측정하는 동작은 유지한다.

## 현재 네이티브 메뉴 실측

- 라이브: https://chzzk.naver.com/live/4de764d9dad3b25602284be6db3ac647
- 다시보기: https://chzzk.naver.com/video/15195598
- 브라우저 API로 현재 페이지의 DOM과 computed style, 페이지 스타일시트를 읽었다. 사용자 컴퓨터의 네이티브 앱 조작은 사용하지 않았다.
- 두 페이지 모두 `.pzp-pc` 바로 아래에 `.pzp-settings.pzp-pc-settings.pzp-pc__settings[role="menu"]`가 있었다. 해상도·재생 속도 등의 하위 메뉴는 별도 형제 요소다.
- 톱니바퀴 버튼은 `.pzp-setting-button[aria-label="설정"]`이고 `aria-expanded`가 열림 상태를 나타낸다. 열면 플레이어에 `pzp-pc--setting`·`pzp-pc--setting-home`이 붙으며, `.pzp-pc--setting-home > .pzp-pc__settings` 규칙이 기본 메뉴를 표시한다.
- 기본 메뉴 행은 `.pzp-ui-setting-home-item[role="menuitem"]`이며, `__top` → `__left` → `__label` 구조를 사용한다. 현재 라이브의 라이트 테마에서 메뉴 배경은 `rgba(25, 25, 28, 0.7)`, 라벨 색상은 `rgba(255, 255, 255, 0.6)`이었다. 네이티브 CSS가 hover·focus·active와 작은 플레이어 크기의 행 높이·글자 크기도 처리한다.
- 라이브에서 메뉴를 열고 해상도 항목에 ArrowDown을 입력하면 숨겨진 항목을 건너뛰고 선명한 화면으로 포커스가 옮겨졌다. 새 항목 주입 후에도 라디오 모드의 ArrowDown은 해상도로, 해상도의 ArrowUp은 라디오 모드로 이동해 확장 항목을 건너뛰었다. 이를 보완해 확장 항목으로 들어오고 나가는 방향키·Home·End 이동만 연결한다. 네이티브 항목끼리의 이동과 Escape·Tab은 기존 동작에 맡긴다.

## 구현과 회귀 범위

- 확인된 기본 메뉴에만 확장 소유 버튼 하나를 추가한다. 네이티브 행의 클래스와 내부 구조를 재사용하고, 버튼의 배경·테두리 기본값만 조정한다. 네이티브 hover 규칙이 적용되도록 선택자 우선순위를 낮췄다.
- 스트림 정보 항목을 선택하면 열린 톱니바퀴 버튼을 눌러 네이티브 메뉴를 닫고, 기존 정보 패널을 열거나 닫는다. 네이티브 상태 클래스나 React/Vue 내부 상태를 직접 변경하지 않는다.
- 패널 상태에 따라 `스트림 정보 열기`·`스트림 정보 닫기`와 `aria-expanded`를 갱신한다. 패널을 닫으면 톱니바퀴로 포커스를 돌린다.
- 사용자 후속 요청에 따라 패널 하단의 작은 안내 문구를 삭제하고, 지표 이름을 `비트레이트`로 줄였다. `라이브 끝과의 차이` 항목과 계산을 제거하고 `남은 재생 버퍼`를 유지했다. 이에 맞춰 지연 표시 assertion을 제외하고 라이브·VOD의 버퍼 표시 검증을 유지했다.
- 기본 메뉴 재생성이나 확장 항목 제거 시 재부착한다. 메뉴만 바뀌면 기존 패널과 측정을 유지하고, 소스·플레이어 변경·SPA 이동·비활성화 시 기존 정리 경로를 따른다. 분리된 항목의 이벤트 listener를 제거한다.
- 우클릭 전용 테스트는 요청한 변경에 맞춰 우클릭·메뉴 키가 통과하는 테스트와 네이티브 설정 진입·포커스 테스트로 대체했다. 기존 통계·취소·조회 실패·페이지 수명주기 검증은 유지했다.
- 실제 MutationObserver를 쓰는 fixture로 메뉴 재마운트, 항목 단일 재부착, 분리된 버튼 무효화, 보조 플레이어 제외, 불필요한 메뉴 변경·플레이어 재조회·추가 네트워크 요청 부재를 확인한다.
- README, 확장 옵션 설명과 로컬 스토어 등록 문구를 톱니바퀴 조작에 맞췄다. 배포된 1.3.7의 변경 내역과 버전은 수정하지 않았다.

## 검증 상태

- 관련 검사: `node --test tests/stream-info.test.js tests/settings.test.js tests/options-page.test.js` 38개 통과.
- 최종 전체 검사: `npm.cmd run test:all` 746개, `npm.cmd run lint` 통과. 전체 `format:check`는 동시에 추가된 화면 확대 설정의 README 표 정렬 때문에 실패했다. 범위 밖의 표 전체를 다시 포맷하지 않았다. 변경한 런타임·테스트·옵션 HTML·실측 문서는 별도로 Prettier를 확인한다.
- 실제 확장 재로드는 브라우저 URL 보안 정책이 `chrome://extensions/` 접근을 차단했다. 다른 경로로 확장 관리를 우회하지 않았으며, 사용자가 직접 재로드와 치지직 탭 새로고침을 완료했다.
- 재로드 후 라이브에서 `#betterchzzk-stream-info-settings-item`의 실제 주입과 `스트림 정보 열기`를 확인했다. 이전 툴바 버튼·우클릭 메뉴 DOM은 없었다. DOM에 포함된 확장 폰트 URL에서 확장 ID `oijgeclpcafhkbaameifdomjononepol`을 확인했다. 브라우저 API가 isolated execution context 목록을 제공하지 않아 해당 context 자체는 별도 조회하지 못했다.
- 라이트 테마에서 네이티브 행과 새 행의 높이·padding·글꼴·배경·테두리가 일치했다. 사용자가 패널이 열리는 것을 확인했고, 브라우저 스크린샷에서도 패널과 `스트림 정보 닫기` 항목을 확인했다.
- 당시 콘솔에는 치지직 `player-vendor`·`index` 스크립트의 축약된 오류가 있었다. 조회한 로그에서 확장 소스 경로의 오류는 없었다. 전체 네트워크 로그의 정밀 검사는 수행하지 않았다.
- 이후 추가한 방향키 연결, 하단 문구 삭제·라벨 정리와 라이브 지연 항목 제거는 자동 테스트로 검증했다. 최종 코드의 다크 모드·전체화면·작은 플레이어·VOD 외관과 좁은 확장 설정 팝업은 실제 화면에서 미검증이다.

수동 확인 순서: 확장 다시 로드 → 치지직 탭 새로고침 → 톱니바퀴 설정 → 스트림 정보 열기·닫기. 영상 우클릭과 메뉴 키가 스트림 정보를 열지 않는지, Enter·Space·Escape, 옵션 껐다 켜기, SPA 이동 후 중복 여부도 확인한다.
