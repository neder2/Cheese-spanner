# 팔로잉 고정 초기 표시 조사 — 2026-09-16

- 작업 브랜치: `1.3.9`.
- 사용자 증상: 과거에 고정한 채널이 탭을 열었을 때 짧은 주기로 고정 해제·재적용되는 것처럼 몇 차례 깜빡였으며, 조사 시점에는 멈춘 상태.
- 대상 URL: `https://chzzk.naver.com/lives`.
- 사용자가 방송을 시청 중이므로 별도 Chrome 탭에서 조사했다. 시청 중인 탭의 새로고침이나 설정 변경은 하지 않았다.

## 관찰

- 현재 DOM은 `#sidebar nav[aria-label="팔로우"]` 아래 `ul > li` 구조이며, 구역과 전체 목록의 `aria-expanded`는 모두 `true`였다.
- 펼친 목록은 21행이었고, 고정된 오프라인 행에는 `data-bcsf-pinned="1"`, `data-bcsf-order-group="offline-pinned"`와 고정 표시가 있었다.
- 일반 상태에서 100ms 간격 12회 확인한 고정 행의 CSS `order`는 모두 `-1`이고 위치도 일정했다.
- 검증 탭 새로고침 후 80ms 간격 15회 샘플에서는 목록 등장 전 → 기본 순서(`order: 0`, 고정 마커 없음) → 고정 순서(`order: -1`, 고정 마커 있음)로 한 번 전환되는 과정이 관찰됐다.
- 이후 80ms 간격 15회 샘플에서는 고정 순서와 위치가 유지됐다. 이 간격의 샘플링은 프레임 단위의 변화나 모든 초기화 경로를 보장하지 않는다.

## 최초 조사 판단과 한계

- 초기 목록에 고정 표시가 나중에 적용되는 현상은 확인했지만, 반복 해제·재적용의 원인은 확정하지 못했다.
- 저장된 고정 값이 실제로 변경됐다는 증거는 없다. DOM 표시만 관찰했다.
- 반복 증상을 재현하지 못했으므로 런타임 수정이나 타이머·재시도 추가는 하지 않았다.
- 확장 재로드 및 수정본 주입 검증은 수행하지 않았다. 런타임 수정본은 없다.
- 재발 시 해당 탭의 초기 행 교체, 고정 마커·CSS 순서 변화, 옵션 및 저장 고정 목록의 초기 로드 순서를 함께 확인해야 한다.

## 코드 분석과 보완

- 펼친 목록의 행을 교체하면 새 행에 고정 마커가 없고, 기존 구현은 다음 RAF에서 정렬 속성과 아이콘을 복구한다. 초기 DOM 교체가 반복되면 고정 표시가 끊길 수 있다는 가설이다. 사용자 탭에서 실제 반복 교체가 발생했다는 증거는 아직 없다.
- 8행 JSDOM 목록을 세 번 교체하고 RAF 실행 전후를 비교하니, 매번 고정 마커·아이콘이 사라졌다가 복원됐다. 저장된 고정 값은 유지됐고 저장 호출은 0회였다.
- `sidebarCustomization.js`의 기존 오프라인 행 보정 경로를 고정에도 적용했다. DOM mutation 전달 시 변경된 행의 현재 링크를 다시 읽고 고정 표시·순서·접근성 상태를 복구한다. 목록 자체가 교체되면 다시 탐색한다.
- 최초 고정 목록을 읽기 전에는 고정 UI 적용을 보류하고, 읽기가 끝나면 RAF를 기다리지 않고 적용한다. 옵션 비활성화 시 캐시와 준비 상태를 정리한다.
- 추가 타이머, 재시도, 네트워크 요청, 저장 형식 변경은 없다. 기존 네이티브 행을 이동하거나 복제하지 않는다.

## 보완 후 검증

- 새 회귀 테스트 중 행 교체·링크 재사용 두 검사가 수정 전 실패했고 수정 후 통과했다.
- 관련 테스트 34개 통과: 반복 행 교체, 이름 DOM 교체, 링크 재사용, 라이브·오프라인 전환, 목록·사이드바 재마운트, SPA 이동, 초기 저장값 로드, 옵션 끄기·켜기, 고정 편집 상태를 확인했다.
- 변경하지 않은 행을 즉시 다시 탐색하지 않는지, 고정 아이콘을 불필요하게 교체하지 않는지, 추가 저장·네트워크 호출이 없는지도 확인했다.
- `npm.cmd run test:all`: 793개 통과. `npm.cmd run lint`, `npm.cmd run format:check`: 통과.
- 별도 Chrome 탭의 로컬 화면에서 현재 소스와 기존 `tests/fixtures/sidebar-pin-layout.html` 기반 8행 목록을 사용했다. 각 RAF에서 목록을 교체한 뒤 mutation 전달 이후 마이크로태스크에서 확인했다. 라이트·다크 모드 각각 6회 중 고정 표시·순서 누락은 0회, 아이콘은 2개를 유지했다. 테마별 화면과 콘솔 오류·경고 없음도 확인했다.
- 이 로컬 검증은 실제 확장 실행 context의 주입 확인을 대체하지 않는다. 브라우저 도구의 URL 보안 정책이 `chrome://extensions/` 접근을 차단하여 확장 재로드와 치지직에서의 수정본 주입 확인은 수행하지 못했다. 차단 우회는 시도하지 않았다.
- 최소 수동 확인: 방송 시청을 마친 뒤 Chrome 확장 관리에서 치즈 스패너를 다시 로드하고, 새 치지직 탭에서 팔로잉을 펼쳐 고정 표시가 유지되는지 확인한다.
