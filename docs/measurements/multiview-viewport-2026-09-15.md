# 멀티뷰 창의 페이지 전체 이동

- 날짜: 2026-09-15 (KST)
- 브랜치: `1.3.8`
- 요청: 자유 배치의 이동 범위를 플레이어 밖 사이드바·채팅까지 넓히기.

## 현재 치지직 구조 측정

대상은 `https://chzzk.naver.com/live/7c4d5ea51cc36eff812e9c6059704f3f`이다. 브라우저 API로 네이티브 플레이어부터 문서 루트까지 computed style을 읽었다.

- `.chzzk_player.type_live`와 바로 위 wrapper는 당시 `(240,60)`에 약 `1284×722.8px`로 배치돼 있었다.
- 상위 플레이어 영역에 `overflow:hidden`, 본문 스크롤 영역에 `overflow:auto`, 최상위 페이지 영역에 `overflow:clip`이 있었다.
- 콘텐츠 section에는 `transform:matrix(1,0,0,1,0,0)`이, 플레이어 wrapper에는 `isolation:isolate`가 있었다.
- 이 구조에서는 창의 이동 좌표만 넓히거나 일반 fixed 요소로 바꾸면 상위 요소의 클리핑·좌표 기준·겹침 순서에 영향을 받는다. 측정한 클래스 해시나 크기를 런타임에 하드코딩하지 않았다.

## 구현

기존 플레이어 부모를 [HTML Popover API의 manual 표시](https://developer.mozilla.org/en-US/docs/Web/API/Popover_API/Using#using_manual_popover_state)로 올리고, 페이지 표시 영역 전체를 배치 기준으로 사용한다. 네이티브 플레이어와 보조 영상의 DOM 부모는 유지한다. 상위 페이지의 transform·overflow 스타일도 덮어쓰지 않는다.

- 전체 레이어의 배경과 backdrop은 투명하며, 창을 제외한 영역은 포인터 입력을 통과시킨다. 창이 덮지 않은 사이드바·채팅·헤더는 계속 사용할 수 있다.
- 설정창도 페이지 위층에 표시해 자유 창에 가려지지 않도록 한다.
- 기존 `freeWindows`의 플레이어 상대 좌표를 처음 사용할 때만 페이지 상대 좌표로 변환하고 `freeWindowSpace:"viewport"`를 저장한다. 기존 화면상의 위치·크기를 이어받으며, 이미 변환한 좌표를 다시 변환하지 않는다.
- 이동·크기 조절의 경계는 브라우저 페이지 표시 영역이다. 창이 화면 밖으로 사라지지 않도록 유지한다. 창 크기 변경 시 저장한 좌표를 덮어쓰지 않고 표시만 다시 계산한다.
- 자유 배치를 끄면 manual 표시와 임시 속성을 정리하고 기존 분할 배치로 돌아간다. 다시 켜면 마지막 페이지 전체 배치를 복원한다.
- 전체화면 진입 시 자유 배치와 설정창의 위층 표시를 접고, 전체화면 종료 시 저장한 자유 배치로 복원한다. 저장된 모드와 좌표는 유지한다.
- 표시 기능이 없거나 열기가 실패하면 옵션을 켰다고 표시하지 않고 실제 실패를 안내한다. 현재 방송 재생은 유지한다.

## 자동 검증

기존 자유 배치 테스트에 페이지 밖 이동, 이전 좌표 이관, 전체화면·창 크기 변경, 표시 실패와 정리를 추가했다. JSDOM에는 Popover API가 없어 연결된 요소·manual 상태를 검사하는 API 스텁을 사용하고, 실제 클리핑과 클릭 대상은 아래 Chrome 검증으로 따로 확인했다.

- 페이지 원점과 떨어진 플레이어에서 사이드바·채팅 영역까지 이동하는지 확인했다.
- 네이티브 DOM 부모, 영상 노드, 재생 인스턴스·요청 수와 원래 transform·overflow를 유지하는지 확인했다.
- 기존 배치를 한 번만 이관하고 새로고침 시 다시 이관하지 않는지 확인했다.
- 전체화면 진입·종료, 창 크기 변경, 옵션 해제에서 위층 표시와 저장값을 확인했다.
- API 부재·열기 취소·예외가 발생했을 때 실패 안내와 정리를 확인했다.

관련 테스트 이후 `npm.cmd run test:all` 733개, `npm.cmd run lint`, `npm.cmd run format:check`가 모두 통과했다.

## 로컬 Chrome 검증

URL은 `http://127.0.0.1:18768/live/aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa`이며, 실제 방송 재생 없이 사용하는 임시 UI 테스트 페이지다. 플레이어 상위에 transform과 overflow clipping을 두고 별도 사이드바·채팅을 배치했다.

- 자유 배치를 켰을 때 플레이어 부모와 설정창이 `:popover-open` 상태가 됐다. 전체 레이어는 `1878×885px`, 메인과 보조 창은 각각 기존 `600×337.5px`, `300×168.75px`를 유지했다.
- 포인터로 보조 B를 `(0,337)`의 사이드바 위로, 보조 C를 `(1274,375.75)`의 채팅 위로 옮겼다. 원래 플레이어의 오른쪽 끝은 `1124px`였으며, 두 위치의 `elementFromPoint`는 각각 해당 보조 영상을 가리켰다.
- 창이 덮지 않은 사이드바 버튼을 눌러 실제 클릭 횟수가 증가하는 것을 확인했다.
- 새로고침 뒤 위 좌표·크기가 복원됐다. 메인을 `(0,97)`로 옮겨 사이드바 위에 놓았을 때도 클릭 대상이 네이티브 메인이었고 DOM 부모는 `video-region`으로 유지됐다.
- 라이트·다크 표시를 확인했다. 라이트 모드에서 설정창은 흰 배경으로 표시됐고, 채팅 위 보조 창과 겹친 지점의 클릭 대상도 설정창이었다. 가로 넘침은 없었다.
- 설정 스위치에서 Space로 껐을 때 메인은 원래 `(224,127)`로 돌아갔고, 다시 켜면 기억한 `(0,97)` 위치로 복원됐다. 페이지 위층의 표시와 임시 속성도 모드에 맞게 적용·해제됐다.
- 전체화면 테스트 버튼의 `requestFullscreen()`은 브라우저에서 `TypeError: not granted`로 거절돼 실제 진입·종료를 검증하지 못했다. 해당 전환·복원은 자동 테스트로 확인한 범위다.

## 직접 확인할 항목

이 대화에서 확장 관리 페이지가 브라우저 보안 정책에 막혀 수정 후 실제 확장 재로드·치지직 주입 검증은 수행하지 못했다. 검증용 로컬 페이지와 실제 확장 검증을 구분한다.

1. 확장을 다시 로드하고 치지직 탭을 새로고침한다.
2. 멀티뷰 설정에서 자유 배치를 켜고 메인·보조 창을 사이드바·채팅 위로 옮긴다.
3. 창의 크기 조절·앞으로 가져오기·우클릭 취소와 창이 덮지 않은 페이지 조작을 확인한다.
4. 자유 배치 끄기·켜기, 새로고침, 브라우저 크기 변경과 실제 플레이어 전체화면 진입·종료를 확인한다.
