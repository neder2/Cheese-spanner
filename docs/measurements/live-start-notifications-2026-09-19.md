# 방송 시작 알림·지정 채널 자동 탭 열기 검증

## 작업 범위

- 날짜: 2026-09-19 KST
- 브랜치: `1.3.9`, 시작 HEAD: `52d7d3536811dc0cde223fdc7a5adac67955571e`
- 기존 작업 변경을 유지한 채 기능을 추가했다. 버전 변경·커밋·push·릴리스는 수행하지 않았다.
- 전체 사용 여부는 `shared/settings.js`의 두 옵션으로 관리한다. 채널별 선택은 `chrome.storage.local`에 저장하며 service worker의 단일 큐에서 변경한다.

## 현재 API 실측

PowerShell의 HTTPS GET으로 다음 응답을 확인했다. 로그인 쿠키를 별도로 전달하지 않았다.

| Endpoint                                                                                       | 확인한 응답                                                                                     |
| ---------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `https://api.chzzk.naver.com/service/v3/channels/c100f81959d1c17044be0541eed56f5b/live-detail` | `code=200`, `status=OPEN`, `liveId=21174134`, `openDate=2026-09-18 18:17:16`, 채널명 `피닉스박` |
| `https://api.chzzk.naver.com/service/v3/channels/6c837d7222ccc4431ca7835a4340be8e/live-detail` | `code=200`, `status=CLOSE`, `liveId=21174085`, 채널명 `부산MBC 스포츠마니아TV`                  |

라이브 응답의 `content.channel.channelId`가 요청 ID와 일치하는지 확인했다. 구현은 관측한 `OPEN`·`CLOSE`와 유효한 양의 정수 방송 ID만 처리한다. 실패·빈 응답·알 수 없는 상태를 오프라인으로 취급하지 않으며 방송 제목 변경은 새 방송으로 취급하지 않는다. 이 실측은 모든 채널·방송 형식의 증명이 아니다.

## 동작과 권한

- `alarms` 권한으로 1분 주기의 alarm 하나를 사용한다. worker 실행 시 없어진 alarm을 복구하고 중복 실행은 합친다. 동시 상태 요청은 2개, 각 요청의 제한 시간은 8초다.
- 채널은 최대 32개, 중복 방지 방송 ID는 채널별·동작별 최근 16개로 제한한다. 꺼진 동작·삭제된 채널의 상태는 정리한다.
- 처음 등록·활성화하거나 브라우저를 시작할 때 첫 유효 응답은 기준 상태로 기록한다. 기준 조회 실패 후의 첫 유효 응답도 조용히 기록한다. worker 재시작 시에는 저장된 상태를 유지한다.
- 상태를 먼저 저장한 뒤 알림·탭 열기를 시도한다. 강제 종료나 API 실패 시 같은 방송의 동작을 반복하지 않는 쪽을 선택했으므로, 저장 직후 worker가 강제 종료되면 해당 방송의 동작이 누락될 수 있다. 알림 실패와 탭 열기 실패는 독립적으로 처리한다.
- `notifications`는 선택 권한이며 옵션 저장 버튼의 사용자 조작 안에서 요청한다. 미리보기 호스트 권한도 동시에 필요하면 한 번의 요청으로 묶는다. 권한 거부·해제는 자동 탭 열기를 막지 않는다.
- 자동 열기는 `active:false`를 사용한다. 기존 라이브 탭이 있으면 유지하고, 알림을 직접 클릭하면 기존 탭과 창을 활성화한다. URL 확인에는 기존 치지직 호스트 권한을 사용하며 `tabs` 권한을 추가하지 않았다.
- 원격 실행 코드·추가 호스트·외부 분석 전송은 추가하지 않았다.

설계 시 [Chrome alarms](https://developer.chrome.com/docs/extensions/reference/api/alarms), [notifications](https://developer.chrome.com/docs/extensions/reference/api/notifications), [tabs](https://developer.chrome.com/docs/extensions/reference/api/tabs), [permissions](https://developer.chrome.com/docs/extensions/reference/api/permissions)의 공식 문서를 확인했다.

## 수행하지 못한 검증과 수동 절차

브라우저 도구가 `chrome://extensions/` 접근을 정책으로 차단했다. 다른 경로나 도구로 우회하지 않았다. 따라서 **실제 확장 재로드, 현재 확장 ID·주입 확인, 실제 알림 권한 창, OS 알림 표시와 실제 방송 시작에 따른 탭 생성**은 검증하지 못했다. 자동화 테스트의 API 모의 실행과 로컬 화면 렌더링을 실제 확장 동작으로 간주하지 않는다.

1. 확장 관리에서 치즈 스패너를 다시 로드하고 치지직 탭을 새로고침한다.
2. 설정의 **탐색 → 방송 시작 알림·자동 열기**에서 채널을 추가하고 채널별 알림·자동 열기를 선택한다. 위 두 옵션을 켜고 저장하면서 알림 권한을 승인한다.
3. 이미 진행 중인 방송에는 반응하지 않는지 확인한다. 이후 새 방송이 시작되면 데스크톱 알림과 비활성 배경 탭이 각각 한 번만 생기는지 확인한다.
4. 같은 채널의 라이브·대기 탭을 미리 열어 두면 추가 탭이 생기지 않는지, 알림 클릭으로 기존 탭에 이동하는지 확인한다. 대기 화면 자동 새로고침과 SPA 이동 후의 URL도 함께 확인한다.
5. 알림 권한 거부·기존 승인·해제 상태를 확인한다. 기능 끄기와 채널 삭제 후 새 동작이 없는지, 브라우저 재시작 후 진행 중 방송을 건너뛰는지 확인한다. OS에서 알림이 차단되어 있으면 OS 설정도 확인한다.
