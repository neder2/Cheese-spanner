# Space·M·F·T 선택 단축키 복구

2026-09-14 사용자 요청으로 1.3.7 작업 브랜치에 추가했다. 기존 자동 실패 감지 기능을 복원하는 대신 Space·M·F·T를 선택적으로 소유한다. Space 홀드 배속이 켜져 있으면 Space는 해당 기능에 맡긴다. `screenShortcutsEnabled`는 기본 false이며 과거 `shortcutRescueEnabled`와 독립적이다.

## 관측

- 대상: https://chzzk.naver.com/live/feb20a676694b1163fed010da0848303
- 실제 버튼 클래스: `.pzp-pc__viewmode-button`, `.pzp-pc__fullscreen-button`.
- Space·M 추가 시 같은 URL에서 `.pzp-pc__playback-switch`, `.pzp-pc__volume-button`과 각각 일시 정지·음소거 라벨을 확인했다. Space 홀드 옵션 변경 즉시 위임/직접 처리 전환, 반복 입력 중복 클릭 방지 및 입력창 제외 회귀 검사를 추가했다.
- 넓은 화면 버튼 클릭 시 `aria-label`이 `넓은 화면`에서 `좁은 화면`으로 변했다. 플레이어 버튼에 포커스를 둔 T 입력도 전환했다.
- 자동화의 본문 키 입력은 전환하지 않았으나 문서 포커스 차이가 섞여 있어 사용자 제보 재현으로 확정하지 않았다.
- 전체화면 버튼 및 키 검사에서 `TypeError: not granted` 오류가 발생했다. 브라우저 도구는 확장 관리 페이지 접근을 차단하여 작업 코드의 확장 재로드 및 실제 주입 검증은 하지 못했다.

## 구현과 검증 범위

활성화 시 window capture에서 해당 키를 소유하고 현재 메인 플레이어의 실제 버튼을 동기 클릭한다. 네이티브 bubbling 키 핸들러로 전파하지 않으며 반복 입력은 다시 클릭하지 않는다. 비활성화하면 리스너를 제거한다. 라우트·비디오·버튼을 매 입력 시 확인하여 교체 전 노드를 저장하지 않는다. 새 권한과 원격 실행은 없다.

회귀 검사는 기본 꺼짐과 옛 설정 무시, 중복 초기화 및 옵션 반영, 네이티브 핸들러와 중복 실행 방지, 반복 키, 입력창·조합키·다른 단축키 제외, 버튼 없음·비활성, SPA 이동·플레이어 교체를 다룬다.

관련 테스트 26개 통과. 전체 기본 병렬 실행은 685개 중 광고 팝업·카테고리 검색 대기 검사 2개가 실패했고 해당 검사만 재실행하면 통과했다. `npm.cmd run test:all -- --test-concurrency=2`로 재검사한 전체 685개는 모두 통과했다. `npm.cmd run lint`, `npm.cmd run format:check`, 추가 문서 포맷 검사와 `git diff --check`도 통과했다.

Space·M 추가 후 관련 테스트 27개와 전체 686개(`npm.cmd run test:all -- --test-concurrency=2`)가 통과했다. 린트·전체 포맷 검사도 다시 통과했다.

수동 확인: 확장 재로드 후 라이브/VOD 새로고침 → 옵션 켜기 → F/T 각각 진입·복귀 및 길게 누르기 → 채팅 입력 중 미개입 → 옵션 끄기 → SPA 이동. 좁은 설정 팝업의 라이트·다크 표시와 실제 List-KR 병용은 미검증이다. 다른 확장이 먼저 capture에서 키를 차단하는 경우까지 이 기능으로 복구된다고 보장하지 않는다.
