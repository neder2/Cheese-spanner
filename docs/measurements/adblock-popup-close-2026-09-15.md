# 광고 차단 안내 닫기와 단축키 차단 상태

이 보완은 1.3.9 개발 변경분이다. 1.3.8에는 포함하지 않는다.

## 2026-09-15 조사

- 대상: https://chzzk.naver.com 에서 참조한 https://ssl.pstatic.net/static/nng/glive/resource/p/static/js/index-GNyFfAPg.js (HTTP 200).
- 응답 SHA-256: `94487c96be175c488592e5844725fdf6aa43c0a4969530edf1f1ca8583122eb8`.
- 네이티브 단축키 훅 `uY`는 `G(Xr)` 상태가 참이면 바로 반환한다. 모달 컴포넌트 `oi`는 기본 `maintainFullscreen=false`일 때 마운트에서 `H(Xr)(true)`, effect 정리에서 false를 설정한다.
- 모달의 닫기 컨트롤은 `aria-label: popup.close`와 `onClickHandler: closeButtonHandler`로 연결된다. `hideCloseButton` 기본값은 true이므로 모든 안내에 닫기 버튼이 있다고 가정할 수 없다.
- 소스 응답 분석이며, 실제 광고 차단 안내가 발생한 브라우저 DOM이나 제보 환경을 재현한 결과는 아니다. 광고 차단 안내가 해당 모달을 사용하며 숨겨진 채 남을 때 단축키 차단 상태가 유지될 수 있다는 조건부 원인 분석이다.

## 변경 계약

- 광고 차단 문구가 있는 표시 중인 팝업 안에서 접근 가능한 이름이 `닫기`인 버튼이 정확히 하나일 때 네이티브 click을 호출한다. 설치·확인·링크를 추측해서 누르지 않는다.
- 닫기 버튼을 확인하면 팝업과 해당 팝업만 포함하는 배경을 잠시 숨긴 뒤 버튼을 누른다. 다음 프레임까지 남아 있으면 숨김을 해제한다. 버튼이 없거나 비활성·모호하면 숨기지 않으며, 클릭 예외·옵션 해제·라우트 변경 때도 즉시 복원한다. body 스크롤 강제 해제와 반복 타이머는 사용하지 않고 React 내부 상태를 직접 수정하지 않는다.
- 같은 팝업·내용·버튼에 대한 반복 클릭을 막고, 숨김·내용 변경·노드 재삽입·버튼 교체·SPA 이동·옵션 비활성화 시 정체성을 다시 확인한다. 별도 재시도 타이머나 observer는 추가하지 않는다.
- 기존 CSS 숨김·스크롤 복원 테스트는 의도적으로 변경한 계약에 맞춰 실제 닫기 콜백 실행 및 스크롤 소유권 유지 검사로 대체했다. 다른 안내 제외와 통합 옵션 동작 검사는 유지한다.

## 검증과 한계

- 새 핵심 회귀 테스트 4개는 수정 전 실패하고 수정 후 통과했다. 추가 테스트로 숨겨진 상위 요소, 중첩 팝업, SPA 이동과 버튼 교체를 확인했다.
- 관련 대상 검사 11개, 최종 `npm.cmd run test:all` 790개가 통과했다. `npm.cmd run lint`, `npm.cmd run format:check`, `git diff --check`도 통과했다.
- 네이티브 상태 해제 테스트는 닫기 콜백으로 상태가 정리되는 모형이며 실제 치지직 React 상태를 측정한 것은 아니다.
- 독립 브라우저 도구가 제공되지 않았고 컴퓨터 사용 도구는 사용하지 않았다. 확장 재로드·실제 주입, 실제 광고 차단 안내의 한국어 닫기 라벨·동작, List-KR 병용, 라이트·다크 화면은 미검증이다.
- 수동 확인: 확장을 다시 로드하고 치지직 탭을 새로고침한다. 광고 차단 안내 발생 시 닫기 버튼이 있는 안내가 닫히는지, 이후 M·F·T가 동작하는지 확인한다. 닫기 버튼이 없는 안내가 화면에 남는지, 옵션을 끄면 자동 닫기가 중단되는지도 확인한다.

## 2026-09-19 선행 숨김 보완

- 현재 홈페이지가 참조하는 `https://ssl.pstatic.net/static/nng/glive/resource/p/static/js/index-DdGx9_UO.js`를 다시 조회했다. 공용 모달의 `popup.close` → `closeButtonHandler` 연결과 `_dimmed_jao35_2` 배경 클래스가 유지된 것을 소스에서 확인했다. 실제 광고 차단 안내 DOM 재현은 아니다.
- 사용자 요청에 따라 닫기 직전에 확장 소유 CSS 속성으로 일시 숨김을 적용한다. 레이아웃은 유지하고 DOM 제거는 네이티브 닫기 핸들러에 맡긴다. 공유 배경은 숨기지 않는다.
- 단일 RAF는 닫기 재시도나 성공 판정이 아니라 숨김 복원 시점이다. 다음 프레임에도 남은 팝업은 다시 표시해 실패를 감추지 않는다. 비동기 제거·예외·옵션 해제·라우트 이동에서도 숨김 상태를 정리한다.
- 선행 숨김과 실패 복원·공유 배경 보호 테스트는 수정 전 실패, 수정 후 통과했다. 기존 중복 클릭·입력 상태·DOM 재사용 검사를 유지했다. 실제 화면의 깜빡임과 라이트·다크 화면 검증은 미수행이다.
- 관련 대상 14개와 전체 `npm.cmd run test:all` 806개가 통과했다. 린트·전체 포맷 검사와 `git diff --check`도 통과했다.
