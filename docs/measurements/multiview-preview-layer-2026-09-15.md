# 자유 배치와 팔로잉 미리보기의 표시 순서

- 날짜: 2026-09-15 (KST)
- 브랜치·작업 버전: `1.3.8`
- 요청: 팔로잉 미리보기를 자유 배치의 메인·보조 창 위에 표시하기.

## 원인과 변경

자유 배치의 플레이어 부모는 manual popover로 브라우저 최상위 표시층에 올라간다. 기존 팔로잉 미리보기는 일반 페이지의 fixed 요소여서 높은 z-index로도 그 위에 표시되지 않았다.

- 자유 배치 중에는 기존 미리보기 노드와 접힌 고정 채널의 hover bridge를 manual popover로 표시한다. 좌표·크기·영상 DOM은 유지한다.
- 멀티뷰는 표시층 변경 후 `betterchzzk:multiview-layer-change` 이벤트를 발행한다. 미리보기는 이를 받아 이미 열려 있는 경우에도 새 플레이어 층보다 위로 올린다.
- 미리보기 옵션을 끄면 이벤트 리스너를 제거한다. 미리보기 종료·자유 배치 해제 시 표시층을 정리하며, 일반 모드의 미리보기는 기존 방식을 유지한다.

## 자동 검증

두 실제 feature를 함께 실행하는 회귀 테스트를 추가했다. 기존 구현에서는 최상위 표시층에 미리보기가 없어 실패했고 수정 후 통과했다. 자유 배치 켜기·끄기, 플레이어 DOM 교체, 연결 영역을 통한 마우스 이동, 미리보기 종료·재개, 옵션 비활성화를 검사했다. 표시층 변경 중 미리보기 영상·HLS 인스턴스와 메타데이터 요청 수가 유지되는지도 확인했다.

- 팔로잉 미리보기·멀티뷰 관련 테스트: 124개 통과
- 전체 `test:all`: 778개 통과
- `lint`, `format:check`, `git diff --check`: 통과

## 로컬 Chrome 검증

대상: `http://127.0.0.1:18770/live/aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa`

실제 방송 없이 미디어와 메타데이터만 대체한 UI fixture에서 두 feature의 현재 소스를 함께 불러왔다. 브라우저의 실제 Popover API와 hit testing을 사용했다.

- 라이트·다크 모드 모두 자유 배치 부모, 미리보기, 연결 영역이 `:popover-open`이었다.
- 미리보기는 `(198,103)`에 `460×332.8125px`, 연결 영역은 `(188,238)`에 `10×62px`로 표시됐다. 기본 popover 여백이나 테두리가 위치를 바꾸지 않았다.
- 메인 영상과 겹친 미리보기 중앙의 `elementFromPoint`는 미리보기 요소를 반환했다. 연결 영역 중앙도 해당 연결 요소를 반환했다.
- 미리보기를 닫으면 미리보기 표시층과 연결 영역이 정리되고 자유 배치 부모의 표시층은 유지됐다. 브라우저 오류 로그는 없었다.

브라우저 도구의 확장 관리 페이지 접근 제한으로 수정 후 실제 확장 재로드·치지직 주입 검증은 하지 못했다. 확장을 다시 로드하고 치지직 탭을 새로고침한 뒤 자유 배치에서 팔로잉 채널에 마우스를 올려 확인해야 한다.
