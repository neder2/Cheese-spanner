# 멀티뷰 자유 배치 구현과 검증

같은 날 이어진 [페이지 전체 이동 변경](multiview-viewport-2026-09-15.md)에서 자유 배치 범위를 사이드바·채팅까지 넓혔다. 아래 기록은 최초의 플레이어 내부 자유 배치 검증이다.

- 날짜: 2026-09-15 (KST)
- 작업 브랜치: `1.3.8`
- 요청: 멀티뷰 내부 설정에서 자유로운 창 배치를 켜고 끄기.

## 동작과 저장 범위

- 멀티뷰 설정에 **자유 배치** 스위치를 추가했다. 기존 탭과 새 탭의 기본값은 꺼짐이다. 전역 확장 옵션 대신 기존 탭 구성에 `freeLayoutEnabled`와 최대 6개의 `freeWindows`를 저장한다.
- 창의 위치·크기는 영상 영역에 대한 비율로 보관하고, 배열 순서로 겹침 순서를 기억한다. 채널 ID, 중복, 유한한 좌표, 화면 경계를 검증하며 잘못된 창 좌표는 현재 분할 배치에서 다시 계산한다.
- 켤 때 현재 창 크기를 사용하고 이후에는 각 창을 독립적으로 이동·확대·축소한다. 영상 비율과 화면 경계를 유지한다. 창을 클릭하거나 키보드로 초점을 두면 앞으로 가져온다. 끄면 기존 분할 트리를 사용하고, 다시 켜면 기억한 자유 배치를 사용한다.
- 네이티브 메인 플레이어를 다시 부모에 붙이거나 복제하지 않는다. 기존 부모 안에서 위치·크기와 겹침 순서만 바꾼다. 영상 이동·크기 조절은 재생 인스턴스, 네트워크 요청, 볼륨·음소거, 채널별 딜레이를 바꾸지 않는다.
- 이동·크기 조절 미리보기는 저장값과 분리하며 놓을 때 확정한다. Esc·우클릭·포인터 취소·포인터 캡처 해제·창 초점 이탈·탭 숨김·옵션 변경·플레이어 교체 시 취소하고 임시 리스너와 캡처를 해제한다.
- 창에 초점을 두면 방향키로 이동한다. 모서리에 초점을 두면 방향키로 크기를 조절하고 Shift를 함께 누르면 조절 폭이 커진다. 기존 영상 버튼·볼륨 슬라이더의 키보드 조작은 유지한다.
- 설정 목록에서 방송 자리를 옮길 때는 자유 창의 크기와 해당 자리의 소리를 유지하며, 메인 교체는 기존 라우터 경로를 사용한다. 단순히 자유 창을 드래그할 때는 방송 교체나 소리 교환을 하지 않는다.
- **기본 배치**는 분할 배치와 기억한 자유 창 배치를 초기화한다. **보조 방송 정렬**은 분할 모드에서 사용하며 자유 모드에서는 이유를 안내한다.

## 자동 검증

`tests/live-multiview.test.js`에 다음 회귀 범위를 추가했다.

- 기본 꺼짐과 내부 스위치, 포커스 유지, 켜기·끄기 및 마지막 자유 배치 복원.
- 독립 이동·겹침·네 모서리 크기 조절·영상 비율·화면 경계·키보드 이동.
- 드래그 중에는 저장하지 않으며 취소하면 이전 위치로 복원되는지 확인.
- 방송 추가·제거·네이티브 DOM 교체·새로고침·메인 승격 이후 채널별 위치 유지.
- 설정 목록의 세 방송 순환 이동에서 창 크기와 자리별 소리 유지, 음소거 갱신 중 목록 드래그 유지.
- 이전 세션과 잘못된 좌표·중복 채널 처리.

기존 분할·싱크·음량·화질·라우트·정리 테스트도 유지했다.

전체 `npm.cmd run test:all` 730개와 `npm.cmd run lint`를 통과했다. 변경 파일의 포맷을 정리하고 저장소 전체 `npm.cmd run format:check`를 확인했다.

## 로컬 Chrome UI 검증

- URL: `http://127.0.0.1:18768/live/aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa`
- 별도 임시 테스트 페이지에서 저장소·영상 메타데이터·HLS를 스텁으로 제공하고 실제 저장소의 멀티뷰 스크립트를 로드했다. 화면에 테스트용임을 표시했으며 실제 방송·CDN 요청·소리 재생은 수행하지 않았다. 이 결과는 실제 확장 주입 검증과 구분한다.
- 실제 포인터로 보조 B 창을 `(약 624, 127)`에서 `(284, 282)`로 이동했다. 메인과 겹친 지점의 `elementFromPoint`가 B 창을 가리키는 것을 확인했다.
- 메인의 보이는 부분을 누르자 메인이 앞으로 올라왔고 같은 겹침 지점의 클릭 대상이 네이티브 메인으로 바뀌었다. 네이티브 부모는 유지했다.
- 메인 오른쪽 아래 모서리를 끌어 크기를 약 `600×337.5`에서 `479.1×269.5`로 바꿨다. 두 보조 창은 `300×168.75`로 유지했다.
- 페이지 새로고침 후 이동한 B와 조절한 메인 좌표·크기가 복원됐다.
- 내부 스위치에서 Space로 껐다 켰을 때 메인 너비가 약 `600 → 479.1px`로 복원됐고 분할 구분선도 모드에 맞게 표시·제거됐다.
- 라이트·다크와 영상 영역 너비 360px 환경에서 스위치를 확인했다. 설정창 가로 넘침은 없었고 체크 상태의 배경·글자색은 각각 `rgb(0,255,163)`과 `rgb(14,15,16)`이었다. 초기 호버 색상 충돌을 발견해 기존 패널의 시맨틱 브랜드 색과 호버 규칙을 적용했다.
- 검증 탭의 수집된 콘솔 경고·오류는 없었다.

## 실제 확장 검증 한계

이 대화에서 브라우저 보안 정책이 확장 관리 페이지 접근을 차단했다. 확장 관리나 실제 치지직 주입을 다른 경로로 우회하지 않았다. 수정 후 확장 재로드, 실제 라이브·타임머신·전체화면에서의 동작은 직접 확인이 필요하다.

1. Chrome 확장 관리에서 치즈 스패너를 다시 로드하고 치지직 라이브 탭을 새로고침한다.
2. 멀티뷰에 보조 방송을 추가하고 채팅 상단 **멀티뷰 설정 → 자유 배치**를 켠다.
3. 메인·보조 창을 옮겨 겹치고 각각 앞으로 가져온다. 모서리로 크기를 바꾼 뒤 Esc·우클릭 취소, 버튼·볼륨 조작을 확인한다.
4. 자유 배치 끄기·다시 켜기·새로고침·넓은 화면·전체화면·방송 추가·제거 후 배치와 재생 상태를 확인한다.
