## 확인된 결함과 아직 확정할 수 없는 부분

기존 채팅 복구는 SPA VOD 진입 뒤 한국어 제목이 없고 video가 DOM에 연결됐다는 이유로 새로고침을 승인했어요. `getReloadHref()`는 그 순간 위치를 `currentTime` URL에 넣고 이후 소비하지 않았어요. 열린 패널·준비 상태·채팅을 닫은 사용자 의도는 확인하지 않았어요.

기존 MAIN의 URL 보정도 250~10,500ms에 같은 시간을 적용하며, 취소·종료 뒤 같은 주소의 화질 요청이 오면 다시 예약했어요. 전체 스크립트 회귀에서 사용자 탐색으로 300초가 된 뒤 화질 요청을 보내면 첫 250ms 보정이 12초로 되돌렸어요. 이 최초 잘못된 쓰기는 코드 경로의 확정 결함이에요. 신고자가 실제로 이 주소·이동 순서를 사용했는지는 확보하지 못했어요.

공식 공개 [index-VdvK-ysl.js](https://ssl.pstatic.net/static/nng/glive/resource/p/static/js/index-VdvK-ysl.js)를 2026-10-01에 내려받아 실행하지 않고 읽었어요. 첫 `play` 처리에서 명시적 `currentTime`이 `watchTimeline`보다 우선하고, watch-event의 `payload.positionAt`이 위치 입력인 것을 확인했어요. 끝까지 10초 이하·기간 밖인 watchTimeline은 0을 선택해요. 인증정보는 읽거나 기록하지 않았어요.

예전 5초 스킵 회귀는 `/live` 가드이고 이번 `/video` 쓰기와 다른 경로예요. 일반 URL의 늦은 네이티브 초기화·광고 간접 영향은 코드만으로 확정할 수 없어요. 시간을 늘리거나 새 영구 VOD 저장기를 만들지 않았어요.

## 최소 변경

- `features/vodReplayChatFix.js`: 네이티브 `aside#vod-aside`가 실제 존재하고 readyState·유한 duration이 준비된 경우로 자동 복구를 좁혔어요. 닫힌/없는 패널·미준비 영상의 불필요한 새로고침을 막아요. 열린 패널의 제목 누락에 대한 제한된 시도는 남겼어요.
- 복구 새로고침은 원래 URL을 그대로 사용해요. 위치는 `betterchzzk:vod-chat-resume` sessionStorage 한 건의 `{href, seconds, at}`으로 최대 60초만 전달해요. 첫 playing 또는 실제 진행 뒤 한 번 적용하고 안정화 성공 뒤 지워요. 탐색·댓글 타임코드·다른 VOD·pagehide·만료·잘못된 값도 취소해요. 준비 중에는 쓰지 않고 전달 저장이 실패하면 재로드하지 않아요.
- `features/autoQualityPage.js`: URL 보정이 안정화되면 종료하고 같은 VOD·시간의 화질 요청·BFCache·hash/부가 쿼리로 다시 시작하지 않아요. 사용자 탐색·댓글 타임코드가 pending URL 보정을 취소해요. 명시적 0초도 처리하며 사용자가 연 URL을 지우지 않아요. 완료한 URL 의도가 후속 화질 변경의 현재 위치 복원까지 막지 않게 했어요.
- `tests/vod-resume.test.js`에 전체 MAIN/isolated 스크립트의 회귀 27개를 추가했어요. `tests/playback-media-lifecycle.test.js`의 기존 두 긍정 검사는 열린 네이티브 패널·준비된 영상 fixture로 맞추고 기존 quiet-window·maximum-settle assertion을 유지했어요.
- README·PRIVACY·기능 지침·architecture/business-rules/contracts/security/engineering-notes·tracking 문서에 최종 동작과 남은 검증을 반영했어요. 설정 UI·권한·manifest 로드·background writer는 바꾸지 않았어요.

과거 확장이 만든 무표식 currentTime 주소는 사용자 타임코드와 구분할 수 없어 자동 삭제하지 않아요. 이런 기존 주소를 다시 열면 네이티브도 URL 시간을 우선해요. 해당 주소가 신고 조건인지 확인하고, 출처가 확인된 경우 일반 VOD 주소에서 다음 복원을 대조해야 해요.

## 남은 제한과 후속 확인

- 브라우저 URL 정책이 확장 설정·관리 페이지 접근을 거부했어요. 사용자 확인으로 확장 재로드는 진행했지만 자동 화질/광고의 새 문서 OFF·단독·둘 다 비교는 수행하지 않았어요. 우회하지 않았고 사용자 기존 설정은 직접 바꾸지 않았어요.
- 도구가 네트워크 본문 캡처·첫 이벤트 listener 설치를 제공하지 않아 인증된 watch-event.positionAt, 다음 상세 watchTimeline, 첫 play/playing/seeking/seeked와 화질 변경의 전체 순서를 기록하지 못했어요. DOM 표본의 이어보기 성공을 이 요청 체인의 검증으로 확대하지 않아요.
- 일회용 채팅 복구의 실제 장애→재로드→소비 전체 순서는 통제 테스트로 확인했고 자연 발생한 실제 장애에서 재현하지 못했어요. 다른 VOD·뒤로/앞으로·늦은 초기화·탐색·저장 오류는 자동 검사와 실제 화면 결과를 구분해요.
- 네이티브 화질 메뉴 클릭 한 번은 브라우저 입력 시간 초과로 열리지 않았고, 후속 화면에도 메뉴가 없었어요. 재생은 진행했으며 기존 1080p를 유지했어요. 화질 변화와 위치 복원의 검증은 전체 스크립트의 트랙 전환 모델이고 실제 메뉴 전환 성공으로 보고하지 않아요.
- 신고자의 당시 URL·닫기 시점·서버 응답이 없어 신고 원인은 유력한 코드 경로로 남아요. 새 기능 안내·포장·릴리스 전 점검은 이번 요청의 범위가 아니며 릴리스 준비 완료로 보고하지 않아요.
