# 스트림 정보의 저지연·재생 관측 검증

이후 독립 저지연 우선 옵션·제어는 사용자 요청으로 제거했어요. 스트림 정보의 현재 방식·지연·버퍼·끊김·프레임 측정은 유지하며, 아래 수치는 해당 측정 기능을 구현했을 당시의 검증 기록이에요.

## 확인 범위

2026-09-28, branch `1.4.1`, HEAD `ea22dfcdbeb167a75b038e50e9780afaa3aa221a`의 작업 파일을 기준으로 확인했어요. manifest·package는 `1.4.0`을 유지했고 커밋·배포하지 않았어요. 같은 폴더의 기존 저지연·배너·기록 백업·확대·옵션 UI 변경은 보존했어요.

공개 라이브 HTML `https://chzzk.naver.com/live/75cbf189b3bb8f9f687d2aca0d0a382b`를 HTTP로 다시 조회해 [페이지 진입 코드](https://ssl.pstatic.net/static/nng/glive/resource/p/static/js/index-BBIPHoDO.js)를 참조하는 점을 확인했어요. 앞서 조회한 동일 배포 파일과 [재생 모듈](https://ssl.pstatic.net/static/nng/glive/resource/p/static/js/player-vendor-BYg0wCyN.js)의 트랙 종류·선택 목록·onLive getter 구조를 근거로 읽기 경로를 구성했어요. 공개 코드 사본은 제품에 넣지 않았어요.

이 기록은 코드 확인과 자동 회귀 결과예요. 실제 Chrome 확장 주입·영상 진행·실제 지연 초 수·안정성 개선·픽셀 배치를 관측한 결과가 아니에요. 컴퓨터 사용 도구는 사용하지 않았어요.

패널이 열려 있고 문서가 보일 때 기본 1초 간격으로 표본을 수집해요. 최근 60초, 최대 120개 표본과 진행 중을 포함한 최대 128개 끊김 구간만 메모리에 보관해요. 정기 표본 간격이 3초를 넘으면 그래프·프레임·지연 시계를 다시 잡아요. 그 사이 이벤트로 실제 관측한 시간과 대기 후보는 유지하지만 실제 관측이 끊긴 시간은 포함하지 않아요. 실제 관측한 초 수를 함께 표시하며 닫으면 자료를 폐기해요. 네이티브의 정상적인 1.03배속 같은 양수 배속도 관측하며 복원하거나 오류로 판단하지 않아요.

같은 방송의 새 소스·메인 영상은 새 live-detail 응답의 OPEN·동일 채널·양수 safe integer liveId로 확인해 과거 자료를 유지해요. 다른 방송·미확인 교체는 새 기록을 시작하고, 숨김·전환은 선을 끊어요. 그래프는 지연 실선과 버퍼 점선, 재생 방식 변경 세로 점선을 구분하며 자동 우열 판정은 하지 않아요.

## 정기 표본 공백 보완

정기 표본은 1초 뒤 10초에만 수집되고 중간에는 미디어 이벤트가 오는 경우, 이벤트의 최근 시각만 보면 그래프의 9초 공백이 감춰졌어요. 정기 표본 시각을 별도로 관리하도록 보완하고 3배 경계·설정된 주기·관측한 끊김과 짧은 후보 보존 회귀를 추가했어요. `node --test tests/live-timing.test.js tests/stream-info-model.test.js tests/stream-info.test.js`는 61개 통과, 종료 코드 0이에요.

독립 검토의 실제 MAIN·모델·패널 연결에서도 버퍼 경로가 두 구간으로 끊기고 긴 프레임 차분이 버려지며, 실제 이벤트 관측 10초와 제어 호출 0이 유지되는 점을 확인했어요. 이후 전체 1,110개 테스트와 lint·format:check·diff 검사를 재실행해 모두 종료 코드 0을 확인했어요. 병행 작업 파일 때문에 잠시 실패했던 후속 포맷 검사도 이 최종 실행에서는 통과했어요. 독립 최종 검토에서 코드·문서의 지적을 모두 해결했어요.
