# 다른 탭에서 복귀 후 무음 조사

## 관측과 한계

- 날짜: 2026-09-17 KST.
- 대상: `https://chzzk.naver.com/live/a6c4ddb09cdb160478996007bff35296`.
- 사용자 보고: 다른 탭을 사용한 뒤 방송 탭으로 돌아와도 소리가 없으며 새로고침하면 복구됨.
- 검사 시 컴프레서 버튼은 활성·준비 상태였고 본영상은 `muted=false`, `paused=false`, `readyState=4`였다. 사용자는 이미 새로고침해 소리가 돌아왔다고 확인했다.
- 따라서 무음 당시 AudioContext 상태와 원인은 실브라우저에서 확정하지 못했다. 이 기록의 테스트 재현은 브라우저에서 같은 증상을 재현했다는 의미가 아니다.

## 코드에서 확인한 누락

오디오 복구 코드는 초기 정상 실행 후 입력 이벤트를 해제했으며 이후 `statechange`, `visibilitychange`, 창 `focus`를 구독하지 않았다. DOM 변화나 별도 옵션 조작 없이 오디오가 중단됐다면 탭 복귀 자체는 재개를 요청하지 않았다. 또한 `resume()` Promise가 성공하면 실제 상태 확인 없이 입력 복구 이벤트를 해제했다.

[Web Audio 명세](https://webaudio.github.io/web-audio-api/)의 AudioContext 상태와 resume 계약을 확인했다. 일반적인 탭 전환이 항상 AudioContext를 중단시킨다고 가정하지 않는다.

## 변경과 검증 범위

- 문서의 공유 AudioContext에 상태 변화, 탭 표시 복귀, 창 포커스 복구를 연결했다. 단순히 탭을 숨기는 이벤트는 재개를 요청하지 않는다.
- 재개 Promise 처리 후 실제 상태가 running인지 확인한다. 실패하거나 중단 상태가 유지되면 사용자 조작으로 재개할 기회를 유지한다.
- 진행 중인 재개 요청은 공유한다. 자동 재개가 대기 중일 때 사용자 조작으로 한 번 더 요청할 수 있지만 연속 클릭·포커스 이벤트로 무한히 요청하지 않는다.
- 컴프레서 비활성 상태에서도 기존 오디오 출력 연결의 복구는 유지한다. 문서 종료 시 이벤트를 해제하고, 늦은 Promise가 이벤트를 다시 설치하지 못하게 한다. 주기적인 타이머와 페이지 새로고침은 추가하지 않았다.
- 기존 코드에서 탭 복귀, 후속 중단 감지, Promise 완료 후 입력 복구 테스트가 실패함을 확인한 뒤 수정했다. 테스트는 중복 요청, 거절 후 재시도, 사용자 조작 승격, 종료 후 정리도 검사한다.
- 이전 턴에서 브라우저 도구의 확장 관리 페이지 접근이 차단됐다. 수정본의 실브라우저 적용과 실제 음성 출력 확인은 별도로 남아 있다.
- 검증 결과: 오디오 복구 하위 검사 5개를 포함한 전체 802개 중 801개가 통과했다. 전체 검사를 두 번 실행했으며 모두 기존 카테고리 검색 스크롤 검사(`tests/extension-pages.test.js:1538`) 하나가 조건 대기 시간 초과로 실패했다. 해당 검사는 단독 실행에서 통과했다. 범위 밖 테스트의 대기 시간이나 assertion은 변경하지 않았다. lint, 전체 format:check, diff 공백 검사는 통과했다.
