# 전체화면 볼륨 표시 크기 — 1.3.9

## 확인 근거

- 2026-09-19 `https://chzzk.naver.com`에서 참조한 `https://ssl.pstatic.net/static/nng/glive/resource/p/static/css/player-vendor-Ct4cRQDi.css`와 `index-DGkZNTRv.css` 응답을 조회했다. 실제 브라우저 렌더링을 측정한 것은 아니다.
- 네이티브 `.pzp-pc--fullscreen.pzp-pc--size-l`/`--size-large`의 하단 버튼 행은 `transform:scale(1.5)`를 적용한다. 기본 툴팁 글꼴은 13px이지만 행의 변환을 함께 받는다.
- 볼륨 슬라이더의 `.pzp-ui-slider__handler-wrap`는 일반 10px, 전체화면 15px이며 트랙 `.pzp-ui-progress`는 각각 2px/3px이다. 볼륨 슬라이더 hover·focus·pressed 상태에서는 표시점이 `scale(1.4)`로 확대된다.
- 확장 퍼센트 툴팁은 body/전체화면 루트에 따로 마운트하므로 네이티브 font-size만 복사하면 행의 확대 효과가 빠진다. 컴프레서 표시점·트랙은 10px/2px로 고정돼 있었고 조작 중 확대 효과가 없었다.

## 변경

- 퍼센트 툴팁에 네이티브 툴팁의 실제 렌더링 폭과 layout 폭 비율을 적용한다. 네이티브 툴팁을 측정할 수 없으면 해당 볼륨 컨트롤 비율, 그것도 없으면 1을 사용한다. 특정 전체화면 배율을 런타임 상수로 고정하지 않는다.
- 확대된 툴팁의 중앙·하단 기준점과 배치 간격도 같은 배율로 맞추고, 기존 영상 영역 안쪽 배치 계산을 유지한다.
- 컴프레서는 네이티브 표시점·트랙의 computed 크기를 CSS 변수에 반영한다. 이미 공통 컨트롤 행이 확대하므로 변환 전 크기를 복사해 이중 확대를 피한다. 네이티브 노드가 사라지면 이전 값을 지우고 기존 기본값을 사용한다.
- 기존 observer와 예약 경로로 전체화면 클래스 변경·네이티브 볼륨 부품 교체를 감지한다. 호버·키보드 포커스·드래그 중 표시점 확대는 CSS로 처리한다.

## 검증

- 배율 반영·일반 크기 복귀와 표시점·트랙 동기화 회귀 테스트 2개는 수정 전 실패했다. 수정 후 관련 8개가 통과했다.
- 전체 `npm.cmd run test:all` 808개와 린트·전체 포맷 검사, `git diff --check`가 통과했다.
- 자동 검사는 JSDOM에서 치수를 제공한 모형이다. 실제 확장 재로드·주입, 라이트·다크 화면, 시각적인 강조 효과와 전체화면 경계 배치는 미검증이다. 사용할 수 있는 독립 브라우저 도구가 없고 컴퓨터 사용 도구는 사용하지 않았다.
- 수동 확인: 확장 재로드와 치지직 탭 새로고침 후 일반/전체화면에서 기본 볼륨 바와 컴프레서 바를 비교한다. 퍼센트 글자 크기·위치, 표시점·트랙 두께, hover·Tab 포커스·드래그 강조, 전체화면 해제 후 원래 크기 복귀를 라이트·다크에서 확인한다.
