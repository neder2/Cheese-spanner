# 그리드 이용 조건과 대안 조사 — 2026-09-14

## 결론과 범위

조사 목적은 **Windows의 기존 브라우저에서 고화질을 유지하며, 네이버 약관을 지키는 방식으로 그리드를 사용하지 않을 수 있는지** 확인하는 것이에요.

확인한 공식 약관·도움말·공개 플레이어 코드·판례에서는 이 조건을 모두 만족하는 확장 프로그램 방식을 입증하지 못했어요. 그렇다고 모든 UA 변경이나 그리드 회피가 곧바로 불법이라는 결론도 나오지 않아요. 실제 운영체제에서 공식 플레이어가 제공하는 재생을 이용하는 방법과, 플레이어의 환경 판정·재생 정보를 바꾸는 방법을 구분해야 해요.

테스트 후보는 아래에 남겼어요. 이번 조사에서는 공개 자료를 읽고 코드를 정적으로 분석했으며, 브라우저 설정 변경·설치 프로그램 실행·재생 실험·확장 기능 수정은 하지 않았어요. 정적 코드에서 확인한 조건은 해당 환경에서 실제로 실행됐다는 증명이 아니에요.

## 공식 약관에서 확인한 내용

### 커넥터 설치·삭제와 그리드

[공식 NLiveConnector 설치 파일](https://appdown.pstatic.net/naver/nliveconnector/NLiveConnectorSetup.exe)에 포함된 한국어 이용약관을 실행 없이 추출했어요. 현재 배포본에 들어 있는 문서의 시행일은 **2020-04-01**이에요.

- 제7조 제3항: 프로그램 실행 중 이용자 간 미디어 전송을 위해 PC와 네트워크 자원의 일부를 사용할 수 있다고 정해요.
- 제9조 제2항: 이용자는 언제든 프로그램을 삭제해 계약을 해지할 수 있어요.
- 제5조 제2항: 커넥터 프로그램의 개작·변경·역분석 등을 제한해요.

설치 거부·삭제가 가능하다는 근거는 있지만, 그리드만 제외하면서 고화질을 받을 권한이나 별도의 선택권을 보장하는 조항은 확인하지 못했어요. 커넥터 약관의 프로그램 변경 제한을 모든 브라우저 설정 변경에 그대로 적용할 수도 없어요.

### 네이버 공통 약관

[네이버 이용약관](https://policy.naver.com/policy/service.html)의 확인한 시행일은 **2025-07-10**이에요. 서비스 또는 포함된 소프트웨어의 복사·수정·변형 등을 제한하지만, UA 변경을 이름으로 명시해 금지하는 문구는 찾지 못했어요.

따라서 브라우저 기본 기능이라는 이유만으로 그리드 회피 목적의 사용까지 허용된다고 단정할 수 없고, 반대로 UA 변경만으로 곧바로 위법이라고 단정할 수도 없어요. 같은 페이지의 자동화·어뷰징 방지 조항 역시 모든 확장 프로그램을 일괄 금지하는 문구로 확대 해석하지 않았어요.

## 법률과 판례가 말해 주는 범위

- [대법원 2022. 5. 12. 선고 2021도1533](https://www.law.go.kr/precInfoP.do?precSeq=221765)은 정보통신망 접근권한을 보호조치·약관 등 객관적 사정으로 판단해요. 해당 사건의 정보 이용 제한 조항만으로 API 접근이 제한됐다고 보지는 않았어요. 약관 문제와 형사상 침입이 자동으로 같아지는 것은 아니지만, 이 판결이 치지직 고화질 제한 우회를 허용한 것은 아니에요.
- [저작권법 제2조 제28호](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0002&lsiSeq=283335&urlMode=lsScJoRltInfoR)와 [제104조의2](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=02&joNo=0104&lsiSeq=283335&urlMode=lsScJoRltInfoR)는 기술적 보호조치와 무력화·관련 도구 배포를 규율해요. 치지직의 해당 그리드 조건이 법률상 보호조치인지 직접 판단한 공개 판례는 이번 조사에서 찾지 못했어요. 무료 배포라는 사실만으로 이 쟁점이 사라지지는 않아요.
- [대법원 2010. 9. 30. 선고 2009도12238](https://law.go.kr/LSW/precInfoP.do?precSeq=146317)은 이용자 PC의 광고 대체·삽입 사건이에요. 현실적인 정보처리 장애가 없다는 이유로 컴퓨터등장애업무방해는 부정했지만, 광고 출처 혼동에 관한 부정경쟁 판단은 별도로 했어요. 이를 모든 광고 차단이나 그리드 우회가 합법이라는 근거로 사용할 수 없어요.

‘개인 시청’, ‘무료 확장 배포’, ‘네이버 약관 준수’는 각각 별도로 검토해야 해요. 기술 테스트가 성공하더라도 약관상 허용 여부까지 증명되지는 않아요. 치지직 올인원에 전달됐다는 공문 원문은 확보하지 못했으므로, 실제 문제 삼은 조항이나 요구 범위는 확정하지 않았어요.

## 현재 공개 코드에서 확인한 내용

### PC: UA만으로 결정하지 않아요

2026-09-14 라이브 HTML이 참조한 [PC 엔트리](https://ssl.pstatic.net/static/nng/glive/resource/p/static/js/index-GNyFfAPg.js)와 [플레이어 번들](https://ssl.pstatic.net/static/nng/glive/resource/p/static/js/player-vendor-BYg0wCyN.js)을 데이터로 읽었어요.

- PC 엔트리가 UA 추가 검사 플래그를 켜요.
- 실제 연결된 플레이어 모듈 `9352`는 Windows UA 또는 GPU 렌더러의 Windows 표식(`Direct3D`, `WDDM` 등)을 확인해요. 브라우저 지원 여부도 함께 판단해요.
- 모듈 `99112`는 가능한 경우 `Navigator.prototype.userAgent`의 원래 getter를 사용해요. 단순한 JavaScript 속성 덮어쓰기와 DevTools UA 변경은 같지 않아요.
- Opera도 지원 브라우저 목록에 있고 URL scheme으로 커넥터를 연결하는 경로가 있어요. 브라우저 확장이 없다는 사실만으로 커넥터까지 없다고 판단할 수 없어요.

따라서 ‘Mac Opera UA로 바꿨다’만으로 P2P 미사용을 결론 내릴 수 없어요. Client Hints도 일관되게 기록할 필요는 있지만, 이번에 추적한 그리드 OS 판정의 핵심은 UA와 GPU 정보였어요.

[Chrome 공식 문서](https://developer.chrome.com/docs/devtools/device-mode/override-user-agent/)도 UA 변경은 브라우저가 자신을 알리는 방식을 바꾸며, Chrome 내부 동작 자체를 다른 브라우저로 바꾸지는 않는다고 설명해요.

### 모바일 웹: P2P 비활성과 360p 제한이 함께 있어요

공식 모바일 라이브 주소의 HTML은 일반 GET에 200을 반환했어요. 이것은 재생 성공을 뜻하지 않아요.

[모바일 엔트리](https://ssl.pstatic.net/static/nng/glive/resource/m/static/js/index-D14R1oox.js)의 본 라이브 컴포넌트 `JC` → `YC` → 실제 사용부를 추적했어요. `LiveProvider.fromJSON`에 `p2pDisabled: true`, `track: 360`, `maxLevel: 360`을 전달해요. 초기 트랙 선택과 후속 화질 제어에도 360p 조건이 있어요.

모바일 웹의 공식 재생 경로는 P2P 비활성의 정적 근거가 있지만, **고화질을 유지하는 대안으로는 맞지 않아요**. 이번 엔트리에서 확인한 PC 강제 이동 함수는 일부 채팅·후원·구독 경로를 대상으로 하며 `/live/`는 포함하지 않았어요. 다른 모듈·서버 조건이나 실제 Windows 재생까지 확인한 것은 아니에요.

### 현재 Better Chzzk 방식과의 차이

조사 시점의 `features/gridBypassPage.js`는 `JSON.parse`를 감싸 공식 재생 데이터의 `p2pPath` 계열을 제거하고 `meta.p2p`를 false로 바꿔요. 단순히 커넥터 설치를 거절하거나 실제 다른 OS에서 접속하는 방식과는 달라요.

이 동작을 약관에 부합한다고 입증할 근거는 확보하지 못했어요. 설명을 없애거나 GitHub에서만 코드를 제외해도 배포 패키지의 실제 동작에 대한 판단은 달라지지 않아요. 이 문서는 기능 삭제·활성화·배포를 실행한 기록이 아니에요.

## 추가 조사: Windows 확장 안에서 가능한 타협안

사용자가 다른 방법을 요청해 같은 날짜에 공식 PC 엔트리의 재생 경로를 추가로 추적했어요. 업로드만 끄면서 고화질을 유지하는 공식 사용자 설정은 확인하지 못했어요. 공개 코드의 일부 설정명 검색 결과만으로 커넥터 내부에 그러한 기능이 전혀 없다고 단정하지는 않아요.

### 홈·채널 상단의 기존 미리보기 확대

`index-GNyFfAPg.js`의 `FP` 컴포넌트(문자 범위 1882062–1884808)는 홈·채널 상단에서 쓰는 공식 미리보기 플레이어예요. `LiveProvider.fromJSON`에 `p2pDisabled: true`를 전달하고, `maxLevel`은 프로파일 조건에 따라 `PP=480` 또는 `NP=720`으로 정해요. 준비 시 음소거하며, 페이지와 활성 상태에 따른 재생 제어가 있어요.

**1080p를 요구하지 않는다면**, 확장이 현재 페이지의 이 공식 플레이어를 확대하고 주변 배치를 조정하는 방법은 추가 테스트할 후보예요. 이 가설은 미리보기의 재생 주소를 가져와 새 플레이어로 교체하거나 화질 상한을 변경하는 것을 포함하지 않아요.

이는 고화질 라이브 우회의 완성된 대안이 아니에요. 실제 제공 해상도, 공식 소리 켜기 조작 유무, 장시간 유지, 채팅과의 조합, 실제 그리드 미사용을 아직 검증하지 않았어요. 약관에 대한 명시적 허락을 확보한 것도 아니에요. 확장만으로 할 수 있는 화면 조정과 별도의 재생 제한 변경을 구분하기 위한 후보예요.

### 타임머신·다시보기는 구분해야 해요

라이브 플레이어 `JY`는 타임머신 접근 조건을 확인하지만, `p2pDisabled`는 공통 그리드 상태인 `p2pAvailable`에 연결해요. 타임머신이라는 이유만으로 항상 그리드를 끄는 독립 분기는 이 경로에서 확인하지 못했어요.

동영상 플레이어 `CQ`는 `liveRewindPlaybackJson`이 있는 경우 `p2pDisabled: true`, `maxLevel: 1080`을 지정해요. 그러나 이는 동영상 정보(`videoNo`)를 받아 구성하는 재생 경로예요. 현재 라이브를 그대로 대체할 수 있다고 판단하지 않았어요. 타임머신과 방송 종료 후 제공되는 다시보기 경로를 혼동하지 않아요.

공식 엔트리에는 제한된 미리보기 상태에서 1080 설정을 사용하는 다른 분기도 있어요. 그 분기의 이용 조건·시간 제한을 유지한 채 일반 라이브를 계속 시청할 수 있다는 근거는 없으므로 해결책으로 제시하지 않았어요.

추가 조사도 정적 분석만 수행했어요. 브라우저 조작·설치·확장 기능 수정은 하지 않았어요.
