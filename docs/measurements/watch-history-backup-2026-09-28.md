# 시청 기록 백업 구현·자동 검증

2026-09-28, branch `1.4.1`, 시작 HEAD `ea22dfcdbeb167a75b038e50e9780afaa3aa221a`에서 구현했어요. manifest·package는 `1.4.0`을 유지해요. 기존 저지연·배너 변경을 보존했고 커밋·공개 배포는 하지 않았어요.

## 구현 범위

기록 페이지의 **기록 백업·관리·삭제 안내**에 **백업 파일 저장**, **백업 파일 불러오기**를 추가했어요. 전체 기간의 시청·내 채팅만 JSON으로 저장해요. 실시간·조회 후원 모두 제외하며, 불러올 때 현재 후원은 유지해요. 파일 선택 후 기간·방송·채팅 수·추가·갱신·동일·건너뜀·삭제 복원 내용을 미리 보여주고 사용자가 확인하면 합쳐요. 옵션 페이지에는 이용 위치와 링크를 안내해요.

파일 변환·검증, 순수 병합, 워커의 문서·토큰 검증, 페이지 파일 조작을 분리했어요. 실제 쓰기는 기존 background 큐 하나를 사용해요. 같은 파일 재적용은 중복 누적되지 않으며, 삭제 복원은 파일에 든 자료만 예외로 보호해요. 후원과 채팅 정리 경계를 분리하고, 상세가 없는 기존 합계의 병합은 건너뛰어 현재 기록을 보존해요.

신규 회귀는 `watch-history-backup`, `watch-history-backup-merge`, `watch-history-backup-controller`, `history-backup-ui`에 있어요. 기존 시청·활동·후원·페이지·배포 안전 검사도 함께 실행했어요. UI 검사는 실제 controller·merger·store를 연결한 합성 저장소에서 파일 선택과 미리보기·확인 저장·기록 화면 재조회를 검증해요.

기본 `npm.cmd run lint`는 다른 작업의 임시 보관 테스트 사본 두 개에서 `require` 전역 선언 오류 8개로 종료 코드 1이었어요. 보관 사본만 실행 인자로 제외한 프로젝트 소스 전체 검사는 통과했어요. 사본과 검사 설정은 수정하지 않았어요.

원본 파일 왕복, 구형 다시보기·세션 시각·URL 변환, 금지 필드·위험 URL·합계 모순 거부, 같은 파일 반복 적용, 겹친 탭·세션, 삭제→복원→늦은 메시지/ID 연결→새 삭제, 후원 보존, 확인 만료·동시 변경·읽기/쓰기 오류·큐 회복을 확인했어요. 파일 선택 취소·동일 파일 재선택·늦은 읽기·페이지 이탈·응답 손실·빈 파일·전부 동일·전부 건너뜀도 확인했어요.

최종 독립 검토는 차단 사항 없이 승인됐어요. 여러 임시·정식 방송의 복원 범위가 각각 유지되는지, 상세 없는 여러 행의 합계를 같은 숫자라는 이유로 합치지 않는지, 시청과 채팅의 복원 범위를 따로 갱신해 늦은 ID 연결에서도 자료가 보존되는지를 추가 회귀로 확인했어요.

2,000개 방송·3,000개 한국어 채팅의 합성 원본 10,468,409바이트에서 compact JSON 백업 10,445,238바이트를 만들고 재입력했어요. 16 MiB 파일 상한 아래의 계산 검증이며 실제 사용자 자료나 Chrome 메시지·저장 성공 실측은 아니에요.

## 미수행 범위와 수동 확인

실제 Chrome 확장 재로드·파일 대화상자·다운로드 완료·워커 재시작·복원과 두 테마/좁은 화면의 실제 배치는 확인하지 않았어요. 컴퓨터 제어 도구 사용에 관한 기존 작업 경계를 유지했어요. 실제 사용자 기록에 삭제나 복원을 실행하지 않았어요.

개발 확장을 다시 로드하고 옵션의 시청 기록 안내에서 페이지를 열어 저장한 파일을 다시 선택해 미리보기·취소·재선택을 확인해요. 별도 검증 프로필에서는 파일 병합·반복 적용·삭제 자료 복원·현재 후원 보존을 확인해요. 미리보기 후 워커를 재시작하면 저장 전에 재확인을 요구해야 해요. 라이트·다크·좁은 화면·키보드에서 버튼·내용·포커스·오류 안내도 확인해요.
