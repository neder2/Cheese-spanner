# 1.3.7 자동 화질 초기화 최적화

## 범위

2026-09-14, 사용자 요청에 따라 브랜치 `1.3.7` / HEAD `b2f22a2b6e36ea3c1402c3b22580b3f644c3f4a2`에서 진행했어요. 첫 playing까지 기다리는 안전장치와 네이티브 화질 선택·안내 닫기를 유지하면서 반복 조회·정보 탐색·예약을 줄였어요. 버전 증가·커밋·push·릴리스는 수행하지 않았어요.

## 발견한 중복과 수정

- 이미 예약한 즉시 실행도 요청마다 취소하고 다시 예약했어요. 먼저 잡힌 실행 시점이 더 빠르면 유지하고, 더 이른 실행이 필요한 경우에만 앞당겨요. 실행할 때는 최신 옵션을 사용해요. MAIN world와 isolated world에 동일하게 적용했어요.
- 첫 playing과 네이티브 화질 선택 Promise를 기다리는 동안 두 world가 반복해서 적용을 요청할 수 있었어요. 이때만 응답에 `waitForEvent: true`를 넣어 반복 타이머를 정리해요. 기존 playing 리스너와 선택 Promise 완료가 적용을 재개해요. 플레이어·트랙이 아직 발견되지 않은 일반 대기는 기존 제한된 재시도를 유지해요.
- 직접 연결된 플레이어에 유효한 videoTracks가 있어도 내부 객체 그래프를 먼저 펼쳤어요. 직접 트랙이 유효하면 즉시 사용하고, 없는 경우에만 기존 후보 순서로 추가 탐색해요.
- 리스너 연결과 실제 선택이 같은 적용 과정에서 트랙 목록을 두 번 찾았어요. 같은 동기 실행 안에서 한 번 확인한 목록을 두 단계가 공유해요. 여러 적용·라우트 사이에 목록을 장기 캐시하지 않아요.
- 선택 Promise가 끝나기 전에 selected 표시만 바뀐 경우에도 대기 상태를 유지해요. 성공 확인을 앞당겨 표시하지 않으며, 실패·옵션 끄기·새 플레이어의 기존 정리 동작을 유지해요.

첫 재생의 다음 task에서 화질을 적용하는 순서는 유지했어요. 새 타이머·더 짧은 반복 간격·play 강제 호출·메타데이터 수정·네트워크 요청은 추가하지 않았어요. 기존 그리드 방식으로 복귀하지 않아요.

## 회귀 근거

수정 전 새 검사 4개가 실패하고 수정 후 통과했어요. 같은 40회 옵션 갱신에서 MAIN의 최초 예약 ID가 1에서 41로 바뀌던 사례는, 수정 후 최초 예약 1개를 그대로 유지해요. 초기 재생·미완료 선택 중 남던 반복 타이머는 없어지고 실제 완료 신호로 다시 시작해요. 확인된 직접 트랙이 있는데도 발생하던 내부 객체 접근 2회는 0회가 됐고, 한 번의 적용에서 트랙 getter를 한 번 읽는 것을 확인했어요.

두 world를 실제 콘텐츠 유틸과 함께 로드한 추가 검사에서 각 world의 예약을 하나씩 유지하고, 첫 재생 대기 중 양쪽의 반복 타이머가 모두 정리되는 것을 확인했어요. 대기 도중 720p로 바꾼 최신 설정 적용과 비활성화 정리도 확인해요. 네이티브 화질 18개와 안내 닫기 10개, 관련 검사 총 28개가 통과했어요.

이 수치는 정해진 입력을 준 회귀 검사에서의 작업 횟수예요. 실제 브라우저의 첫 영상 표시 시간이나 목표 화질까지의 시간을 동일 조건으로 전후 비교한 수치는 아니에요. 커넥터 확인·기본 화질 첫 재생·목표 화질 전환에 필요한 네이티브 로딩은 남아 있어요.
