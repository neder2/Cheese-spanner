## 자동 재현으로 확인한 문제

아래는 현재 소스와 HEAD 소스를 각각 독립 JSDOM에 넣어 비교한 **합성 조건**이에요. 실제 사이트에서 이 문구·DOM 전이가 발생했다고 주장하지 않아요. 임시 스크립트와 결과는 `/tmp/chzzk-*-20261017.*`에 두었으며 저장소 테스트를 약하게 만들거나 수정하지 않았어요. 각 스크립트는 순차 실행했고 종료 코드 0으로 관측값을 출력했어요.

### 1. 정상 모달의 광고 관련 단어를 일반 닫기 대상으로 오인해요

- 근거: `features/adblockPopup.js`의 `isAdblockPopupLike`(143–150행)는 팝업 전체의 `adblock` 또는 떨어져 있는 `광고`·`차단`을 모두 허용해요. 307–327행은 이번에 추가한 `팝업 닫기`도 실제로 눌러요.
- 재현: 제목은 `사용자 정보`, 본문은 `닉네임: Adblock연구소` 또는 `닉네임: 광고문의 · 사용자 차단`, 전용 광고 안내 식별자 없이 일반 모달로 만들었어요. `팝업 닫기`에서는 HEAD가 0회·유지, 현재 코드가 1회·제거였어요. `닫기`에서는 HEAD/현재 모두 1회·제거였어요. 일반 로그인 문구 대조는 둘 다 0회·유지, 관측된 광고 안내 문구를 넣은 합성 양성 대조는 의도대로 처리됐어요.
- 영향: 광고 차단 안내가 아닌 정상 팝업을 닫을 수 있어요. 넓은 키워드 판별은 기존 문제이며, 이번 라벨 추가가 그 영향을 현재 공용 닫기 버튼까지 넓혔어요.
- 재현에서 DOM을 제거한 것은 합성 닫기 핸들러예요. 확장이 잘못된 버튼에 click을 전달한 결과를 측정했으며, 정상 팝업을 직접 삭제하는 별도 코드가 있다는 뜻은 아니에요.
- 후속: 일반 본문·닉네임 키워드만으로 승인하지 않고 안내 제목·전용 식별자·도움말 등 실제 광고 안내의 독립 근거로 좁혀야 해요. 새 별칭 자체를 없애기보다 대상 판별을 바로잡는 편이 적절해요.

### 2. 숨긴 SVG 안의 문구도 설치 안내 근거로 사용해요

- 근거: `features/qualityInstallGuide.js`의 `shown`(83–91행)은 `HTMLElement`만 조상을 검사하지만 새 `guideContents`(138–168행)는 모든 `Element`의 텍스트를 읽어요.
- 재현: 화면의 문단은 `플레이어 설정을 확인하세요.`, 알려진 설치 안내 문구는 `aria-hidden=true`, `display:none`인 SVG의 `title`에만 넣고 나머지 구조와 두 버튼은 유지했어요. HEAD는 미설치 버튼 0회, 현재는 1회였어요. 보이는 문단의 정상 안내 대조는 둘 다 1회였어요. 설치 버튼은 어떤 조건에서도 누르지 않았어요.
- 영향: 화면에 보이는 안내가 일치하지 않아도 합성 안내의 일반 화질 버튼에 click을 전달했어요. 실제 화질 변경 handler는 연결하지 않았으므로 화질 변경까지 재현한 것은 아니에요. 이번 본문 탐색 확장에서 생긴 오탐 조건이에요. 실제 사이트의 현재 안내는 p/strong 기반이라 이 구조의 발생 여부는 미확인이에요.
- 후속: SVG의 title/desc 같은 표시용 본문이 아닌 텍스트를 의미 근거에서 제외하고, 아이콘 하위 요소도 상한·추가 동작 검사는 유지해야 해요.

### 3. 같은 표시 상태의 설치 안내를 다시 누를 수 있어요

- 근거: `features/qualityInstallGuide.js` 221–225행은 문구 미일치만으로 `handled`·`button`을 초기화해요.
- 재현: 첫 미설치 클릭 뒤 안내를 계속 표시하고 설치 버튼 문구만 `처리 중` → 원래 문구로 바꿨어요. 같은 root·같은 미설치 버튼·계속 표시된 상태에서 HEAD와 현재 모두 미설치 클릭이 1 → 2회로 늘었어요. 설치 클릭은 0회였어요.
- 영향: 같은 표시 수명에 같은 버튼의 click을 두 번 전달해요. 실제 네이티브 handler의 부작용은 모델링하지 않았고, 사이트가 같은 중간 문구를 사용하면서 안내가 남는 경우의 반복 호출 가능성이에요. 이번 보강에서 새로 생긴 문제는 아니고, 실제 치지직의 해당 전이는 미관측이에요.
- 후속: 단순 문구 미일치와 새로운 표시 수명을 구분해, 숨김 후 재표시·재삽입·실제 버튼 교체처럼 의도된 조건에서만 다시 허용해야 해요.

## 본영상과 광고 소유 검토

새 ref 위치 대응은 같은 컴포넌트의 유일한 인접 쌍과 현재 채널·liveId·SDK 등록·video/container·alternate 일치·적용 직전 후보집합을 확인해요. 일정은 복사본의 `adSources`만 바꾸며 원본·순서·시간은 유지해요. 이번 검사에서 본영상 소스·시간·정지 상태가 잘못 바뀌었다는 증거는 없어요.

다만 기존 `isCurrentScheduleOwner`(492–523행)는 최초 검사와 달리 같은 host fiber 내부의 `stateNode`와 video host의 `return`을 재확인하지 않아요. 표시 정보 조회 도중 이 내부값 하나를 바꾼 세 합성 조건에서도 광고 일정은 변환됐어요. 별도 본영상의 src 속성 쓰기 0회, 시간 123·정지 상태 유지였어요. 이는 **소유 재검증 공백**이며 실제 React 전이·다른 본영상에 대한 피해를 입증한 결과는 아니에요. 방어 강화 후보로 구분하고 실제 발생 결함으로 단정하지 않아요.

확인형 광고 안내의 전용 식별자·도움말·단일 버튼·현재 React 연결 검증에서 별도의 신규 일반 모달 오호출은 발견하지 못했어요. 함수의 모양만으로 내부 상태 setter 의미까지 영구 보장할 수는 없으므로 향후 배포 코드의 실제 연결은 계속 확인해야 해요.

## 종료 상태와 검사 범위

- 옵션 화면에서 동영상 광고 차단·시청 방해 팝업 제거가 모두 ON이고 저장됨·저장 버튼 비활성임을 재확인했어요. 확장 관리 화면의 AdGuard는 사용 안함으로 유지됐어요.
- 직접 연 두 방송·옵션·확장 관리 탭을 닫고 사용자의 기존 치지직 탭은 보존했어요. 다른 옵션·확장·계정 설정은 변경하지 않았어요.
- 이번 후속에서는 런타임·상시 테스트를 바꾸지 않았어요. 합성 비교 스크립트 4종을 순차 실행해 관측값을 대조했고, 수정한 문서 4개의 포맷 검사와 `git diff --check`를 통과했어요. 전체 런타임 테스트·lint는 코드 변경이 없어 반복하지 않았어요. 이전 전체 검사 통과가 이번에 새로 찾은 오탐 조건까지 검증했다는 뜻은 아니에요.

## 후속 구현: 필요한 프로필·신고 창 예외 (같은 날 21시대)

앞 절은 수정 전 리뷰 기록이에요. 이후 사용자가 필요한 정상 팝업만 예외 처리하도록 요청해 `1.4.5`, HEAD `3f852d3` 위에서 `adblockPopup.js`와 회귀 테스트를 수정했어요. 버전·커밋·배포는 하지 않았어요.

- 실제 일반 Chrome의 Elements에서 내 프로필은 `role=alertdialog`, `aria-modal=true`, `_container_xwsra_2`와 내부 `button._profile_xwsra_38`를 확인했어요. 다른 사용자 닉네임 팝업은 `_container_y6scg_2`와 내부 `_contents_y6scg_5`·`_control_y6scg_300`을 확인했어요. 닉네임 문자열을 수집하거나 계정 프로필을 변경하지 않았어요.
- 현재 공개 페이지 번들 `index-uNhAs37B.js`에서 방송·영상·클립 신고의 `신고하기` 제목과 `ul[role=radiogroup] input[type=radio][name=report-reason]`, 스트리머샵 신고의 `스트리머샵 신고하기`와 `ul[role=group] input[type=checkbox][name=report-reason]` 조합을 확인했어요. 공유용 `#spi_button.naver-splugin`은 팝업이 아닌 실행 버튼이므로 예외 근거로 쓰지 않았어요.
- 프로필은 전용 클래스 토큰의 숫자 접미사 변화와 내부 래퍼·문구 변화에 대응해요. 신고는 제목 공백·줄바꿈과 내부 래퍼 변화에 대응해요. 근거 요소와 입력 그룹은 현재 팝업 소속이어야 하며, DOM 재사용·`name/type` 속성 변경 때 다시 판단해요. 이 조건을 충족한 창은 숨기거나 버튼을 클릭하지 않아요. 전용 광고 확인 안내 경로는 먼저 평가하고 기존 동작을 유지해요.
- 수정 전 팝업 검사 40개 중 17개가 실패해 프로필·신고 오탐을 재현했어요. 수정 후 팝업 닫기·확인형 광고 안내·설치 안내 관련 검사 108개가 통과했어요. 두 종류 광고 관련 닉네임, 두 닫기 라벨, 신고 제목, 클릭·submit 0회, 형제 광고만 처리, 재사용, 입력 속성 변경, 불완전 구조·팝업 밖 그룹의 부정 대조를 포함해요. 변경 JS lint·변경 파일 포맷·diff 공백 검사를 수행했어요. 공용·재생·권한·설정 경계 변경이 없어 전체 검사는 반복하지 않았어요.
