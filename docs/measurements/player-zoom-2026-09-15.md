# 플레이어 휠 확대 구현과 검증 범위

- 날짜: 2026-09-15 (KST)
- 브랜치: `1.3.8`, 작업 시작 HEAD: `659ad7ff5782bea66cf2ce1d395a80b41f1fd83b`
- 요청: 커서 중심 휠 확대, 플레이어 버튼으로 확대 모드를 켠 동안만 적용하는 방식과 항상 적용하는 방식 선택.
- 동작 참고: [Discord 2026-02-04 패치 노트](https://discord.com/blog/discord-patch-notes-february-4-2026)의 화면공유·게임 스트림 확대 및 이동. Discord의 배율 한계나 세부 UI를 동일하게 실측했다는 의미는 아니다.

## 구현

- `playerZoomEnabled` 기본값은 꺼짐, `playerZoomMode` 기본값은 `manual`이다. 옵션을 켜면 `manual`은 플레이어 돋보기 버튼으로 확대 모드를 전환하고, `always`는 영상 위 휠을 바로 처리한다.
- 현재 커서 아래의 영상 좌표를 유지하며 1–5배로 확대한다. 확대 중 왼쪽 드래그로 이동하고, 되돌리기 버튼이나 수동 모드 끄기로 복원한다. 영상 비율에 따른 여백과 이동 경계를 계산한다.
- 메인 영상에만 transform과 clip을 적용하고 네이티브 DOM 부모와 컨트롤은 유지한다. 볼륨·재생바·설정·보조 영상·미리보기·조합키는 대상에서 제외한다.
- 확대 중 메인 영상 드래그는 확대 영역 이동이 소유한다. 멀티뷰의 Alt 드래그와 보조 영상 드래그는 기존 동작을 따른다. 드래그 직후 발생하는 클릭만 막고 일반 클릭·더블클릭의 기본 동작은 유지한다.
- 휠·드래그 경로에서 전체 영상 목록을 다시 찾지 않는다. 관련 DOM 교체 때 공용 메인 영상 선택기를 사용하며, 페이지 이동·소스 변경·옵션 해제·pagehide에서 확대와 관련 리스너·관찰자를 정리한다.
- 창 크기·전체화면 변경 시 영상 크기에 맞게 확대 위치와 경계를 다시 계산한다. 확대 배율과 이동 위치는 저장하지 않는다.

## DOM 근거와 한계

네이티브 플레이어와 오른쪽 하단 컨트롤은 기존 `getPlayerRoot`와 `.pzp-pc__bottom-buttons-right`를 사용한다. 기존 [2026-09-14 스트림 정보 측정](stream-info-2026-09-14.md)과 [2026-09-15 베타 피드백 측정](beta-feedback-2026-09-15.md)에 기록된 구조를 참고했다. 이번 작업에서 실제 치지직 DOM을 새로 측정하지는 못했다.

현재 제공된 화면 조작 도구는 컴퓨터 사용 도구이며, 저장소 지침에서 별도 요청 전 사용을 금지하고 있다. 이 도구를 사용하거나 확장 관리 제한을 우회하지 않았다. 실제 확장 다시 로드·주입, 실방송의 휠·드래그, 라이트·다크 외관과 좁은 팝업은 미검증이다.

## 자동 검증

### 150% 이상 확대 시 왼쪽 버튼 소실 수정

- 사용자 보고: 150% 이상 확대하면 왼쪽 확장 버튼이 사라짐.
- 원인: 스킵·빨리 감기와 컴프레서의 컨트롤 위치 판정이 확대된 `video.getBoundingClientRect().bottom`을 사용했다. 영상의 실제 표시 영역은 clip으로 고정되어 있지만 이 값에는 transform이 반영된다.
- 재현: 라이브·VOD 통합 fixture에서 영상의 원래 위치를 `(100,60)`, 크기를 `800×450`, 컨트롤 중심 Y를 `490`으로 설정했다. 커서 `(300,100)`에서 150% 확대하면 영상 rect의 bottom이 `510`에서 `715`로 바뀐다. 컨트롤 허용 범위의 시작이 `715−150=565`가 되어 실제 컨트롤을 대상 밖으로 판정한다. 이 수치는 브라우저 실측이 아니라 회귀 테스트의 재현 좌표다.
- 수정 전 새 통합 테스트는 두 경로에서 모두 실패했다. 라이브에서 빨리 감기·스킵·컴프레서가 제거됐고, VOD에서 컴프레서가 제거됐다.
- 수정: 공용 `getVideoViewportRect`가 확대 기능이 등록한 변환만 역산해 원래 표시 영역을 반환한다. 컨트롤 판정과 볼륨 툴팁 배치는 이 영역을 사용한다. 변환 기록은 영상별 WeakMap에 두고 확대 해제·소스/라우트 변경·영상 교체 때 제거한다. 확대와 드래그도 같은 표시 영역을 사용하며, 다른 코드가 적용한 변환은 임의로 되돌리지 않는다.
- 수정 후 통합 테스트는 150%·500% 확대 중 원래 버튼 DOM이 유지되고 제거 후 재생성도 발생하지 않음을 확인한다. 드래그·창 크기 변경, 원래 크기 복원, 옵션 해제, SPA 이동, 영상 교체와 변환 기록 정리도 검사한다.
- 첫 전체 검증에서 기존 오디오 수명주기 fixture 종료 뒤 JSDOM의 제거된 document를 관찰하는 비동기 오류가 발생했다. 해당 fixture가 생성한 관찰자를 페이지 종료 전에 해제하도록 보완했으며 기존 동작 assertion은 유지했다.

### 확대 박스 슬라이더와 고정 배치

- 확대 표시와 되돌리기 버튼을 작은 패널로 묶고, 100–500% 범위의 `input[type=range]`를 추가했다. step은 1이며 입력 즉시 반영한다. 휠은 커서 중심, 슬라이더는 현재 표시 영역의 중심을 유지한다.
- 후속 요청에 따라 배율 표시·슬라이더·되돌리기 아이콘 순서의 한 줄로 줄였다. 패널은 180px 너비와 34px 높이를 기준으로 하고, 슬라이더가 남은 너비를 사용한다. 되돌리기는 기존 설정 화면의 복원 아이콘 경로를 재사용하며, 24px 버튼 안의 16px 아이콘과 접근성 이름·되돌리기 title 안내를 제공한다.
- 수동 모드는 켜는 즉시 100%부터 패널을 표시한다. 항상 적용 모드는 확대할 때 표시하며, 슬라이더가 100%에 도달해도 포커스나 드래그가 남아 있으면 계속 조절할 수 있다.
- 마우스가 접근하면서 네이티브 컨트롤이 나타나면 클릭하기 전에 박스가 위로 이동했다. 후속 요청에 따라 bottom을 64px로 고정하고 패널의 transform·transition과 컨트롤 표시 상태에 따른 위치 분기를 제거했다. 기존에 컨트롤이 보일 때 놓이던 위치를 항상 사용한다.
- 위치 고정용 계산·키보드 상태·포커스 진입 처리를 제거했다. 100%에서도 포인터 조절·키보드 포커스가 남아 있으면 패널을 유지하며, 네이티브 range의 포인터 캡처와 키보드 기본 동작도 유지한다.
- 기존 시맨틱 표면·텍스트·테두리 색상을 사용한다. 트랙은 2px, 손잡이는 10px이며 입력 영역은 24px 높이로 둔다. 배율은 고정 폭 숫자로 표시하고 버튼은 패널 안에서 별도로 구분한다. 패널의 이동·색상 전환 애니메이션은 없으며, `prefers-reduced-motion`에서는 버튼 누름 효과도 생략한다.
- 기존의 버튼 숨김·배율 텍스트 검사는 새 패널의 숨김·별도 배율 표시·되돌리기 버튼 검사로 옮겼다. 배율과 복원 계약은 유지하며, 1% 입력·중심 좌표 보존·100% 포커스 유지·키보드 기본 동작·마우스 진입과 컨트롤 표시 전환 시 위치 유지·패널 교체와 비활성화 정리를 검증한다. 마우스 진입 직후 컨트롤을 표시하는 테스트는 수정 전 52px 이동으로 실패하고 수정 후에는 동일한 위치를 유지한다.
- JSDOM에서 상태 전환과 CSS 규칙·테마 토큰 선택을 확인한다. JSDOM은 background의 CSS 변수 기본값을 실제 브라우저처럼 계산하지 못하므로 색상 대비와 실제 슬라이더 외관은 실브라우저 미검증 범위에 남긴다.

## 직접 확인할 순서

1. Chrome 확장 관리에서 치즈 스패너를 다시 로드한 뒤 치지직 탭을 새로고침한다.
2. 설정 → 플레이어 → 화면 확대에서 휠로 화면 확대를 켜고 저장한다. 버튼 방식에서 돋보기를 켜기 전·후의 휠을 비교한다.
3. 영상 여러 위치에서 150%·500%로 확대하고 드래그 및 원래 크기를 확인한다. 슬라이더를 1%씩 조절하고 방향키·Home·End도 확인한다. 왼쪽 스킵·빨리 감기·컴프레서가 유지되는지, 클릭 재생·더블클릭 전체화면과 볼륨·재생바 조작도 확인한다.
4. 적용 방식을 영상 위에서 항상으로 바꾼 뒤 저장하고, 버튼 조작 없이 휠이 적용되는지 확인한다.
5. 라이브·타임머신·VOD, SPA 이동·새로고침·전체화면·창 크기 변경·라이트·다크와 옵션 해제를 확인한다. 멀티뷰 메인 확대 중 드래그와 Alt 드래그도 구분해서 확인한다.
6. 하단 컨트롤이 숨겨진 뒤 되돌리기 아이콘에 마우스를 올린다. 네이티브 컨트롤이 다시 나타나도 확대 박스가 움직이지 않고 클릭할 수 있는지, 슬라이더와 키보드 조작 중에도 같은 위치인지 확인한다.
