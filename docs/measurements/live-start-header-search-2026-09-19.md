# 상단 방송 알림 버튼과 채널명 검색 — 2026-09-19

## 최종 사용자 흐름

- 사용자 요청에 따라 방송 하단·채널 페이지의 개별 등록 버튼을 없애고 치지직 우측 상단의 **방송 알림** 버튼 하나로 통합했다. 기존 파일·DOM ID·채널 저장 키를 유지한다.
- 버튼을 열면 등록 채널과 검색창이 나온다. 채널명을 입력하고 검색 또는 Enter를 누르면 최대 5개 결과를 표시한다. 프로필과 API가 제공한 팔로워 수로 동명 채널을 구분하고 **데스크톱 알림**·**자동 입장**을 각각 선택한다. 두 항목의 켬·끔을 함께 표시하며 검색어를 지우면 등록 목록으로 돌아간다. 자동 입장만 켠 채널, 두 항목을 모두 끈 채널도 목록에 유지해 다시 선택할 수 있다.
- **방송 알림 → 상단 방송 알림 버튼 표시**(`liveStartButtonEnabled`)는 기본 켜짐이다. 저장 후 즉시 표시를 바꾸며 기존 알림·자동 열기 동작과 채널 목록은 유지한다. 전체 알림은 기존대로 기본 꺼짐이고, 채널 등록만으로 알림 권한이나 전체 기능을 켜지 않는다.
- 버전·권한은 추가하지 않았다. GitHub 릴리스는 초안 상태를 유지하며 커밋·배포 패키지 재생성·릴리스 재게시를 하지 않았다.

## 수명주기와 데이터

- 검색 제출 1회당 검색 API 1회만 호출한다. 입력 중 자동 조회·상세 시청자 수 조회·주기적 검색은 없다. 중복 제출을 막고, 입력 변경·닫기·SPA 이동·헤더 재마운트·표시 해제 때 취소한다. 늦은 응답은 현재 패널을 바꾸지 않는다.
- 검색어와 검색 결과는 열린 패널의 메모리에만 둔다. 채널 목록 저장은 기존 백그라운드 직렬 큐를 사용하며 신규 채널의 ID와 이름은 채널 API로 확인한다. `set-notify`·`set-auto-open`은 해당 불리언 하나만 바꿔 나머지 선택을 보존한다. 어느 항목으로 처음 등록해도 다른 항목의 기본값은 꺼짐이다. 실제 저장 실패를 성공처럼 표시하지 않는다.
- 표시 해제는 화면의 관찰자·리스너·패널·버튼을 정리한다. 옵션 리스너는 유지해 다시 켰을 때 복원한다. 백그라운드 알림 감시는 별도 옵션 두 개만 따르므로 버튼 표시 여부에 영향받지 않는다.
- 등록 중 중복 클릭과 최신 저장소 상태를 덮는 늦은 응답을 막는다. 검색 결과 버튼은 채널 ID로 유지해 저장·상태 변경 때 키보드 포커스를 불필요하게 잃지 않는다. Esc와 닫기 버튼은 상단 버튼으로 포커스를 돌린다.
- 기존 개별 버튼 테스트는 사용자 요청으로 바뀐 흐름에 맞춰 상단 검색·선택 채널 등록 테스트로 교체했다. 저장 오류, 최신 상태 보존, SPA·재마운트·pagehide/pageshow, 관련 없는 DOM 변경의 무조회 보호 범위는 유지하고 검색 취소·표시 옵션을 추가했다.

## 검증

### 등록 목록 프로필 사진 수정

- 사용자가 사진 누락을 보고했다. 검색 API에는 `channelImageUrl`이 있지만, 등록 응답을 저장하는 코드와 `normalizeChannels`가 이를 남기지 않아 패널을 다시 열면 빈 아바타가 됐다. 사진이 없는 행에 메타데이터가 늦게 들어와도 기존 행의 이미지를 갱신하지 않는 문제도 있었다.
- `service/v1/channels/7ce8032370ac5121dcabce7bad375ced`의 현재 응답에서 검색과 같은 프로필 주소를 확인했다. 새 채널 등록·옵션 화면 추가 때 주소를 보존하며 공용 이미지 URL 검증을 거친 값만 저장한다. 후속 알림·자동 입장 변경도 이 필드를 유지한다.
- 기존 채널에서 누락된 주소는 열린 패널에서만 동시 최대 2개씩 조회한다. 현재 페이지의 캐시는 최대 32개이며, 검색 결과에서 이미 확인한 주소도 재사용한다. 입력 변경·닫기·라우트 이동·비활성화 시 취소한다. 오류나 ID가 다른 응답은 이미지를 공급하지 않고, 자동 재시도 루프를 만들지 않는다. 프로필 조회 실패도 알림·자동 입장 조작을 막지 않는다.
- 행을 새로 만들지 않고 사진 주소 변경만 반영한다. 같은 주소는 토글 변경 때 재요청하지 않고, 이미지 로드 실패 후 렌더링마다 반복 로드하지 않는다.
- 수정 전 패널 재오픈 테스트의 사진 누락을 재현했다. 사진 보존·기존 행 갱신·누락 주소 조회의 동시성·캐시 재사용·취소·ID 불일치와 기존 데이터 호환성을 검사했다.
- 독립 브라우저에서 실제 채널을 등록한 뒤 저장소의 사진 주소를 확인하고, 페이지 새로고침 후 등록 목록의 이미지가 실제 로드됨(`naturalWidth: 600`)을 확인했다.
- 사진 주소 없이 저장된 기존 채널도 별도 임시 프로필에서 API로 주소를 확인해 실제 이미지가 로드됨(`naturalWidth: 600`)을 확인했다. 320px 라이트·일반 다크 화면에서 이미지와 넘침 없음도 확인했다.

### 채널명 오른쪽으로 버튼 배치

- 사용자의 정정에 따라 글자 우측 정렬을 되돌리고, 채널명 아래에 있던 데스크톱 알림·자동 입장 버튼을 채널명 오른쪽의 같은 행으로 이동했다. 프로필·채널 정보·버튼 순서의 3열로 배치하며, 기존 상태·접근 가능한 이름·동작과 Pretendard 글꼴은 유지한다.
- 두 버튼은 12px 글자·30px 최소 높이로 줄이고 행 여백은 위아래 8px로 정리했다. 긴 채널명과 팔로워 수는 다른 버튼과 겹치지 않도록 말줄임하며 전체 내용은 title로 확인할 수 있다.
- 실제 검색 결과에서 행 높이 54.5px, 채널 정보와 버튼의 수직 중앙 정렬을 확인했다. 320px 라이트 화면에서도 모든 행에서 버튼이 이름 오른쪽에 위치하고 동일 행에 있으며, 패널과 행의 수평 넘침이 없었다. 데스크톱 알림 토글도 정상 반영됐고 페이지 JavaScript 오류는 없었다.

### 전체 확인

- 등록 채널이 많을 때 박스가 계속 커진다는 요청에 따라 목록의 콘텐츠 높이를 245px(현재 등록 행 약 5개)로 제한하고 내부 세로 스크롤을 적용했다. 검색창·제목은 목록 바깥에 유지한다. 포커스 테두리와 × 클릭 영역이 잘리지 않도록 목록 가장자리의 4px 여유는 남겼다.
- 실제 치지직 검색 API에서 받은 채널 8개를 독립 검증 프로필에 등록해 목록의 표시 높이 253px(안쪽 여백 포함), 전체 콘텐츠 399px, 행 높이 49px를 확인했다. 휠로 목록만 146px 이동하고 패널 높이 485px와 패널·페이지 scrollTop 0이 유지됐다. 키보드로 마지막 행 버튼에 포커스해도 목록이 스크롤됐으며, 라이트 테마와 3개로 줄었을 때 자동 높이 복원도 확인했다.

- 사용자 요청으로 각 등록 채널의 맨 오른쪽에 **× (등록 해제)** 버튼을 추가했다. 같은 행 배치를 유지하며, 검색 결과에는 실제 등록된 채널에만 이 버튼을 표시한다. 등록 목록에서 해제하면 행이 사라지고 검색 결과에서 해제하면 두 선택이 꺼지고 해제 버튼이 숨겨진다.
- 후속 요청으로 × 버튼의 테두리·배경·안쪽 여백을 없애고 배치 너비를 26px에서 16px로 줄였다. 높이는 24px이며, 주변 4px의 투명 클릭 영역으로 조작 여유를 유지한다. 실제 라이트·다크 화면과 hover에서 테두리 0·투명 배경을 확인했고, 배치 영역 바깥 2px를 눌러도 등록 해제가 동작하는 것을 검증했다. 키보드 포커스 표시는 유지한다.
- 기존 백그라운드 `remove` 명령을 같은 확장의 치지직 최상위 탭에도 허용했다. 발신자·출처·프레임·채널 ID 검사는 유지하며, 채널 전체 삭제는 기존 직렬 큐를 거쳐 두 기능과 해당 중복 방지 상태를 정리한다. 전역 옵션과 다른 채널 설정은 바꾸지 않는다.
- 해제 중 같은 채널의 조작을 잠그며 실패하면 기존 등록을 유지하고 오류를 표시한다. 검색 결과에서 숨겨진 해제 버튼의 키보드 포커스는 사용 가능한 선택 버튼으로 이동한다. 허용된 삭제·잘못된 발신자 거부·중복 클릭·실패·설정 동기화를 자동 검사했다.
- 실제 치지직에서 두 기능을 선택한 채널을 해제해 등록 행이 없어지고, 저장소의 대상 목록이 빈 배열로 바뀐 것을 확인했다. 380px 라이트 화면의 검색 결과에서도 등록된 채널에만 해제 버튼이 나타나고, 해제 뒤 두 선택이 꺼지는 것을 확인했다. 수평 넘침과 페이지 JavaScript 오류는 없었다.

- 수정한 색상으로 확장을 새 브라우저 세션에 다시 로드해 라이트·다크 패널을 검증했다. 홈에서 게임 탭으로 네이티브 SPA 이동 후 버튼이 하나이고 등록 목록이 유지되는 것을 확인했다. 관찰한 페이지 JavaScript 오류는 없었다.
- 520px 브라우저에서 패널이 화면 안에 위치하고, 420px 옵션 페이지의 라이트·다크 화면에서 수평 넘침이 없음을 확인했다. 옵션 패널의 진입 애니메이션 완료 후 화면을 확인했다.
- 최종 글꼴은 Chromium의 실제 렌더링 정보에서 `Pretendard Variable` / `PretendardVariable-SemiBold`, custom font 사용을 확인했다. 버튼의 계산된 크기·굵기·행간은 14px·600·19.6px이었다. 320px 라이트 화면에서도 두 항목이 한 줄에 함께 표시되고, 패널과 각 버튼의 scrollWidth가 clientWidth와 같았다. 다크 화면도 확인했으며 페이지 JavaScript 오류는 없었다.
- 실제 OS 데스크톱 알림 승인·거부와 새 방송 시작 전환은 이번 UI 변경의 실브라우저 확인 범위에 포함하지 않았다. 기존 자동 검사로 해당 동작 계약을 확인한다.
