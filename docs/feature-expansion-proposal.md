# Better Chzzk 추가 기능 기획안

작성일: 2026-09-14<br>
대상: Better Chzzk 저장소의 `1.3.7` 작업본 — 현재 확장 표시 이름은 **치즈 스패너**예요.<br>
상태: **요청 기능을 정리한 문서이며, 구현이나 출시가 확정된 명세는 아니에요.**

치지직 올인원 1.5.1과 비교한 뒤 선택하신 기능에, 시청 기록 백업·복원을 더해 정리했어요. 기능 목록은 사용자 요청을 기준으로 하고, 아래의 세부 조작·기본값·복원 방식은 검토용 제안이에요. 출시 버전과 개발 일정은 지정하지 않아요.

## 2. 기능별 동작 초안

### 2.1. 저지연 우선 설정

2026-09-28 사용자 요청으로 구현했던 독립 저지연 옵션과 제어를 제거했어요. 아래 내용은 당시 초안이며 현재 구현 계획이 아니에요.

**목표:** 같은 화질에서 사용할 수 있는 재생 방식 중 저지연 방식을 우선 선택할 수 있어요.

- 설정에 `저지연 우선`을 추가해요.
- 사용자가 선택한 화질을 기준으로, 실제 제공되는 트랙에서 저지연 재생 가능 여부를 확인해요.
- 저지연 트랙이 없을 때는 가능한 일반 트랙으로 재생하고, 적용 상태는 실제 결과를 바탕으로 표시해요.
- 사용자가 직접 고른 화질, 일시정지, 타임머신 위치, 멀티뷰에서 저장한 딜레이와 충돌하지 않도록 해요.
- 강제 배속으로 라이브를 따라잡거나 주기적으로 재생 위치를 이동하는 동작은 별도 요구로 다뤄요. 이번 요청은 저지연 방식의 우선 선택이에요.

**검토할 사항:** 기본 켜짐 여부, 자동 화질을 껐을 때의 동작, 옵션 변경의 즉시 적용 여부예요. 현재 작업본의 화질 선택 로직과 실제 플레이어 동작을 구현 시점에 다시 확인해요.

### 2.2. 앰비언트 효과

**목표:** 영상 주변의 여백에 영상 색상을 반영한 부드러운 빛 효과를 표시해요.

- 켜기·끄기와 효과 강도를 제공하는 구성을 제안해요.
- 효과는 영상과 조작 버튼을 가리지 않고, 플레이어 주변 배경에 적용해요.
- 기본 화면·넓은 화면·전체 화면에서 효과 범위를 조정해요.
- 초기 범위는 메인 영상으로 제안해요. 멀티뷰 보조 영상별 효과는 부하를 확인한 뒤 확장 여부를 검토해요.
- 꺼진 상태나 영상이 없는 화면에서는 색상 추출과 화면 갱신을 멈춰요.

**검토할 사항:** 강도 범위, 갱신 빈도, 숨겨진 탭에서의 처리, 밝은 테마에서의 표현이에요. 브라우저나 영상 조건 때문에 색상을 읽을 수 없으면 실제 적용 불가 상태를 안내해요.

### 2.3. 글꼴 설정

**목표:** 치지직 화면과 채팅의 글꼴을 사용자 취향에 맞게 선택해요.

- `치지직 기본 글꼴`로 돌아갈 수 있게 해요.
- 적용 대상을 `화면 전체`와 `채팅`으로 구분하는 구성을 제안해요.
- 글꼴 선택과 함께 굵기·채팅 글자 크기 조절을 검토해요.
- 한글·영문·숫자가 포함된 미리보기 문구로 적용 결과를 확인할 수 있게 해요.
- 아이콘과 이모티콘, 배지는 글꼴 변경 때문에 깨지지 않도록 해요.
- 설치된 글꼴이나 확장에 포함할 수 있는 글꼴을 우선 검토해요. 사용자 지정 원격 글꼴 주소 입력은 별도 범위로 남겨요.

**검토할 사항:** 제공할 글꼴 목록, 폰트 파일 배포 조건과 용량, 설정·시청 기록 페이지에도 적용할지 여부예요. 현재 옵션 화면에 적용된 Pretendard만으로 사용자 글꼴 선택 기능이 구현된 것으로 보지 않아요.

### 2.4. 채팅 위치·크기 조절

**목표:** 라이브·다시보기 화면에서 채팅을 보기 편한 위치와 너비로 배치해요.

- 위치는 `기본값 / 왼쪽 / 오른쪽`을 제안해요.
- 채팅과 영상 사이 경계를 드래그해 너비를 바꾸고, 키보드로도 조절할 수 있게 해요.
- `기본 크기로 복원`을 제공해요.
- 화면이 좁아지면 채팅과 영상이 사용할 수 있는 최소 공간을 확보해요.
- 기존 채팅 접기, 모아보기, VOD 댓글 탭과 전체 화면 동작을 함께 유지해요.

**검토할 사항:** 최소·최대 너비, 페이지 이동 후 기억 여부, 일반 화면과 넓은 화면의 크기를 따로 저장할지 여부예요.

### 2.5. 사이드바 위치·크기 조절

**목표:** 팔로잉 사이드바를 좌우로 배치하고 채널명을 읽기 편한 너비로 조절해요.

- 위치는 `기본값 / 왼쪽 / 오른쪽`을 제안해요.
- 경계 드래그와 키보드 조작으로 너비를 바꾸고 기본 크기로 되돌릴 수 있게 해요.
- 채널 고정, 폴더, 접기·숨김, 방송 미리보기의 기준 위치를 함께 갱신해요.
- 채팅과 사이드바를 같은 쪽에 지정했을 때의 순서를 일관되게 정해요.
- 미리보기 카드가 화면 밖으로 나가지 않도록 남은 공간에 맞춰 표시해요.

**검토할 사항:** 같은 쪽에 둔 채팅과 사이드바의 배치 순서, 접힌 사이드바 너비, 좁은 화면과 전체 화면에서의 동작이에요.

### 2.6. 팔로잉 폴더·접기·숨김

**목표:** 팔로잉 채널을 주제나 시청 습관에 따라 폴더로 분류해요.

- 폴더 생성·이름 변경·삭제와 순서 변경을 제공해요.
- 팔로잉 채널을 폴더에 넣고 빼거나 다른 폴더로 옮길 수 있게 해요.
- 폴더별 접기 상태를 기억하고, 방송 중인 채널 수를 표시하는 구성을 제안해요.
- 폴더에 넣지 않은 채널은 기본 목록에서 계속 확인할 수 있게 해요.
- 오프라인 채널 숨김과 폴더 접기는 별도 설정으로 유지해요.
- 폴더 삭제 시 채널은 기본 목록으로 돌아가며, 실제 치지직 팔로우는 해제하지 않아요.
- 고정 채널을 폴더 안에서 먼저 표시하는 방식을 우선 검토해요.

**현재 있는 기능:** `followingListStateEnabled`, `followingOfflineHidden`, `followingPinEnabled`와 관련 저장값을 활용할 수 있어요. 기존 사용자 선택을 새 폴더 설정으로 무조건 덮어쓰지 않아요.

**검토할 사항:** 한 채널의 여러 폴더 소속 허용 여부, 폴더 수 상한, 고정 채널의 표시 규칙, 폴더 숨김의 지원 범위예요.

### 2.7. 방송 시작 알림·지정 채널 자동 탭 열기

**목표:** 선택한 채널의 새 방송을 데스크톱 알림으로 확인하고, 원하는 채널은 방송 시작 시 자동으로 열어요.

- `방송 시작 알림`과 `방송 시작 시 자동 탭 열기`를 독립적으로 설정해요.
- 알림 대상과 자동 열기 대상은 채널별로 관리해요.
- 같은 방송의 상태를 여러 번 조회해도 알림·탭 열기는 한 번만 실행해요.
- 알림을 누르면 해당 방송으로 이동해요.
- 자동으로 열 채널의 방송 탭이 이미 있으면 중복으로 만들지 않는 방식을 제안해요.
- 자동 열기는 배경 탭을 기본안으로 하고, 현재 작업 중인 화면을 강제로 전환하지 않아요.
- 브라우저 실행 직후 이미 진행 중인 방송을 새 방송으로 처리할지 별도 규칙을 정해요.
- 기존 `offlineLiveReloadEnabled`는 열린 대기 화면의 새로고침을 계속 담당해요. 두 기능이 같은 방송에 중복 반응하지 않도록 연결해요.

**검토할 사항:** 확인 주기, 최초 상태 확인 기준, 알림 권한 거부 시 안내, 브라우저 재시작 후 중복 방지예요. 브라우저가 종료된 동안의 실시간 알림은 보장하지 않아요. 필요한 브라우저 권한은 실제 구현 방식에 맞춰 검토해요.

### 2.8. 채팅 멀티뷰

**목표:** 여러 방송의 채팅을 한 화면에서 함께 확인해요.

- 채널 URL 입력이나 팔로잉 선택으로 채팅을 추가하고 제거해요.
- 채널별 이름과 채팅 영역을 구분하고, 패널 순서와 크기를 조절할 수 있게 해요.
- 영상 멀티뷰를 켜지 않아도 사용할 수 있는 구성을 제안해요.
- 채널 구성과 배치를 저장해 다시 열 수 있게 해요.
- 최대 6개를 초기 검토안으로 두되, 실제 채팅 로딩·메모리 부하를 확인해 상한을 정해요.
- 채팅 작성은 각 채널의 로그인·작성 권한을 그대로 따르며, 입력 대상 채널을 분명히 표시해요.
- 일부 채팅을 불러오지 못하면 해당 패널에만 상태를 안내해요.

**검토할 사항:** 기존 멀티뷰 옆 배치와 별도 채팅 전용 화면 중 기본 진입 방식, 네이티브 채팅을 표시할 수 있는 경로, 채팅 도구·글꼴 설정 적용 범위예요. 올인원의 iframe 방식을 그대로 사용할 수 있다고 가정하지 않고 실제 표시 가능 여부를 확인해요.

### 2.9. 설정 파일 저장·불러오기

**목표:** 현재 설정을 파일로 저장하고, 재설치나 다른 브라우저 환경에서 다시 불러와요.

**백업 초안**

- `설정 파일 저장`으로 JSON 파일을 내려받아요.
- 파일에 형식 버전, 확장 버전, 내보낸 시각을 기록해요.
- 기능 옵션·단축키·고정 채널과, 향후 추가할 폴더·알림 대상·글꼴·배치 설정을 포함해요.
- 장기 저장되는 멀티뷰의 채널별 화질·딜레이도 설정 백업 대상에 포함하는 안을 제안해요.
- 시청 기록은 별도 백업으로 제공해요. 로그인 정보·권한 승인 상태·탭 ID·일시적인 실행 상태는 설정 파일에 넣지 않아요.

**불러오기 초안**

1. 파일의 형식과 버전을 확인해요.
2. 적용할 설정과 알 수 없거나 지원하지 않는 항목을 안내해요.
3. 사용자가 적용하면 기존 설정 검증·저장 경로를 통해 반영해요.
4. 새 권한이 필요한 기능은 해당 환경에서 권한을 허용한 뒤 사용할 수 있게 해요.
5. 적용 완료와 새로고침이 필요한 항목을 구분해 알려드려요.

**검토할 사항:** 불러온 파일에 없는 설정은 현재 값을 유지하는 안을 제안해요. 이전 버전 키의 변환 규칙과 저장 위치별 백업 목록을 정의해야 해요. 파일을 읽은 직후에는 기존 값을 변경하지 않아요.

### 2.10. 시청 기록 백업·복원

**목표:** 로컬 시청 기록을 파일로 보관하고, 기존 집계 의미를 유지하며 복원해요.

**백업 초안**

- 시청 기록 페이지에 `시청 기록 백업`과 `시청 기록 복원`을 제공해요.
- 초기 범위는 전체 기록의 JSON 백업으로 제안해요.
- 방송·채널 식별 정보, 시청 세션과 시간 구간, 날짜별 기록, 제목·방제 이력 등 복원에 필요한 원본 데이터를 포함해요.
- 계산된 총 시청 시간만 저장하지 않고, 겹치는 시간을 다시 계산할 수 있는 데이터를 보존해요.
- 설정 백업과 구별할 수 있도록 백업 종류와 형식 버전을 기록해요.

**복원 초안**

1. 파일 종류·형식·데이터의 유효성을 검사해요.
2. 기록 수와 기간, 현재 기록과 겹치는 항목을 미리 보여줘요.
3. `기존 기록에 합치기`를 기본안으로 하고, `백업으로 전체 교체`는 별도 선택으로 제공해요.
4. 합치기는 안정적인 방송·세션 식별자와 시청 구간을 기준으로 처리해요. 같은 파일을 두 번 불러와도 시청 시간이 늘어나지 않아야 해요.
5. 전체 교체는 변경될 범위를 안내하고 현재 기록을 먼저 백업할 수 있게 해요.
6. 복원 중 열린 방송에서 새 기록이 들어와도 덮어쓰기나 중복이 생기지 않도록 기존 기록 저장 경로에서 순서를 관리해요.
7. 저장 성공 뒤 달력·목록·합계를 다시 계산하고 실제 반영 결과를 표시해요.

**기존 구조와의 연결:** 기록 변경은 `background.js`와 `shared/watchHistoryStore.js`의 단일 쓰기 경로를 통해 처리해요. 삭제 이후 늦게 도착한 기록을 막는 기존 규칙과, 사용자가 의도적으로 선택한 백업 복원의 관계를 명시해야 해요.

**검토할 사항:** 구버전·부분 손상 파일, 저장 상한 초과, 날짜 경계, 서로 다른 기기의 중복 시청 구간, 복원 실패 시 기존 기록 보존이에요. 저장할 수 없는 부분을 조용히 버리지 않고 적용 전 안내해요. 복원 미리보기 이후에는 실제 반영 시점의 최신 기록으로 충돌을 다시 확인해요.

## 3. 함께 정할 동작

아래 항목은 구현된 규칙이 아니라 기능 간 충돌을 줄이기 위한 제안이에요.

| 조합                                       | 제안                                                                   |
| ------------------------------------------ | ---------------------------------------------------------------------- |
| 저지연 우선 + 타임머신·멀티뷰 싱크         | 사용자가 정한 재생 위치와 저장 딜레이를 존중해요.                      |
| 글꼴 + 채팅 크기 조절                      | 긴 닉네임·배지·줄바꿈과 입력창 높이를 함께 확인해요.                   |
| 채팅 이동 + 사이드바 이동                  | 같은 쪽으로 배치했을 때 순서와 최소 너비를 명확히 정해요.              |
| 폴더 + 채널 고정 + 오프라인 숨김           | 폴더 소속·고정 순서·방송 상태의 적용 순서를 일관되게 정해요.           |
| 방송 알림 + 자동 열기 + 대기 화면 새로고침 | 방송 단위로 중복 동작을 막고 기존 탭을 활용해요.                       |
| 설정 복원 + 알림·자동 열기                 | 복원 직후 진행 중인 방송을 한꺼번에 열지 않도록 최초 확인 기준을 둬요. |
| 시청 기록 복원 + 진행 중 시청              | 복원과 실시간 기록 저장을 같은 쓰기 경로에서 조정해요.                 |

## 4. 향후 완료 확인 기준

각 기능을 구현하게 되면 다음 결과를 확인해요. 이 목록은 이번 문서 작성에서 수행한 테스트 결과가 아니에요.

- 저지연 지원·미지원 방송에서 설정 결과가 맞고, 화질과 재생 위치가 불필요하게 바뀌지 않아요.
- 앰비언트 효과를 끄거나 페이지를 떠나면 관련 화면 갱신 작업이 정리돼요.
- 글꼴과 배치를 바꿔도 라이트·다크 모드, 좁은 화면, 전체 화면에서 조작할 수 있어요.
- 채팅·사이드바 위치와 크기를 기본 상태로 되돌릴 수 있어요.
- 새로고침·페이지 내부 이동·목록 재생성 뒤에도 폴더·고정·접기·숨김 규칙이 일관돼요.
- 같은 방송에 알림이나 자동 탭 열기가 중복 실행되지 않아요.
- 채팅 멀티뷰에서 채널 추가·제거·재배치와 입력 대상 구분이 정상적으로 작동해요.
- 설정을 백업한 뒤 변경하고 다시 불러오면 백업한 값으로 복원돼요.
- 같은 시청 기록 백업을 반복 복원해도 중복 시간이 늘어나지 않아요.
- 복원 실패·미지원 파일·저장 공간 부족 상태에서 기존 데이터가 보존되고 실패 이유가 표시돼요.

## 5. 작성 근거와 구현 전 재확인 대상

- 요청 범위는 대화에서 선택하신 기능 목록과 시청 기록 백업·복원 추가 요청을 기준으로 했어요.
- 비교 참고 자료는 치지직 올인원 1.5.1의 설정 화면·설정 스키마·실행 코드예요.
- 현재 기능은 Better Chzzk 저장소의 `manifest.json`, `README.md`, `shared/settings.js`, 팔로잉 관련 소스에서 확인했어요.
- 백업 설계 시에는 `options.js`, `history.js`, `background.js`, `shared/watchHistoryStore.js`와 각 기능의 저장 키를 다시 확인해야 해요.
- 작성 시점은 `1.3.7` 브랜치, HEAD `b2f22a2`에 커밋되지 않은 변경이 있는 상태예요. 문서는 출시 완료 기능 목록이나 특정 커밋만의 동작 보증으로 사용하지 않아요.
