# 방송 목록 필터 1단계(적용 조건 줄) 설계 — 2026-10-17

## 범위와 근거

2026-10-17 사용자가 방송 목록 필터가 부실하다고 했고, 개선 방향을 3단계로 나눈 뒤 1단계(조건 유지·적용 조건 표시·이상/이하 선택·검색 개선)부터 진행하기로 했어요. 같은 날 시안 3개(A 적용 조건 줄, B 조건 버튼, C 범위 패널)와 지금 모습을 화면으로 비교했고, 사용자가 **A**를 골랐어요. 시안 파일은 세션 임시 폴더에만 있으며 저장소에 넣지 않았어요. 아래 본문이 시안 A의 화면을 글로 옮긴 기준이에요.

같은 날 사용자가 남은 결정 3개를 추천대로 확정했고(맨 아래 `결정 결과`), 이 설계대로 구현했어요. 구현에서 달라진 점은 `구현 결과`에 적었어요. 2단계(19세·채널 숨김·제목 제외어, 태그·카테고리 포함 조건)와 3단계(정렬, 조건 조합 저장, 팔로워 조회 진행률)는 이 문서의 범위 밖이에요.

작업 기준은 `1.4.5` branch, HEAD `e73d03c`예요. 작업 트리에 있는 다른 세션의 미커밋 변경(광고 팝업, status·findings 기록)은 건드리지 않아요. 커밋·버전·릴리스는 범위 밖이에요.

## 실제 화면 근거와 한계

- 저장소의 코드·테스트·문서만 읽어 정리했어요. 내장 브라우저가 치지직 페이지를 막아서 **실제 Chrome·치지직 화면은 확인하지 않았어요.** 시안의 배치는 `mountToolbar()`의 장착 규칙(전체 방송은 정렬 줄 또는 라이브/동영상 탭 줄, 카테고리는 라이브/동영상/클립 탭 줄)을 따른 근사예요.
- 지금 필터 상태와 초기화 위치는 `features/categoryTools.js`에서 확인했어요. 경로가 바뀌면 `mountToolbar()`가, 도구를 떼면 `removeTools()`가 검색어·숫자 조건을 비워요. 그래서 방송을 보고 돌아오거나 새로고침하면 조건이 사라져요.
- 검색은 공백을 지운 검색어 한 덩어리가 `buildSearchText()`·`buildMetaSearchText()`의 공백 제거 문자열에 들어 있는지만 봐요(`shared/data.js`의 `normalizeCompact`). 그래서 `롤 -대회`는 `롤-대회`를 찾고, 제목·채널·카테고리·태그의 경계를 넘어 일치할 수도 있어요.
- 숫자 필터 메뉴는 옵션의 프리셋 6개로 만든 구간 버튼과 끌어서 고르는 범위 선택, `직접 최소 ~ 최대` 입력이에요(`filterModel.js`의 `getFilterPresetRanges`·`combineFilterOptionRanges`).
- 탭 단위 저장의 선례는 멀티뷰의 `betterChzzkMultiviewSession`(사이트 sessionStorage, `features/liveMultiview/model.js`의 `readSession`)이에요. `docs/security.md`는 이 저장을 페이지 스크립트가 읽을 수 있는 보관으로 설명해요.

## 1. 조건 모델

조건 종류는 지금과 같아요. 팔로워 수, 시청자 수(라이브)·조회수(영상·클립), 진행 시간(메타데이터를 쓸 수 있는 라이브 목록만)이에요.

- **종류별 상태:** `{ mode, min, max }`. `mode`는 `none`(전체)·`min`(이상)·`max`(이하)·`range`(범위) 중 하나예요. 지금의 종류별 전역 변수 12개(`followerFilterMin`·`…Custom` 등)를 종류별 객체 하나로 모아요.
- **실제 조건(effective range):** `min` 모드는 `min`만, `max` 모드는 `max`만, `range`는 둘 다 써요. 값이 0이면 그 끝은 제한이 없어요. 범위에서 최소가 최대보다 크면 바꿔서 적용해요(입력 순서와 무관, 양끝 포함). 모드만 고르고 값이 없으면 조건이 아니에요. 배지 수·초기화 버튼 활성·결과 수 표시에서도 조건으로 세지 않아요.
- **모드 전환:** 이상↔이하는 지금 값을 그대로 옮겨요. 이상·이하에서 범위로 바꾸면 그 값을 해당 끝에 두고 다른 끝은 비워요. `전체`는 값을 지우지 않고 모드만 바꿔서, 다시 이상을 고르면 직전 값이 돌아와요. 저장할 때는 실제 조건만 남겨요(§5).
- **판정:** 기존 `passesCountRange`(양끝 포함)를 실제 조건으로 호출해요. 팔로워 미조회·조회 실패를 0명으로 보지 않는 규칙, 진행 시간 결측을 통과시키지 않는 규칙, 시청자 필터의 표시 보존 행(sticky)과 제외의 AND 판정은 그대로예요.
- **순수 함수 위치:** `filterModel.js`에 `effectiveRange(state)`, `setFilterMode(state, mode)`, `formatConditionLabel(kind, range, context)`, `parseSearchTerms(query)`, `matchesSearchTerms(fields, terms)`, `normalizeListFilterRecord(record, context)`를 둬요. 모델은 지금처럼 UI 상태를 직접 저장하지 않고 sessionStorage에도 접근하지 않아요.

## 2. 필터 메뉴

지금 위치(필터 버튼 아래 팝오버)와 열림·닫힘 규칙(자동 갱신 중 유지, 바깥 신뢰 클릭·버튼 재클릭·Escape로 닫기, Escape 뒤 버튼으로 초점 복귀)은 그대로예요.

- 메뉴 너비는 약 410px로 줄이고 종류마다 한 묶음씩 세로로 쌓아요.
- **묶음 머리:** 왼쪽에 종류 이름, 오른쪽에 모드 버튼 4개(`전체 · 이상 · 이하 · 범위`). 모드 버튼은 `aria-pressed`를 쓰는 `type="button"`이고 묶음에 종류 이름 레이블을 붙여요.
- **이상·이하일 때:** 옵션 프리셋 6개를 빠른 값 버튼으로 보여 줘요(예: `100명`, `1천명`, `1만명`). 누르면 그 값으로 적용하고, 이미 고른 값을 다시 누르면 값만 비워요. 아래에 `직접 [입력] 명 이상`(또는 `이하`)을 둬요. 입력은 지금 파서 그대로 `2천`·`1.5만`·`1,000`과 시간 소수(`1.5`)를 받아요.
- **범위일 때:** `[최소] ~ [최대] 단위` 입력만 보여 줘요. 한쪽만 채우면 그 쪽만 적용해요.
- **전체일 때:** 묶음 머리만 남겨 메뉴를 짧게 유지해요.
- **아래 줄:** 왼쪽 `필터 초기화`(숫자 조건만 해제, 숫자 조건이 없으면 비활성. 지금 규칙 그대로), 오른쪽 안내 `방송을 보고 돌아와도 이 탭에서 유지돼요`.
- **없애는 것:** 구간 버튼(`○명 이하`, `○명 ~ △명`, `○명 ~ 최대`)과 끌어서 범위 고르기, 이에 딸린 pointer 처리·`data-in-range`·`data-range-edge`. 범위는 `범위` 모드 입력으로 대체해요.
- 메뉴를 열면 첫 묶음에서 선택된 모드 버튼으로 초점을 옮겨요.

## 3. 적용 조건 줄

조건(실제 숫자 조건 또는 검색 단어)이 하나라도 있으면 툴바가 있는 줄 바로 아래에 새 줄 `#betterchzzk-category-filter-chips`를 보여 주고, 없으면 `hidden`으로 숨겨요.

- **위치:** 툴바를 붙인 host(전체 방송의 정렬 줄·대체 줄 또는 라이브/동영상 탭 줄, 카테고리의 탭 줄) 안에 `flex: 0 0 100%` 항목으로 넣어요. host는 이미 확장 CSS로 `flex-wrap: wrap`이라 별도 형제 노드를 React 영역 밖에 만들지 않아도 줄이 나뉘어요. 카테고리·태그 제외 줄은 지금 위치 그대로예요.
- **내용 순서:** 라벨 `적용 중` → 숫자 조건 칩 → 검색 단어 칩 → `모두 해제` → 오른쪽 끝 결과 수.
- **숫자 조건 칩:** `팔로워 1만명 이상`, `시청자 300명 이상`, `조회수 1천회~5천회`, `진행 4시간 이하`. 숫자는 팔로워 배지와 같은 축약 표기를 써요. 칩 본문을 누르면 필터 메뉴를 열고, 오른쪽 `×`(이름: `시청자 300명 이상 해제`)는 그 종류를 `전체`로 돌려요.
- **검색 단어 칩:** `“롤” 포함`, `“대회” 빼기`. 빼기 칩은 위험색 계열로 구분해요. 본문을 누르면 검색창에 초점을 옮기고, `×`는 그 단어만 지운 검색어를 바로 적용해요(전체 방송에서도 Enter 없이 적용하는 명시 조작이에요).
- **칩 색:** 이번 조건 칩은 옅은 브랜드 면(`--sem-color-surface-brand-alpha-weak`)과 브랜드 글자, 영구 제외 칩은 지금처럼 채운 브랜드색이라 두 줄의 의미가 구분돼요. 라이트의 작은 브랜드 글자는 대비 4.5:1을 넘는 값을 쓰고 검증 기록에 대비값을 남겨요.
- **모두 해제:** 검색어와 숫자 조건을 한 번에 지워요. 카테고리·태그 제외 목록과 집계 설정은 건드리지 않아요.
- **결과 수:** 지금 검색창 옆 `.bcgt-status`(`보이는 수 / 전체 수`)를 이 줄 오른쪽으로 옮기고 `확인한 600개 중 4개`처럼 써요. 조회한 범위만 센다는 기존 규칙에 맞춘 표현이에요. `aria-live="polite"`는 유지해요. 제외 항목만으로는 이 줄을 보이지 않는 지금 규칙도 유지해요.
- **변경 감시:** 이 줄은 확장 소유 노드로 `isOurNode()`에 넣어 자기 변경이 다시 적용을 예약하지 않게 해요. 직접 제거되면 다음 적용에서 다시 붙여요.

## 4. 검색 규칙

- **문법:** 띄어쓰기로 나눈 단어를 모두 포함해야 보여요(AND). `-`로 시작하는 단어(두 글자 이상)는 그 단어가 들어간 카드를 빼요. `-` 하나만 있는 단어는 무시해요. 대소문자는 구분하지 않아요.
- **일치 범위:** 단어마다 제목·채널명·카테고리 이름·태그 중 **한 칸 안에서** 찾아요. 원본 카드 DOM 글자도 텍스트 노드 단위의 칸으로 나눠서 칸 경계를 넘는 일치를 막아요. 팔로워·진행 시간 배지 글자는 지금처럼 빼요. 원본 카드에 보이는 다른 표시 글자(예: 시청자 수 문구)는 지금처럼 검색 대상에 남아요.
- **적용 시점:** 지금 그대로예요. 전체 방송은 Enter에서만 적용하고 한글 조합 확정 Enter·누르고 있는 Enter·같은 값 재제출은 무시해요. 카테고리 목록은 입력 120ms 뒤 적용해요.
- **입력 도움말:** 검색창에 초점이 있을 때만 아래에 `띄어쓰기 = 모든 단어 포함 · -단어 = 빼기 · Enter 적용`(카테고리 목록은 Enter 문구 없이)을 보여 주고 `aria-describedby`로 연결해요. placeholder `현재 목록 검색`은 그대로예요.
- **길이:** 검색어는 최대 100자(`maxlength`)예요.
- **비교 키:** `getActiveFilterKey()`·시청자 필터 표시 보존 키는 원문 대신 정규화한 단어 목록을 써서 띄어쓰기만 다른 같은 검색이 새 탐색을 만들지 않게 해요.

## 5. 조건 유지(탭 sessionStorage)

### 저장 형식

사이트 sessionStorage 키 `betterChzzkListFilterSession` 하나에 JSON으로 둬요.

```json
{
    "version": 1,
    "routes": {
        "global-lives/lives": {
            "savedAt": 1760704800000,
            "query": "롤 -대회",
            "filters": {
                "views": { "mode": "min", "min": 300, "max": 0 },
                "duration": { "mode": "max", "min": 0, "max": 14400 }
            }
        }
    }
}
```

- 경로 키는 `categoryToolsRepository.routeKey(route)`의 결과예요(`global-lives/lives`, `{유형}/{ID}/lives|videos|clips`).
- 실제 조건만 저장해요. 조건이 없는 종류는 빼고, 검색어도 조건도 없는 경로는 항목을 지워요.
- 숫자는 안전한 정수만 받아요. 인원·횟수는 1~10,000,000, 진행 시간은 초 단위 1~604,800(옵션 상한 168시간)이에요. 진행 시간은 라이브 목록 키에서만 받아요.
- 경로는 최대 20개이고 넘치면 `savedAt`이 가장 오래된 경로부터 지워요. 검색어는 최대 100자예요.

### 읽기·쓰기 시점

- **읽기:** 목록 경로에 들어와 툴바를 붙일 때 한 번 읽어요. `mountToolbar()`에서 경로 키가 바뀌면 지금처럼 메모리를 비운 뒤 그 경로의 기록을 적용해요. 새로고침, 다른 페이지에서 돌아오기, 기능 OFF→ON 모두 같은 경로로 처리돼요. 검색 입력란·메뉴·칩 줄도 복원값으로 맞추고 자동 추가 탐색은 사용자가 조건을 건 것과 같게 시작해요.
- **쓰기:** 사용자 조작으로 조건이 바뀐 직후에만 해당 경로 항목을 읽고 고쳐 써요. 대상은 검색 적용(Enter·카테고리 입력 적용), 칩 `×`, `모두 해제`, 모드·빠른 값·직접 입력, `필터 초기화`예요. 경로 이동·`removeTools()`·기능 OFF·진행 시간 비대상 목록의 자동 정리 같은 **자동 초기화는 쓰지 않아요.**
- **읽기 검증:** JSON 해석 실패, 다른 version, 형식이 틀린 경로 항목은 적용하지 않아요. 한 종류만 틀리면 그 종류만 버리고 나머지는 적용해요. 검증 실패로 저장값을 지우지는 않고, 다음 정상 쓰기가 그 경로 항목을 새 형식으로 덮어써요.
- **저장소 오류:** sessionStorage 접근·쓰기가 예외를 내면(차단·용량) 조건 유지 없이 지금처럼 메모리로만 동작하고 오류 표시는 하지 않아요.

### 경계와 한계

- 페이지 스크립트도 이 키를 읽고 바꿀 수 있어요. 검색어와 숫자만 있는 비민감 자료이고, 읽은 값은 화면 필터 조건으로만 쓰며 저장·탭·권한 같은 특권 동작으로 이어지지 않아요.
- Chrome이 탭을 복제하거나 닫은 탭 다시 열기·시작 시 이전 탭 계속 기능으로 탭을 복원하면 sessionStorage가 함께 돌아올 수 있어요. 이 경우 조건도 돌아와요. 멀티뷰 세션과 같은 성질이고, 검색어를 확장 저장소에 영구 저장하지 않는다는 보안 규칙과는 구분해 설명해요.
- 다른 탭에는 반영하지 않아요(탭 단위가 결정 사항이에요).
- 설정 파일 백업에는 넣지 않아요(사이트 sessionStorage는 이미 제외 대상이에요).
- 팔로워 조건이 복원되면 돌아올 때마다 기존 제한(한 번 6개·동시 2개·700ms 간격) 안에서 팔로워 조회가 다시 시작돼요.

## 8. 테스트 계획

- **모델(category-tools-filter-model):** 모드별 실제 조건, 값 없는 모드는 조건 아님, 범위 뒤집힘 교정과 양끝 포함, 모드 전환의 값 이동, 라벨(명·회·시간, 이상·이하·범위), 검색 단어 해석(AND·`-단어`·`-` 단독·연속 공백), 칸 단위 일치(경계 넘는 일치 거부), 기록 정규화(형식·상한·진행 시간 비라이브 거부·한 종류만 버림). 기존 파서·포맷·양끝 포함·제외 검사는 유지하고, 구간 버튼·끌기 범위 검사 3개(`presets … inclusive ranges`, `labels retain count units`, `drag ranges are direction independent`)는 새 계약 검사로 바꿔요. 바뀐 계약은 상태 기록에 적어요.
- **유지(lifecycle):** 같은 경로 SPA 왕복 복원, 새 JSDOM 문서에 같은 sessionStorage를 넘긴 새로고침 복원, 경로별 분리(LoL 라이브 조건이 다른 카테고리·영상 목록에 나타나지 않음), 자동 초기화가 저장값을 지우지 않음, `모두 해제`·칩 `×`·`필터 초기화`의 저장 반영, 손상·다른 version·상한 초과 기록 무시, sessionStorage 예외 시 메모리 동작, 기능 OFF→ON 복원, 칩 줄 자기 변경이 적용을 다시 예약하지 않음(dom-scheduling).
- **화면(extension-pages):** `category filter stays open during automatic refresh…`, `category follower filtering continues…`, `global lives duration filter uses openDate…`의 선택자를 새 메뉴(모드 버튼·빠른 값·직접 입력)로 옮기고 같은 동작을 검사해요. 칩 줄의 위치(정렬 줄·탭 줄 host 안 100% 줄), 결과 수 문구, 칩 `×` 동작을 더해요.
- **검색(category-tools-exclusions):** `global list search keeps a draft until Enter…`는 그대로 통과해야 하고, 단어 칩 `×`의 즉시 적용과 Enter 규칙의 공존을 더해요. 제외 줄과 `모두 해제`의 독립(제외 목록 유지)을 확인해요.
- **키보드(lifecycle `filter keyboard dismissal…`):** Escape가 값을 유지하고 필터 버튼으로 초점을 돌리는 규칙을 새 메뉴에서 유지해요.

## 9. 검증 계획

1. 관련 테스트를 `node --test --test-concurrency=2 <위 파일들>`로 먼저 실행해요.
2. 새 저장 형식(사이트 sessionStorage 키)을 더하므로 마지막에 `npm run test:all -- --test-concurrency=2`, `npm run lint`, `npm run format:check`를 순서대로 한 번 실행해요. `format:check`의 `.claude/settings.local.json` 기존 차이는 범위 밖이에요.
3. 실제 Chrome 확인은 자동 검사와 구분해 기록해요. 전체 방송과 카테고리 라이브·영상·클립에서 조건 걸기 → 방송 클릭 → 뒤로 가기 복원, 새로고침 복원, 다른 카테고리로 이동 시 분리, 탭 닫기 뒤 새 탭에서 비어 있음, 칩 `×`·모두 해제·필터 초기화, `롤 -대회` 같은 검색, 라이트·다크와 좁은 창의 줄바꿈, 키보드 조작.

## 10. 수용 기준

- 전체 방송에서 `시청자 300명 이상`·`진행 4시간 이하`·검색 `롤 -대회`를 건 뒤 방송을 보고 돌아오거나 새로고침하면 같은 조건과 칩 줄이 그대로 보이고, 탭을 닫았다 새 탭에서 열면 비어 있어요.
- LoL 카테고리 라이브에 건 조건은 다른 카테고리나 같은 카테고리의 영상 목록에 나타나지 않고, LoL 라이브로 돌아오면 다시 보여요.
- `롤 -대회`는 `롤`이 들어가고 `대회`가 어느 칸에도 없는 카드만 보여 줘요. `롤`이 제목에 없어도 태그나 카테고리에 있으면 보여요.
- 칩 `×`·`모두 해제`는 바로 적용되고 저장값에도 반영돼요. 제외 목록·집계 설정은 바뀌지 않아요.
- 모드만 고르고 값을 비우면 배지 수·칩 줄·결과 수에 조건으로 나타나지 않아요.
- 기존 규칙(Enter 적용·IME, 팔로워 미조회와 0명 구분, 진행 시간 결측, 표시 보존 행, 제외 AND, 자동 갱신 중 메뉴 유지, Escape 초점 복귀)이 그대로 동작해요.

## 결정 결과

2026-10-17 사용자가 추천안을 그대로 확정했어요.

1. **돌아온 직후 안내:** 별도 안내 줄 대신 칩 줄 라벨을 `이어서 적용 중`으로 바꿨다가 첫 조작 뒤 `적용 중`으로 돌려요. 레이아웃이 흔들리지 않아요.
2. **구현 순서:** UI 통일 T6이 1.4.5 커밋에 반영된 뒤 그 공통 토큰(`--bct-*`) 위에 구현했어요.
3. **결과 수 위치:** 검색창 옆에서 칩 줄 오른쪽으로 옮기고 `확인한 N개 중 M개`로 써요.

## 구현 결과

- 설계대로: 모드 모델과 실제 조건, 빠른 값·직접 입력·범위 입력 메뉴, 적용 조건 줄과 칩 해제·모두 해제, 검색 단어 AND·`-단어`·칸 단위 일치, 탭 sessionStorage 유지와 검증을 넣었어요.
- 설계와 다른 점:
    - 옵션 라벨은 `빠른 값 N` 대신 다른 두 묶음(`시청자/조회수 N`, `진행 시간 N`)과 같은 꼴인 `팔로워 N`으로 맞췄어요. 안내 문구는 `필터 메뉴에서 이상·이하를 고를 때 빠른 값 버튼으로 작은 값부터 보여요.`예요.
    - 칩 줄은 host의 맨 끝 대신 제외 줄 앞에 끼우고 CSS order로 맨 아래에 보이게 했어요. 두 요소가 서로 맨 끝 자리를 다투며 적용을 다시 예약하지 않게 하려는 거예요.
    - 기능 OFF→ON처럼 목록 주소가 그대로여도 도구를 뗐다 붙이면 탭 기록을 다시 읽어요.
    - 입력칸은 사용자가 친 원문(예: `2천`)을 기억해 값이 같으면 그대로 보여 줘요.
    - `필터 초기화` 뒤 비활성화된 버튼에서 초점이 빠지던 문제를 함께 고쳐 첫 조건 버튼으로 초점을 옮겨요.
- 실제 Chrome·치지직 화면은 확인하지 않았어요. 자동 검사 범위와 결과는 [상태 기록](tracking/status.md)의 같은 날 항목에 있어요.
