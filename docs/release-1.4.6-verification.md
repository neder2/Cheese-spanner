# 1.4.6 릴리스 준비 검증

## 상태

2026-10-28 KST 사용자 요청("1.4.6에 두고 업데이트 할거임. 릴리즈 준비해줘")에 따라 이슈 #5 수정을 1.4.6에 그대로 두었어요. 버전·안내 자료·업데이트 내역·README·스토어 문구를 1.4.6으로 맞추고, 사용자가 확정한 안내 문구로 [최종 배포 ZIP](#최종-배포-zip)을 만들어 대조했어요. 전체 자동 검증을 마쳤고, Chrome for Testing 분리 프로필에서는 Claude가 CDP로 실제 업데이트와 안내를 점검했어요. ### 테스트 종료 뒤 비동기 오류

2026-10-27 기록의 두 오류를 다시 확인했어요.

- `extension-pages`의 `multiview option handles permission approval`: 원인을 확정했어요. 런타임 결함이 아니라 테스트의 대기 경합이에요.
    - 원인: 가짜 Chrome 저장소(`tests/helpers/extension-page-fixture.js`)는 Node 타이머로 콜백을 불러요. 그런데 테스트는 저장 클릭 뒤 고정 20ms만 기다렸어요.
    - 저장 체인이 그보다 늦으면 `dom.window.close()` 뒤에 `finishSave`가 실행돼요. 이때 `hideMessage`·`showMessage`가 닫힌 문서의 `activeElement`를 읽어요.
    - 재현: 세션 임시 사본에서 마지막 대기를 한 턴(`setImmediate`)으로 줄였어요. 10-27과 같은 `generated asynchronous activity after the test ended`와 `reading 'activeElement'`, 파일 단위 실패가 났어요.
- 수정(테스트만):
    - 고정 대기 대신 `waitForCondition`으로 `CheeseSpannerOptionsPage.isReady()`(로드 완료·저장 진행 없음)를 기다려요.
    - 두 번째 저장에서 `volumeWheelStep` 6이 저장됐는지 새로 단언해요. 기존 단언은 줄이지 않았어요.
    - 가짜 콜백을 30ms로 늦춘 임시 사본에서 기존 검사는 실패하고, 수정한 검사는 5회 모두 통과했어요. 저장소 그대로도 5회 모두 통과했어요.
- `following-folders`(최초 작성 환경 기록): 원인을 확정하지 못했어요. 오류 내용이 남아 있지 않아요.
    - 이 저장소에서는 재현되지 않았어요. 전체 실행 3회(10-27 1,903개, 10-28 1,906개·1,907개)와 단독 실행 3회 모두 통과했어요.

## 후보 배포 ZIP

최종 ZIP이 아니에요.

- 명령: `npx --no-install web-ext build --config web-ext-config.mjs --artifacts-dir <세션 임시 폴더>/artifacts --filename "cheese_spanner-1.4.6.zip"`
- 결과: 2,953,135바이트, SHA-256 `a2dc5d5cd8bbb8a5d22c0085a979ce84d8fb23d67eea8d2b3ef0739769491683`, 123개 파일
- 작업 트리와 대조: 압축을 풀어 보니 123개 모두 작업 트리와 바이트 단위로 같아요.
    - manifest는 1.4.6이에요.
    - `shared/updateGuide.js`에 1.4.6 요약, `options.html`에 `liveStartHostAccess`, 공유 `API_HOST_PERMISSION`이 들어 있어요.
- 1.4.5 배포 ZIP과 대조: 기준은 `web-ext-artifacts/cheese_spanner-1.4.5.zip`이에요(123개 파일, SHA-256 `3e7bf387…`로 1.4.5 기록과 같음).
    - 추가·삭제된 파일이 없어요.
    - manifest는 `version`만 달라요. 권한·호스트·콘텐츠 스크립트·웹 접근 자원이 같아서 업데이트 때 새 권한 경고가 없어요.
- 들어 있는 것: 안내 자료·워커 컨트롤러·공용 뷰·콘텐츠 런타임·옵션 연결(`shared/updateGuide.js`, `shared/updateGuideController.js`, `shared/updateGuideView.js`, `features/updateGuide.js`, `optionsUpdateGuide.js`), 라이선스·폰트
- 없는 것: 테스트·문서·스토어 자료·package·숨김 파일, `features/adAutoSkip.js`·`features/updateNotice.js`·`features/chatToolsPage.js`

후보 ZIP을 만든 뒤 런타임 파일은 `shared/updateGuide.js`의 1.4.6 요약만 사용자 확정 문구로 바꿨어요. 그 밖에는 테스트와 문서만 고쳤고, 둘 다 ZIP에 들어가지 않아요.

## 실제 업데이트 점검 (Chrome for Testing, Claude가 CDP로 조작)

방법:

1. 1.4.5 배포 ZIP을 새 임시 폴더에 풀어 새 프로필에 `--load-extension`으로 설치했어요.
2. 같은 경로에 1.4.6 후보 ZIP을 덮어 풀었어요. `diff -r`로 후보 ZIP과 같은 것을 확인했어요.
3. 프로필의 개발자 모드를 켜고 `developerPrivate.reload`로 다시 로드했어요.

탭 초점은 `Emulation.setFocusEmulationEnabled`로 유지했어요. 이 실행은 `--disable-backgrounding-occluded-windows --disable-renderer-backgrounding --disable-background-timer-throttling`을 함께 썼어요.

- 1.4.5 새 설치: 치지직 `/lives`에 6초 동안 안내가 없었어요. 설치 1.3초 뒤에 읽은 안내 상태는 아직 기록되지 않은 `null`이었어요.
- 저장값 이어짐: 1.4.5에서 두 값을 저장했어요.
    - `skipWheelShiftStep` 7(sync)
    - 옵션 화면에서 추가한 방송 알림 채널 1개(`샘웨`)
    - 업데이트 뒤 1.4.6 설정 화면에 7과 `샘웨`가 그대로 보였어요. 브라우저를 재시작한 뒤에도 같았어요.
- 업데이트 결과:
    - 버전 1.4.6, 상태 `ENABLED`, 비활성 사유 없음
    - 안내 상태 `{"status":"pending","version":"1.4.6"}`
    - `api.chzzk.naver.com` 권한 유지(`permissions.contains` true)
- 최초 1회·한 탭: 새 `/lives` 문서(앞)와 `/category` 문서(뒤, 배경 탭)를 열자 앞 탭에만 안내가 나타났어요.

### 보충 점검

같은 후보 ZIP을 새 프로필에 설치하고, 배경 처리 플래그 없이 실행했어요. 안내 상태는 테스트 프로필에서만 `pending`으로 기록했어요. 실제 업데이트 경로는 위에서 이미 확인했어요.

2026-10-28 후보 ZIP 업데이트 프로필(Chrome for Testing)에서도 15859895가 `10.25(일) 17:56 ~ 23:08`로 표시됐어요([실제 업데이트 점검](#실제-업데이트-점검-chrome-for-testing-claude가-cdp로-조작)).

### 라이브 블라인드 원문 복구

1.4.6 후보 ZIP에는 포함하지 않았어요(이 저장소에 소스 없음). 아래는 2026-10-27 기록이에요.

처음부터 클린봇에 가려진 메시지·DOM 원문 캐시 전 블라인드·식별자 없는 행 교체는 기존 DOM 원문 경로로 복구되지 않아, 현재 행의 내부 원문을 MAIN에서 읽도록 보완했어요. 관찰한 라이브 표본에 블라인드 이벤트가 없어 제보 건의 해결은 확정하지 않았어요. 상세 근거는 최초 작성 환경의 `docs/tracking/findings.md` 항목 "2026-10-24 라이브 블라인드 원문 복구"(미커밋)에 있다고 적혀 있었지만, 이 저장소의 findings에는 해당 항목이 없어요.

- [ ] 수정본을 다시 불러오고 치지직 탭을 새로고침한 뒤 원문 표시를 켜요.
- [ ] 클린봇 즉시 차단 메시지와 사후 블라인드 메시지에서 현재 행의 원문이 보이는지.
- [ ] 채팅 재연결·방송 이동·옵션 OFF 뒤 원문이 남지 않는지.
- [ ] 블라인드가 자주 나오는 방송에서 관찰 시간이 필요해요. 서버나 페이지가 원문을 갖지 않은 메시지는 복구 대상이 아니에요.

2026-10-27 Mac 사용자 Chrome에서 원문 표시 옵션은 이미 ON이었고, 토키노 메리 라이브 채팅을 관찰했지만 블라인드 이벤트는 포착하지 못했어요. 현재 Mac 작업 트리에는 위 후보의 `features/chatToolsPage.js`와 `tests/chat-blind-source.test.js`가 없고 manifest에도 새 MAIN 파일이 없어, 이 실측은 문서에 적힌 원문 복구 수정본의 검증이 아니에요. 해당 미커밋 소스를 확보한 뒤 다시 확인해야 해요.

### 사이드바 팔로잉 끝부분 잘림

1.4.6 후보 ZIP에는 포함하지 않았어요(이 저장소에 소스 없음). 아래는 2026-10-27 기록이에요.

2026-10-23 Chrome 홈에서 외부 cosmetic 규칙이 사이드바를 60px 더 내리고 높이를 화면 전체로 바꿔, 아래 구역을 숨긴 상태에서 팔로잉 마지막 행·`접기`가 화면 밖에 남았어요. 배너가 없을 때도 치지직 inline transform·height를 유지하도록 보정했어요. 상세 근거는 최초 작성 환경의 `docs/tracking/findings.md` 항목 "2026-10-23 사이드바 팔로잉 끝부분 잘림"(미커밋)에 있다고 적혀 있었지만, 이 저장소의 findings에는 해당 항목이 없어요. 같은 증상의 기존 기록은 [2026-10-13 사이드바 팔로잉 목록이 끝까지 스크롤되지 않음](tracking/findings.md#2026-10-13-사이드바-팔로잉-목록이-끝까지-스크롤되지-않음--알려진-문제-원인-미확인)이에요.

- [ ] 같은 외부 규칙(`#sidebar { transform: translateY(60px) !important; height: 100% !important; }`)이 있는 홈에서, 사이드바 위쪽이 헤더 아래(약 60px)부터 시작하는지.
- [ ] 팔로잉을 끝까지 펼쳐 스크롤했을 때 마지막 행과 `접기`가 보이는지.

### 방송 알림 사이트 액세스 안내(이슈 #5)

[이슈 #5](https://github.com/neder2/Cheese-spanner/issues/5)의 원인·수정·근거는 [남은 확인 사항](tracking/findings.md#2026-10-28-이슈-5-방송-알림-등록-failed-to-fetch--사이트-액세스-제한-감지안내-수정-사용자-확인-대기)에 있어요. 확장의 사이트 액세스에서 `api.chzzk.naver.com`이 보류되면 방송 확인을 멈추고 안내하며, 옵션의 `치지직 API 접근 허용`으로 다시 요청해요.

이미 확인한 것(2026-10-28, macOS Edge 156.0.4314.50 임시 프로필, 현재 작업 트리 `--load-extension`, CDP와 `developerPrivate`로 사이트 액세스 변경):

- 제한 → 워커가 `onRemoved`를 받아 상태 안내를 남기고 알람을 해제했으며, 워커·옵션의 API 요청은 0건이었어요.
- 제한 중 페이지 등록 응답은 사이트 액세스 안내 문구였어요. 옵션에는 허용 버튼이 나타났고, 채널 추가는 조회 없이 안내했어요.
- 확장 관리 페이지에서 다시 허용 → 워커가 `onAdded`를 받아 확인을 재개했어요. 진행 중 방송은 기준 상태로만 기억해 자동 열기 탭이 열리지 않았어요. 옵션 버튼도 다시 숨겨졌어요.
- 조회를 막은 상태의 등록 응답은 `채널 정보를 확인하지 못했어요. 잠시 후 다시 시도해 주세요.`였어요.
- 옵션 라이트·다크, 420px 팝업 폭, 키보드 초점 화면을 확인했어요.
- 후보 ZIP의 치지직 상단 패널(2026-10-28, Chrome for Testing 새 프로필): `developerPrivate`로 `chzzk.naver.com`만 허용하고 `api.chzzk.naver.com`·`apis.naver.com`은 보류했어요.
    - 홈의 상단 `방송 알림` 패널에서 `샘웨`를 검색하고, 결과의 `데스크톱 알림`을 실제 마우스 입력으로 눌렀어요. 패널은 신뢰된 클릭만 받아요.
    - 패널 안에 `확장의 사이트 액세스에서 api.chzzk.naver.com 접근이 꺼져 있어 채널을 확인하지 못했어요. 설정의 ‘방송 알림’ 탭에서 ‘치지직 API 접근 허용’을 눌러 주세요.`가 표시됐어요. 3줄(326×54px)로 줄바꿈되어 가로 넘침 없이 보였어요.
    - 채널은 저장되지 않았어요.
    - 다크는 치지직 기본 테마에서, 라이트는 루트 클래스를 바꾼 화면에서 봤어요(스크린샷 확인).

남은 실측:

- [ ] 허용 버튼이 띄운 권한 요청 창을 사용자가 수락했을 때 버튼이 사라지고 방송 확인이 재개되는지. 자동 측정은 요청 창 대기까지만 확인했어요.
- [ ] 사용자 Chrome·Edge의 실제 사이트 액세스 화면에서 `api.chzzk.naver.com`을 끄고 켰을 때 같은 안내·재개가 일어나는지.
- [x] 제한 상태에서 치지직 상단 `방송 알림` 패널에 안내 문구가 줄바꿈되어 보이는지. 위 후보 ZIP 패널 확인이에요.
- [ ] 제보자가 사이트 액세스를 확인한 결과.

## 측정 환경 메모

Edge 임시 프로필로 실측할 때는 `--disable-sync`와 `--disable-backgrounding-occluded-windows --disable-renderer-backgrounding --disable-background-timer-throttling`을 함께 써요.

- 동기화를 끄지 않으면 새 프로필에도 사용자 계정의 옵션이 내려와 기본값 측정이 틀어지고, 저장하면 사용자 설정까지 바뀔 수 있어요.
- 창이 다른 창에 가려지면 페이지가 `hidden`이 되고 `requestAnimationFrame`이 멈춰, rAF로 동기화하는 확장 표시가 나타나지 않아요. 이때의 "미표시"는 기능 결함이 아니에요.

Chrome for Testing으로 안내를 점검할 때 알게 된 점(2026-10-28):

- 셸에서 띄운 창이 OS 초점을 가져가요. 초점 에뮬레이션 없이도 `document.hasFocus()`가 true일 수 있어서, 초점이 없는 상태를 전제로 한 단계는 스스로 확인한 뒤 진행해야 해요.
- `Emulation.setFocusEmulationEnabled`를 켠 탭은 배경 탭이 되어도 `visibilityState`가 `visible`로 남아요. 숨은 탭 동작을 볼 때는 그 탭의 에뮬레이션을 꺼요.
- 치지직은 루트 클래스를 직접 바꾸면 곧 원래 테마로 되돌려요. 라이트·다크는 상단 테마 버튼으로 바꾸고 새로고침해요.
- 팝업은 다시보기 뒤 스스로 닫힐 수 있어요. 닫힌 팝업에 보낸 CDP 요청은 응답이 없으므로 시간 제한을 둬요.
- 방송 알림 패널의 버튼은 `isTrusted` 클릭만 받아요. `Input.dispatchMouseEvent`로 눌러요.
