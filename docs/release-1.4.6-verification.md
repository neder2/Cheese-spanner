## 기능별 실측 항목

### 다시보기 시작·종료 시각

표시 규칙은 [계약](contracts.md#다시보기-시작종료-표시)에 있어요. 기본 켜짐인 `vodBroadcastClockEnabled`를 따라요.

이미 확인한 것(2026-10-27, Windows 11, Edge 155 임시 프로필, 확장 미패키징 로드, 로그아웃):

- 같은 날 방송 [15859895](https://chzzk.naver.com/video/15859895): 원본 `10.25`를 숨기고 `10.25(일) 17:56 ~ 23:08`.
- 최근 영상 [15876102](https://chzzk.naver.com/video/15876102): 원본 `21시간 전`을 숨기고 `10.26(월) 17:59 ~ 10.27(화) 00:02`.
- 자정 뒤 공개 [15864635](https://chzzk.naver.com/video/15864635): 원본 `10.26`(공개일)을 숨기고 `10.25(일) 16:29 ~ 10.26(월) 02:29`.
- 세 영상의 종료 시각은 API `duration`과 맞았어요. 구분점·글자색은 원본 조회수와 같고(다크 `rgb(201, 206, 220)`, 라이트 `rgb(46, 48, 51)`), 900px 폭에서는 `조회수 · 날짜` 묶음이 통째로 다음 줄로 넘어가요. 툴팁은 없고, 원본 날짜 묶음의 마우스 안내는 그대로 떠요(DOM 확인).
- 같은 탭 SPA 이동(상대 날짜 영상 → 같은 날 영상) 뒤 숨김 속성이 남지 않았어요.

남은 실측:

- [ ] 사용자 Chrome에서 확장을 다시 불러온 뒤 같은 세 영상의 표시. 사용자 동기화 설정은 `vodBroadcastClockEnabled=false`로 관측됐으니 먼저 옵션을 켜요.
- [ ] 옵션 OFF → 숨긴 원본 날짜가 바로 돌아오고, 다시 ON에서 범위가 한 개만 생기는지.
- [ ] 17시간 분할 다시보기의 두 번째 구간에서 시작 시각이 구간 기준인지.
- [ ] 업로드 영상(`videoType` UPLOAD)에서 범위가 없고 원본 날짜가 그대로인지.
- [ ] 태그가 많거나 제목이 긴 영상, 채팅창을 접은 넓은 화면에서 줄바꿈.

### 라이브 블라인드 원문 복구

처음부터 클린봇에 가려진 메시지·DOM 원문 캐시 전 블라인드·식별자 없는 행 교체는 기존 DOM 원문 경로로 복구되지 않아, 현재 행의 내부 원문을 MAIN에서 읽도록 보완했어요. 관찰한 라이브 표본에 블라인드 이벤트가 없어 제보 건의 해결은 확정하지 않았어요. 상세 근거는 같은 작업의 `docs/tracking/findings.md` 항목 "2026-10-24 라이브 블라인드 원문 복구"(2026-10-27 기준 미커밋)에 있어요.

- [ ] 수정본을 다시 불러오고 치지직 탭을 새로고침한 뒤 원문 표시를 켜요.
- [ ] 클린봇 즉시 차단 메시지와 사후 블라인드 메시지에서 현재 행의 원문이 보이는지.
- [ ] 채팅 재연결·방송 이동·옵션 OFF 뒤 원문이 남지 않는지.
- [ ] 블라인드가 자주 나오는 방송에서 관찰 시간이 필요해요. 서버나 페이지가 원문을 갖지 않은 메시지는 복구 대상이 아니에요.

### 사이드바 팔로잉 끝부분 잘림

2026-10-23 Chrome 홈에서 외부 cosmetic 규칙이 사이드바를 60px 더 내리고 높이를 화면 전체로 바꿔, 아래 구역을 숨긴 상태에서 팔로잉 마지막 행·`접기`가 화면 밖에 남았어요. 배너가 없을 때도 치지직 inline transform·height를 유지하도록 보정했어요. 상세 근거는 `docs/tracking/findings.md` 항목 "2026-10-23 사이드바 팔로잉 끝부분 잘림"(2026-10-27 기준 미커밋)에 있어요.

- [ ] 같은 외부 규칙(`#sidebar { transform: translateY(60px) !important; height: 100% !important; }`)이 있는 홈에서, 사이드바 위쪽이 헤더 아래(약 60px)부터 시작하는지.
- [ ] 팔로잉을 끝까지 펼쳐 스크롤했을 때 마지막 행과 `접기`가 보이는지.
- [ ] 상단 배너가 있는 화면의 기존 보정이 그대로인지.
- [ ] 55개를 넘는 목록을 갱신한 뒤 스크롤 위치.

## 자동 검증에서 남은 문제

`tests/following-folders.test.js`가 테스트 종료 뒤 비동기 작업의 `TypeError`로 파일 단위 실패해서 전체 검사 종료 코드가 1이에요. 2026-10-27 다시보기 커밋 전 HEAD `f8c2559`를 그대로 꺼낸 worktree에서도 같은 1개가 실패했어요. 기능 결함으로 확정한 것은 아니며, 폴더 fixture 종료 뒤 남은 Promise·타이머의 DOM 접근을 추적해야 해요(`docs/tracking/findings.md` 항목 "2026-10-24 전체 검사 중 팔로잉 폴더 테스트 종료 후 비동기 오류", 미커밋). 릴리스 전에 원인을 고치거나 확정해야 해요.

## 측정 환경 메모

Edge 임시 프로필로 실측할 때는 `--disable-sync`와 `--disable-backgrounding-occluded-windows --disable-renderer-backgrounding --disable-background-timer-throttling`을 함께 써요.

- 동기화를 끄지 않으면 새 프로필에도 사용자 계정의 옵션이 내려와 기본값 측정이 틀어지고, 저장하면 사용자 설정까지 바뀔 수 있어요.
- 창이 다른 창에 가려지면 페이지가 `hidden`이 되고 `requestAnimationFrame`이 멈춰, rAF로 동기화하는 확장 표시가 나타나지 않아요. 이때의 "미표시"는 기능 결함이 아니에요.
