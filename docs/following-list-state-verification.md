# 팔로잉 목록 상태 기억 — 2026-09-11

## 실측

Chrome에서 로그인한 `https://chzzk.naver.com/`의 사이드바를 확인했다. 대상은 `#sidebar nav[aria-label="팔로우"]`다.

- 구역 버튼: `aria-expanded="true"`일 때 `aria-label="펼쳐짐, 접기"`, 닫히면 `aria-expanded="false"`와 `aria-label="접힘, 펼치기"`였다.
- 목록 버튼: `더보기`와 `aria-expanded="false"`에서 `접기`와 `aria-expanded="true"`로 전환됐다.
- 구역을 닫으면 목록과 목록 버튼이 DOM에서 제거된다. 같은 문서에서 다시 열면 전체 목록 선택이 유지됐다.
- 전체 목록을 펼친 뒤 구역을 닫고 새로고침하면 구역은 펼침, 목록은 더보기 전 상태로 초기화되는 것을 확인했다.

## 구현과 검증 범위

`팔로잉 목록 상태 기억` 옵션은 기본 꺼짐이다. 기능을 켜면 네이티브 클릭 이후 실제 `aria-expanded` 변화만 저장하고, 구역·목록 상태를 각각 복원한다. 다른 열린 탭에는 저장값을 즉시 적용하지 않는다. 구역을 닫은 상태에서는 전체 목록을 복원하려고 구역을 강제로 열지 않는다.

회귀 테스트는 최초 상태 유지, 두 선택의 독립 저장, 새로고침·SPA·사이드바 교체, 늦게 나타나는 목록 버튼, 사용자 선택 우선, 비활성화 정리, 늦은 저장소 응답, 버튼의 복원 거부, 잘못된 저장값과 재사용된 다른 구역을 포함한다.

## 검증 결과

- 상태 기억·설정·옵션 페이지 관련 테스트 30개와 전체 테스트 584개를 통과했다.
- 린트, 전체 포맷 검사, `git diff --check`를 통과했다.
- 실제 런타임 파일을 사용하는 로컬 브라우저 재현 페이지에서 전체 목록과 구역 접힘의 새로고침 복원, 구역 재개방 시 전체 목록 복원, SPA 이동과 사이드바 교체를 확인했다.
- 실제 옵션 HTML에서 기능을 끄고 저장하면 자동 복원이 중단되고, 다시 켜고 저장하면 마지막 선택이 복원되는 것을 확인했다.
- 라이트·다크 재현 화면과 380px 너비의 설정창에서 동작과 표기를 확인했다. `팔로잉 목록 상태 기억`이 한 줄로 표시되고, 검색과 키보드 체크박스 조작도 동작했다. 완료된 기능 검증 탭의 콘솔 오류·경고는 없었다.
- 로컬 재현의 Chrome 저장소 API는 테스트용 어댑터이므로 실제 확장 주입 검증과 구분한다.

Chrome 확장 관리 페이지는 브라우저 도구에서 접근이 차단되어 설치된 개발 확장의 다시 로드와 실제 isolated world 주입은 직접 확인하지 못한다. 확장을 다시 로드하고 치지직 탭을 새로고침한 뒤, 팔로잉의 구역 접기와 더보기를 각각 선택하고 새로고침·방송 이동 후 유지되는지 확인한다. 옵션을 끈 상태에서는 자동 복원이 중단되는지도 확인한다.
