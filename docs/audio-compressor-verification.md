# 오디오 볼륨 분리 검증 — 2026-09-11

## 변경 범위

1.3.5 브랜치에서 스피커·재생 볼륨바 뒤에 컴프레서·출력 볼륨바를 별도 컨트롤로 배치했다. 컴프레서 출력 볼륨은 0–100%이며, 기존 보정 게인에 곱해 압축 경로에만 적용한다. 재생 볼륨과 음소거 값은 바꾸지 않는다. 컴프레서 영역은 MAIN world의 재생 볼륨 휠 판정에서 제외한다.

컴프레서 켜짐 상태와 출력 볼륨은 background가 실제 발신 탭 ID로 구분해 `chrome.storage.local`에 저장한다. 최대 128개 탭을 보관하고 탭 종료·브라우저 시작 시 정리한다. 서비스 워커의 재시작과 페이지 새로고침에는 상태를 유지한다. 이전 공용 켜짐 값은 읽거나 갱신하지 않는다. 기존 새로고침 복원 테스트는 탭별 복원 계약으로 변경했고, 다른 탭의 상태를 유지하는 회귀 범위를 추가했다. 기존 툴팁 테스트도 재생 볼륨과 컴프레서 출력 볼륨을 각각 표시하는 계약으로 변경했다.

## 네이티브 UI 실측

- 대상: `https://chzzk.naver.com/live/bad6d7da33aec001343a51b85a70fcdb`
- 브라우저에서 일반 화질 재생을 선택한 뒤 확인했다. `.pzp-pc__volume-control` 아래에 스피커 버튼과 `.pzp-pc__volume-slider`가 순서대로 있으며, 슬라이더는 `role="slider"`, `aria-valuemin="0"`, `aria-valuemax="100"`을 사용한다.
- 스피커 버튼은 36px, 트랙은 2px, 핸들은 10px이었다. 접힌 네이티브 볼륨바 너비는 0px이었다.
- 루트가 `theme_dark`인 상태와 `light`인 상태에서 볼륨 트랙의 채움은 `rgb(255, 255, 255)`, 배경은 `rgba(255, 255, 255, 0.5)`였다. 새 컨트롤은 네이티브 클래스와 트랙 색상을 다시 동기화하며 정적 기본값도 둔다.

## 로컬 브라우저 검증

실제 런타임 파일과 네이티브 구조를 반영한 로컬 재현 페이지에서 확인했다. Chrome API는 재현용 구현을 사용하므로 실제 확장 주입과는 구분한다.

- 재생 볼륨 35%에서 컴프레서 볼륨을 키보드로 40%까지 조절해도 재생 볼륨은 35%를 유지했다. 재생 볼륨바를 100%로 바꿔도 컴프레서 값은 유지됐다.
- 컴프레서 볼륨바 드래그로 100%, 휠 한 번으로 95%를 적용해도 재생 볼륨은 35%였다.
- 다른 탭은 꺼짐·100%로 시작했고, 새로고침 시 해당 탭의 켜짐·10%가 복원됐다.
- 기능 비활성화 시 컨트롤을 제거하고, 재활성화와 플레이어 DOM 교체 뒤 켜짐·10%를 복원했다.
- `/lives`로 이동하면 컨트롤을 제거하고, 방송 경로로 돌아오면 켜짐·94%를 복원했다.
- 라이트·다크 모드와 380px 브라우저 너비에서 슬라이더·퍼센트·키보드 포커스 표시를 확인했다. 버튼 도움말과 출력 퍼센트가 겹치지 않도록 했다.
- 완료된 검증 탭에서 콘솔 오류·경고는 없었다. 재현 중 한 탭의 브라우저 제어가 응답하지 않아 다른 탭에서 새로고침·옵션·DOM 교체 검증을 완료했다.
- 최종 저장 방식은 실제 `background.js`를 실행하는 로컬 메시지 어댑터로 다시 확인했다. A 탭의 켜짐·30%가 새로고침 뒤 복원됐고, B 탭은 꺼짐·100%를 유지했다.

## 한계와 직접 확인

브라우저 도구가 Chrome의 기존 `chrome://extensions/` 탭 접근을 차단해 개발 확장의 다시 로드, 실제 확장 ID와 isolated world 주입, 실방송 음성 청취는 확인하지 못했다. 확장 관리에서 개발 확장을 다시 로드하고 서로 다른 방송 두 탭을 새로고침한 뒤, 한쪽 컴프레서의 토글·볼륨바가 다른 탭에 영향을 주지 않는지 확인하면 된다. 각 스피커 오른쪽 재생 볼륨바와 컴프레서 오른쪽 출력 볼륨바도 각각 드래그해 확인한다.
