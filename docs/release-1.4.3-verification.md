# 1.4.3 릴리스 준비 검증

## 상태

2026-10-11 KST 사용자의 "업데이트 알림이랑 버전 등 올려서 릴리즈 가능하도록" 요청으로 준비했어요. 버전·안내·문서·배포 ZIP과 자동 검증, Edge 실제 업데이트 점검은 Claude가 수행했어요. 남은 실제 Chrome 점검(아래 `필수 점검 상태`의 미검증 항목)은 같은 날 사용자가 확인하고 "정상"이라고 보고했어요. **이 항목들은 사용자 확인 결과이며 Claude가 직접 관측한 결과가 아니에요.** 사용자 보고에 따라 사용자 요청으로 커밋하고 `1.4.3` branch를 push했어요. 태그·GitHub Release·스토어 제출·main 병합은 하지 않았어요.

- 소스 기준: branch `1.4.3`, HEAD `e73370bbc08c698c42e80dad4c2795ae08d3ab02`와 미커밋 변경(고화질 설치 안내 Edge 변형, 확인형 안내 자동 닫기·깜빡임 보완, 이번 버전·문서 변경). 미커밋 소스는 배포 파일별 SHA-256으로 대조했어요.
- 직전 배포 기준: 원격 태그 `v1.4.2` → 커밋 `40d1feb75d0fbf970d6604855efd258954f41fb7`(origin/main). **이 1.4.3 branch는 그 커밋에서 이어지지 않아요**(공통 조상 `0e08e78`). 두 이력의 차이는 README·`docs/release-1.4.2-verification.md`·tracking 문서뿐이고 런타임 코드는 같아요. 배포본 README가 지운 “개발 작업본” 표시는 이번 README에 같은 문구로 반영했어요. 공개 전 main에 합칠 때 문서 충돌을 정리해야 해요.
- 환경: Windows 11, Node 24.18.0, npm 11.16.0, Microsoft Edge 155.0.4283.45.

- manifest·package·package-lock 루트(`version`, `packages[""].version`)를 1.4.3으로 바꿨어요. 버전 정합성 검사(`tests/extension-pages.test.js`)의 기대값을 이전 릴리스와 같은 방식으로 1.4.3으로 바꿨어요.
- `docs/update-history.md`에 `1.4.3 (2026-10-11)`을 추가했어요. 날짜는 준비일이며 실제 공개일이 다르면 공개 때 맞춰요. README 상단 버전·`1.4.3 변경 사항`, PRIVACY의 앰비언트 로컬 저장 항목, 스토어 설명(`store-assets/chrome-web-store-description.txt`)의 앰비언트 소개를 반영했어요. 새 권한·호스트·서드파티 코드는 없어 권한 설명과 THIRD_PARTY_NOTICES는 그대로예요.

Claude 초안을 2026-10-11 사용자가 이 문구 그대로 확정했어요. 확인형 안내·설치 권유 안내 처리를 안내에 덧붙이는 안도 검토했지만 사용자가 처음 문구를 택해, 이 두 보완은 업데이트 내역·README에만 적었어요.

## 실제 업데이트 점검 — Edge 155 임시 프로필, 16:50~16:57 KST

**Chrome이 아니라 Edge예요.** 이 PC의 Chrome 155는 명령줄 확장 로드를 무시하고, 확장 관리 화면 조작은 도구 경계 밖이라 Chromium 기반 Edge로 대신 확인했어요. 사용자 프로필은 쓰지 않았고 로그인하지 않았으며, 측정 뒤 임시 프로필 프로세스만 종료했어요. 조작은 CDP로 했어요.

- 업데이트 경로: `40d1feb`(v1.4.2)를 임시 폴더에 풀어 압축해제 확장으로 설치하고 버전 1.4.2, 안내 상태 `suppressed 1.4.2`(새 설치는 자동 안내 없음)를 확인했어요. 같은 폴더를 위 1.4.3 ZIP 내용으로 바꾸고 확장 옵션 문서에서 `chrome.runtime.reload()`로 다시 로드해 **같은 ID `ncplijhpegncgkgmbhbdopegeekpmbde`, 1.4.3**과 상태 `pending 1.4.3`을 확인했어요. 삭제·재설치나 안내 저장값 초기화로 대체하지 않았어요. 스토어 배포 업데이트 시험은 아니에요.
