# 방송 시작 동작의 중복 방지

## 배경

alarm·옵션 변경·서비스 워커 재시작이 겹칠 수 있고, 알림 표시·탭 생성은 저장소와 하나의 원자적 작업이 아니에요. 이미 열린 탭 확인만으로 데스크톱 알림의 중복이나 모든 중간 실패를 제어할 수는 없어요.

## 선택

처음 켜거나 브라우저를 시작했을 때 이미 진행 중인 방송은 조용히 기준 상태로 기억해요. 이후 새 방송에 대해 처리 상태를 먼저 저장하고 채널별 알림·자동 입장을 실행해요. 실패 재시도 없이 현재 방식을 유지해요.

자동 입장은 기존 `url`·`pendingUrl`에 같은 채널의 방송·대기 탭이 있으면 새 탭을 만들지 않아요. 자동 입장과 사용자가 알림을 클릭한 뒤 탭을 활성화하는 동작을 구분해요.

## 다른 선택과 차이

알림·탭 효과가 성공한 뒤만 처리 상태를 저장하면 일부 실패는 재시도할 수 있지만, 효과 성공과 저장 사이에 작업이 종료되면 같은 효과가 반복될 수 있어요. 이미 열린 탭 확인은 탭 중복에는 도움이 되지만 알림 전달 여부까지 알려 주지 않아요. 효과별 자동 재시도 보장보다 현재의 중복 방지 우선을 유지해요.

## 결과

처리 상태 저장이 실패하면 효과를 실행하지 않아요. 저장 후 효과가 실패하면 같은 방송에 알림·입장이 누락될 수 있어요. 알림 실패가 별도 자동 입장을 중단시키지는 않아요. 최근 방송 ID 보관에는 상한이 있으므로 무기한 정확히 한 번 전달되는 시스템으로 설명하지 않아요.
