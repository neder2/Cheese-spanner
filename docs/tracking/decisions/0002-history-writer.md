# 시청 기록의 단일 쓰기 경계

## 배경

여러 탭의 시청 세션, 기록 페이지의 삭제, 늦은 방송 ID 확인, 본인 활동과 과거 후원 조회가 같은 기록에 영향을 줘요. 저장소 호출 하나가 성공해도 서로 다른 소비자의 읽기·수정·쓰기가 겹치면 이전 상태가 나중 상태를 덮을 수 있어요.

## 선택

시청 기록 변경은 발신자·형식 검증 뒤 서비스 워커의 Promise 큐에서 최신 값을 읽어 병합하고 저장해요. 콘텐츠는 세션 누적값을 보내며 기록 페이지는 삭제·다시보기 번호 등의 명령을 보내요. 순수 변경 계산과 실제 저장을 나눠요. 과거 후원 조회도 같은 writer로 완료 스냅샷을 전달해요.

## 다른 선택과 차이

각 화면에서 local 기록을 직접 수정하면 코드 경로는 짧아지지만 다중 탭·삭제·조회 완료 사이의 일관된 순서를 보장하기 어려워요. 단순 증분 시간 전송은 재전송 때 중복 누적을 막기 위해 별도 보장이 필요해요. 현재는 절대값 스냅샷과 세션 정체성을 사용해 같은 결과를 다시 받아도 중복 집계하지 않아요.

## 결과

새 기록 생산자는 직접 저장하는 지름길을 만들 수 없어요. 삭제 시점·임시 ID 연결·오래된 세션의 압축·보관 상한까지 함께 검증해야 해요. 쓰기 큐 실패가 이후 작업을 영구 중단시키지 않아야 하며, 실패 응답을 성공으로 표시하지 않아요. 시청 기록 외의 모든 local 설정을 이 큐로 합쳐야 한다는 결정은 아니에요.
