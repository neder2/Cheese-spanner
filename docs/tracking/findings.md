# 치즈 스패너 남은 확인 사항

## 2026-10-28 이슈 #5 방송 알림 등록 `Failed to fetch` — 사이트 액세스 제한 감지·안내 수정, 사용자 확인 대기

- 조건·증상: [이슈 #5](https://github.com/neder2/Cheese-spanner/issues/5)(2026-10-24, Microsoft Edge). 옵션 `방송 알림` 탭에서 채널 ID를 추가하면 `채널 조회에 실패했어요. 네트워크와 주소를 확인한 뒤 다시 시도해 주세요.`가 떠요. 헤더 `방송 알림` 패널은 채널 검색 결과(팔로워 수 포함)를 보여 주지만 `데스크톱 알림`을 누르면 `Failed to fetch`가 떠요. 다른 채널도 같다고 했어요.
- 원인(2026-10-28 실측): 채널 검색은 콘텐츠 스크립트(`features/liveStartRegistration.js`)가 페이지 출처로 요청하고, 등록 확인은 확장 출처에서 요청해요. 옵션 페이지(`optionsLiveStart.js`)와 서비스 워커의 등록 처리(`shared/liveStartMonitor.js`)가 `api.chzzk.naver.com/service/v1/channels/{id}`를 직접 조회해요. macOS의 Edge 156.0.4314.50과 Chrome for Testing 155.0.8059.12 임시 프로필에 현재 작업 트리를 `--load-extension`으로 올리고 CDP로 확인했어요(사용자 프로필 미사용).
    - 사이트 액세스 기본값(요청한 사이트 모두 허용): 워커·옵션 페이지 요청에 `Origin`이 없고 `Sec-Fetch-Site: none`이며 200이었어요. 페이지에서 보낸 등록 메시지도 `ok: true`였고, 확인 뒤 등록을 해제했어요.
    - `chzzk.naver.com`만 허용(`hostAccess: ON_SPECIFIC_SITES`, `permissions.getAll().origins`는 `https://chzzk.naver.com/*`뿐): 같은 요청이 `Origin: chrome-extension://…`, `Sec-Fetch-Site: cross-site`로 나갔어요. 치지직 API는 `Access-Control-Allow-Origin` 없이 403으로 응답했고, 브라우저가 `MissingAllowOriginHeader` CORS 오류로 막아 `TypeError: Failed to fetch`가 됐어요. 이 상태에서도 콘텐츠 스크립트 검색은 200이었고, 페이지 등록 메시지 응답은 제보 화면과 같은 `{ ok: false, error: "Failed to fetch" }`였어요. 옵션 페이지는 같은 오류를 위 일반 실패 문구로 바꿔 보여 줘요.
    - Edge 화면에서 이 상태는 `확장 > 치즈 스패너 세부 정보 > 사이트 액세스`의 `다음 사이트에서 자동으로 액세스 허용`이 꺼지고 `https://chzzk.naver.com/*`만 켜진 모습이에요.
    - 제외한 후보: Edge 추적 방지 `엄격`(`enhanced_tracking_prevention.user_pref` 3)에서도 워커 조회는 200이었어요. Chrome for Testing도 같은 결과라 Edge 전용 동작이 아니에요. 허용 상태의 요청은 측정 시점에도 성공했으므로, 치지직 API가 확장 요청 전체를 막는 변화로 볼 근거도 없어요.
- 미확인: 제보자 Edge의 실제 사이트 액세스 값·Edge 버전·OS는 확인하지 않았어요. 네트워크 필터·회사 정책 같은 다른 원인은 측정하지 않았어요.
- 수정(2026-10-28, 1.4.6 작업 트리 미커밋): `shared/liveStart.js`의 `API_HOST_PERMISSION`을 워커와 옵션이 함께 써요.
    - 워커(`shared/liveStartMonitor.js`): 접근이 보류되면 모든 채널의 방송 확인을 멈추고, 저장된 최근 방송 ID도 기능을 끈 때처럼 비워요. 상태에는 사이트 액세스 안내를 남겨요. `permissions.onRemoved`·`onAdded`의 `origins`에 API 호스트가 있으면 다시 확인하고, 다시 허용한 때 진행 중인 방송은 기준 상태로만 기억해요. 새 채널 등록은 조회 전에 접근을 확인해 안내 문구를 돌려줘요. 조회 실패는 기존 `채널 정보를 확인하지 못했어요…`로, 저장 오류 같은 원문은 `채널 설정을 저장하지 못했어요.`로 바꿔 돌려줘요.
    - 옵션(`optionsLiveStart.js`, `options.html`): 접근이 보류되면 `치지직 API 접근 허용` 버튼을 보여 주고, 채널 추가는 조회 없이 안내해요. 버튼은 클릭에서 `chrome.permissions.request(API_HOST_PERMISSION)`를 호출해요. 권한 변경 이벤트로 버튼과 지난 안내를 갱신해요.
    - 재허용 때 진행 중인 방송을 기준 상태로 두는 동작은 [중복 방지 결정](decisions/0004-live-start-effects.md)과 알림 권한 재허용의 기존 동작에 맞춘 선택이며, 별도 제품 결정으로 확인받지는 않았어요.
- 검증: 수정 전 실패·수정 후 통과하는 회귀 3개(`tests/live-start.test.js`: 워커 일시 중지·상태·재허용 기준화, 등록 안내·원문 오류 차단, 옵션 버튼·클릭 요청·지난 안내 정리)를 추가했어요. 전체 `test:all` 1,906개와 `lint`가 통과했고, `format:check`는 Git 제외 개인 설정 `.claude/settings.local.json`에서만 실패했어요. Edge 156 임시 프로필에서 제한 → 워커 `onRemoved` 수신·상태 안내·알람 해제·확장 출처 API 요청 0건, 페이지 등록 응답의 안내 문구, 옵션 버튼 표시와 채널 추가 안내를 확인했어요. 확장 관리 페이지에서 다시 허용하자 `onAdded` 수신 뒤 확인이 재개됐고, 자동 열기 탭은 열리지 않았어요(기준화). 조회를 막은 상태의 등록 응답은 한국어 문구였어요. 옵션의 라이트·다크·420px 팝업 폭·키보드 초점 화면도 확인했어요.
- 패널 확인(2026-10-28, 1.4.6 후보 ZIP, Chrome for Testing 새 프로필): `chzzk.naver.com`만 허용한 상태로 치지직 상단 `방송 알림` 패널에서 검색 결과의 `데스크톱 알림`을 실제 마우스 입력으로 눌렀어요. 패널 안에 사이트 액세스 안내가 3줄로 줄바꿈되어 가로 넘침 없이 보였고(다크·라이트), 채널은 저장되지 않았어요. 상세는 [1.4.6 검증 기록](../release-1.4.6-verification.md#방송-알림-사이트-액세스-안내이슈-5)에 있어요.
- 공개: 2026-10-28 사용자 승인("공개 진행")으로 이 수정을 1.4.6에 넣어 커밋·태그·GitHub Release로 공개해요. 이슈 #5 답변은 사용자 요청대로 게시하지 않았어요.

## 2026-10-27 1.4.6 동기화 검증 — 테스트 종료 뒤 비동기 오류 1회 (2026-10-28 원인 확정·테스트 대기 수정)

CLOSE 확인 뒤 재생한 시청 시간은 일시적 CLOSE에 시간을 잃지 않도록 같은 기록에 계속 쌓여요. 버린 활동 ID 기억은 최대 1,000개예요. 영상이 일시정지된 채 status 없는 응답이 오면 정해진 세션도 새 활동을 멈춰요. 오프라인에서 방송이 시작되면 새 세션 전 채팅은 버려지고, 기기 시계가 늦으면 직전 오프라인 채팅이 다시 수집될 수 있어요. status가 없는 응답은 본영상이 재생 중일 때만 현재 방송으로 인정해요.
    - 자동 화질: 라이브·VOD 모두 경로·선호 화질·플레이어·video 조합의 입장 적용을 기록하고, 같은 조합의 다시 온 요청(무관한 옵션 저장 포함)은 현재 트랙과 상관없이 `already`로 답해요. 페이지 적용 창이 만든 `selected`는 그 창의 180ms 확인이 끝날 때까지 임시라 선택이 안 먹었으면 한 번 더 고르고, 그 확인 시간 안의 트랙 변화는 사용자 변경도 플랫폼 되돌림으로 봐요. isolated 요청이 직접 바꾼 선택은 확인 없이 바로 완료예요. 영상은 같고 플레이어만 바뀌면 바깥 요청이 와야 다시 적용해요. 사용자 조작 신호는 페이지 어디든 누름을 세므로 전환 직후 영상 밖을 누르면 전환이 만든 정지도 재개하지 않아요. 적용 완료를 경로·선호 화질·플레이어·video 조합당 1회로 보므로 플랫폼의 자체 강등이나 늦게 추가된 높은 트랙에는 다시 적용하지 않아요. 기능을 다시 켰을 때 재적용하는 것은 옵션 저장 시 적용으로 해석한 결과예요.
    - 설정 파일: 손상된 멀티뷰 값 하나는 내보내기에서 알림 없이 그 항목만 빠지고, 방송 대상 이미지 URL은 길이 상한이 없어 극단적이면 1 MiB를 넘을 수 있어요. 권한 확인은 옵션 화면에서만 해요.
