## VOD 이어보기 초기화 — 코드 경로 보완, 신고 조건·서버 순서 미확정

- 현재 상태(2026-10-03): 실사용 비교 뒤 사용자 요청으로 채팅 자동 복구 파일·등록·일회용 위치 전달을 제거했어요. 아래 복구 경로 보완과 장애→복구 검증의 미완료 설명은 제거 전 기록이며 현행 기능의 추가 검증 과제가 아니에요. 네이티브 이어보기 신고의 서버 순서·당시 조건 미확정은 별도로 남아요.

- 2026-10-03 재검증: 관련 자동 검사 176개가 통과했고, 사용자 승인 후 실제 Chrome에서 확장 전체 OFF→ON→OFF→ON을 비교했어요. 같은 채널의 VOD 3개에서 내부 이동·채팅 닫기/열기·시간 탐색·넓은 화면 복원 모두 OFF에서도 정상 채팅을 확인했어요. 필수성은 입증되지 않았고 실제 제목 누락 장애의 복구 효과와 파일 단독 제거 시 상호작용은 미검증이에요. 확장은 ON으로 복원했으며 런타임은 변경하지 않았어요. 조건·주입 확인·제외 표본·한계는 [OFF/ON 실사용 기록](../measurements/vod-chat-ab-2026-10-03.md)에 있어요.
- 확인·수정: 2026-10-01 실제 Chrome의 정상 채팅 닫기는 제목·aside를 없애면서 재생을 유지했어요. 기존 코드의 제목 부재·DOM 연결 판정과 영구 currentTime URL 생성은 오탐·이어보기 덮어쓰기 경로예요. 전체 스크립트 통제 검사에서 탐색 뒤 화질 요청이 300초를 12초로 되돌리는 최초 쓰기도 확인했어요. 열린 패널·준비된 영상으로 범위를 좁히고 위치는 60초 이내의 일회용 sessionStorage로 전달·소비하며, 초기 URL 보정을 완료/취소 뒤 재예약하지 않도록 했어요.
- 결과·영향: 새 회귀 27개는 수정 전 22개 실패·수정 후 전부 통과, 관련 282개·전체 1,459개와 lint도 통과했어요. 사용자가 확장을 재로드한 뒤 일반 URL 새로고침 1,632.56→1,632.12초, 탭 재열기 1,761.43→1,761.11초의 준비 완료·재생 중 표본을 확인했어요. 일반 URL의 초기화는 이 구간에서 재현되지 않았어요. 이것만으로 신고자의 원인을 확정하지 않아요.
- 남은 이유: 브라우저 정책이 확장 설정·관리 URL을 차단해 새 문서 OFF/단독/둘 다 비교를 직접 수행하지 못했고, 네트워크 payload·첫 이벤트 기록 기능도 없어요. 사용자의 재로드 확인을 로드 폴더·소스 바이트 검증으로 확대하지 않아요. 채팅 자동 복구의 필수성은 입증되지 않았으며 실제 장애→복구→소비 전체는 합성 검사만 있어요.
- 기존 주소: 예전 확장의 무표식 currentTime과 사용자 타임코드는 구분할 수 없어 자동 삭제하지 않았어요. 기존 주소 자체가 다음 방문에서 과거 시간을 우선할 수 있어 신고 URL 확인이 필요해요.
- 다음 확인: 당시 주소·조건을 확인하고, 인증정보 없이 첫 잘못된 positionAt/다음 watchTimeline과 play→playing→seeking/seeked→화질 변경을 관측해요. 일반 URL에서도 실패하면 완전히 새 문서의 자동 화질/광고 OFF·단독·둘 다를 비교해요. VOD 내부 이동의 빈 플레이어는 아래 기존 미확정 항목으로 이어가요. 상세 근거·미실행 항목은 `docs/measurements/vod-resume-2026-10-01.md`에 있어요.

## 카테고리 제외의 실제 Chrome 확인 대기

- 조건·확인 범위: 2026-10-01 최종 코드와 자동 검사에서 전체 방송 한정 UI, 이름 검색·정확한 유형/ID, 현재 원본 링크·주입 카드의 채널/liveId, 두 탭 저장 경합·실패 보존·늦은 응답을 확인했어요. 2026-09-30 인증정보 없는 HTTP 조회도 검색 결과와 방송 수 0인 카테고리를 확인했지만 실제 Chrome에서 새 코드를 로드한 뒤의 요청·카드 DOM·저장은 관측하지 않았어요. 현재 기능의 확정 결함을 발견한 기록은 아니에요.
- 가능한 영향: 실제 Chrome의 CORS·기존 로그인 세션 요청이 검색을 막거나, 실제 카드 링크 형식이 식별 계약과 다르면 제외를 적용하지 못할 수 있어요. 홈에서 SPA로 들어온 문서의 sender.url은 실제 수신 정보로 확인하지 않아 엄격한 `/lives` 검증의 성공 여부도 남아 있어요. 자동 fixture로 두 탭 즉시 반영·재시작 복원과 브라우저 기본 Enter/Space·좁은 메뉴·두 테마의 표시까지 증명할 수 없어요.
- 지금 확인하지 않은 이유: 컴퓨터 사용은 사용자의 명시적 재요청 전에는 하지 않는 도구 제한을 유지했어요. 다른 브라우저 제어나 숨은 디버깅 연결로 이를 우회하지 않았으며 HTTP·공식 공개 코드·자동 검사 결과를 실제 확장 주입 성공으로 바꾸지 않아요.
- 다음 확인: 현재 소스를 확장에 다시 로드하고 전체 방송 탭을 새로고침해 실제 UI·요청과 카테고리 링크를 확인해요. 방송 없는 게임 검색, 원본·추가 카드 제외/개별 해제, 인기·최신·추천과 숫자 초기화, 두 탭의 추가·해제와 즉시 반영, 새로고침·새 문서·브라우저 재시작·OFF/ON을 확인해요. 홈→전체 방송의 내부 이동에서는 실제 발신 URL과 저장 결과를 확인하고 다른 경로·집계만 켠 상태는 영향을 받지 않아야 해요. Tab·Enter·Space·Escape·긴 이름·좁은 폭·두 테마도 확인해요. 추가한 임시 항목만 개별 해제하고 기존 선택을 전체 초기화하지 않아요.

## 라이브 PiP 중간 광고 누락 — 코드 보완·재적용 확인, 중간 일정 현장 확인 대기

- 조건·현상: 사용자가 라이브 PiP에서 광고가 나왔다고 보고했어요. 실제 홈·전체 방송 화면에서 active true인 상태로 라이브 PiP와 중간 광고 영상이 유지됐지만, 코드의 `/live/` 주소 조건은 이 경로를 건너뛰었어요. 광고 소재 자체는 도구로 재포착하지 않았어요.
- 보완: 광고 컴포넌트·현재 등록과 본영상 컨트롤러·라이브 PiP 배치의 소유가 함께 맞는 독립 중간 일정만 처리하도록 했어요. 홈 JSON·목록 미리보기·VOD PiP까지 일괄 허용하지 않아요. 새 긍정 회귀 3개 실패를 재현하고 수정 후 관련 62개·인접 210개·전체 1,282개 테스트를 통과했어요.
- 재적용 확인: 사용자가 확장·라이브 탭을 다시 로드하고 PiP로 띄웠다고 확인했어요. 2026-09-30 00:11:53~00:16:42 KST의 `/lives`에서 active true·reloadRequired false와 본영상 시간 118.534→407.345초, 영상 오류 없음·재생 중 상태를 관측했어요. 일정 처리 1회·입장 일정 처리 1회는 그대로였어요.

- 조건·증상: 사용자는 최초 수정 뒤에도 새 탭에서 홈·전체 방송 목록을 먼저 열고 방송을 클릭하면 버튼이 꺼짐이라고 보고했어요. get이 읽기와 등록을 함께 수행하는데 문서 시작에 호출해 목록 단계의 선택을 미리 고정하던 경로를 찾았어요. 수정 전 실제 페이지·worker 연결 회귀 두 개가 실패했고 첫 재생 진입에 조회하도록 보완한 뒤 통과했어요. 수정 전 실제 Chrome의 꺼짐 전환 자체를 독립 재현한 것은 아니에요.

- 남은 이유·영향: 실제 Chrome 접근은 사용자가 추가로 허용한 읽기 전용 범위였어요. 여러 값을 직접 조작하는 비교, 브라우저 완전 재시작, VOD·소리·자동재생 제한은 아직 확인하지 않았어요. 버튼·출력 볼륨의 복원 확인을 실제 압축 소리 적용 성공으로 확대하지 않아요.
- 다음 확인: 라이브 A와 B를 먼저 열고 A에서 ON·30%를 고른 뒤 새 라이브/VOD C가 같은 선택인지 확인해요. 홈·목록 탭을 새로 열어 둔 상태에서 A를 OFF·80%로 바꾸고 그 목록에서 처음 들어가는 방송은 OFF·80%인지, 이미 재생한 B와 C 및 C의 새로고침은 유지되는지 확인해요. 출력 0·100%, 마지막 조작 탭 종료·브라우저 완전 종료 후 재진입, 네이티브 볼륨·음소거와 실제 사용자 입력 뒤 소리 복구를 대조해요.

## 컴프레서 정리 실패와 확장 재로드의 중첩

- 조건·근거: 브라우저 시작의 local 탭 정리가 실패하면 이전 세션 탭 값이 남을 수 있어요. 대기가 session에만 보관된 상태에서 확장 재로드·업데이트가 겹치면 session이 지워져 그 대기도 소실될 수 있어요. 이는 코드 수명 경계 검토이며 실제 Chrome 재현은 미확인이에요.
- 영향: 이 조합 뒤 탭 ID가 일치하면 기본 선택 대신 이전 세션 스냅샷을 고를 가능성이 있어요. session/local 양쪽 제어 기록이 모두 실패한 뒤 워커가 소멸하는 전체 저장 장애도 미저장 대기를 복구할 수 없어요. 실패한 요청은 성공으로 응답하지 않고 원래 선택은 보존해요.
- 남긴 이유: 이번 검증은 정상 재로드의 스냅샷 보존과 정리 실패 후 일반 워커 재생성을 다뤘어요. 저장 장애 뒤 session을 없애는 확장 재로드 중첩은 일반 워커 재시작과 달라 별도 확인 범위로 남겨요.
- 다음 확인: local 정리 실패 뒤 일반 워커 재생성과 확장 재로드를 나눠 실제 결과를 확인해요. 두 제어 저장 수단을 모두 사용할 수 없는 경우 복원 가능한 정보와 선택 보존 정책도 함께 확인해요.

## 새 기능 안내의 실제 화면 검증

- 2026-09-30 릴리즈 확인: 사용자가 실제 Chrome에서 1.4.0→1.4.1 업데이트 후 여러 탭 중 최초 1회, 자동·수동 20초 게이지와 정지/재개, 옵션 팝업 종료 후 안내 유지, 라이트·다크·좁은 화면의 내용/버튼을 모두 직접 확인했다고 답했어요. 아래 미검증 문구는 이 확인 전의 작업 기록이에요. 에이전트 직접 화면 측정과 사용자 수동 확인을 구분하며 최종 전체 검사 1,335개와 ZIP 대조 결과는 docs/release-1.4.1-verification.md에 있어요.
- 타이머 후속 수정: 다시보기에는 타이머·게이지가 연결되지 않았고 제목에 강제로 초점을 옮기는 경로가 있었어요. 다시보기도 같은 20초로 동작하도록 연결하고 강제 초점을 없앴어요. 팝업 종료 후 초점 복귀·호버/키보드 정지·새 20초·늦은 자동 응답·게이지 예외 회귀를 포함한 관련 검사 235개가 통과했어요. 실제 Chrome에서의 사용자 화면·실행 버전 확인은 코드 수정까지만 요청한 범위에 따라 남아 있어요.
- 사용자 확인·옵션 내부 표시 수정: 치지직에서 확장 아이콘으로 연 작은 옵션 팝업 안에 안내가 생기고 팝업 종료 때 사라진다고 확인받았어요. 전달 실패를 옵션 내부 표시로 대신하던 코드를 제거하고 치지직 페이지의 표시 성공만 인정하도록 바꿨어요. 자동 검사에서는 실제 페이지 수신 코드와 별도 옵션 문서를 연결해 치지직에 안내가 생기고 옵션 팝업 종료 후에도 유지되는지 확인했으며 관련 검사 230개가 통과했어요. 실제 Chrome에서 기존 전달이 실패한 원인과 수정본의 주입·연결은 아직 확인하지 않았어요. 후속 실제 Chrome 확인은 사용자가 코드 수정까지만으로 범위를 지정해 수행하지 않았어요.
- 조건·현상: 버전별 1회 상태·다중 탭·20초 타이머·키보드·위치 부재·좁은 공간의 자동 보류는 자동 DOM 검사로 확인했어요. 실제 Chrome에서 상위 버전 설치와 확장 주입, 현재 치지직의 라이트·다크 픽셀 배치는 확인하지 않았어요.
- 영향: 자동 검사만으로 실서비스의 모든 레이아웃에서 알림이 시청을 방해하지 않는다고 확정할 수 없어요. 이전 개발 manifest 1.4.0에서 미래 1.4.1 자료를 노출하지 않은 것은 정상이며, 2026-09-30에는 요청 범위에 따라 버전 파일을 1.4.1로 맞췄어요.
- 후속 구현: 150px의 좁은 세로 배치와 단계별 안내를 한 창으로 교체했어요. 크기 조절·시청기록 백업 두 항목과 짧은 사용법을 함께 보여주고 닫기 버튼만 제공해요. 자동 안내와 수동 다시보기가 공용 렌더링을 사용하며, 이전/다음·설정 이동·위치 강조·스트림 정보 소개는 제거했어요. 20초·호버/초점·한 번 표시·OFF·SPA/BFCache의 상태 경계는 유지해요.
- 창·색상 후속 수정: 다른 창·탭으로 옮겨도 자동·수동 안내를 유지하고 자동 타이머만 멈추도록 바꿨어요. 복귀 시 남은 시간만 이어가는 동작과 표시 승인 전 취소를 포함해 관련 검사 226개가 통과했어요. 테마별 배경·제목·설명·민트색 강조를 정리했고 선언된 기본 색 대비를 계산했어요. 실제 치지직 토큰과 화면 대비는 아직 측정하지 않았어요.
- 지금 확인하지 않은 이유: 이번 요청은 ZIP 생성·릴리즈 노트 게시 이전의 로컬 준비이며 컴퓨터 사용은 명시적 재요청 전에는 하지 않는 경계를 유지해요. 실제 Chrome·배포 파일 검증을 완료했다고 보고하지 않아요.
- 다음 확인: 분리된 검증 프로필에서 실제 1.4.1 업데이트 후 한 탭의 자동 안내와 수동 다시보기가 같은 두 항목을 함께 보여주는지 확인해요. 실제 높이·줄바꿈·닫기 버튼 하나, 다른 창·탭 전환의 유지와 남은 시간 재개, 20초·호버·초점·전체화면·입력·두 테마/좁은 폭·SPA/BFCache와 미저장 편집 보존을 확인해요. ZIP 생성 이후 검증한 소스와 배포 파일도 대조해요. 현재 준비 결과는 `docs/release-1.4.1-verification.md`에 구분해요.

## 2026-10-03 카테고리 제외 고배율 메뉴 배치

- 조건·증상: 실제 Mac Chrome에서 치지직 전체 방송을 300% 확대하면 필터 메뉴 일부가 화면 밖으로 잘렸어요. 정상 100% 배율의 긴 카테고리명·유형·시청자 수 한 줄과 추가·제거 버튼은 두 테마에서 확인했어요.

- 지금 고치지 않는 이유: 이번 카테고리 후보 행 보완보다 넓은 기존 필터 메뉴의 위치·사이트 최소 폭 대응이 필요해요.
- 후속 확인: 메뉴의 가용 화면 경계·스크롤·앵커 배치를 고배율과 좁은 창에서 보완해요. 브라우저 재시작·실제 두 탭 동기화·키보드·SPA 취소도 별도로 확인해요. [검증 기록](../measurements/category-exclusions-mac-2026-10-03.md)에 자동 검증과 실제 확인을 구분했어요.
