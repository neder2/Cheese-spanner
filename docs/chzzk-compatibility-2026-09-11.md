## 완료 근거

작업하면서 각 단계의 수정 파일, 검증 결과, 실제 브라우저에서 확인한 범위를 아래에 기록한다.

- 자동 화질은 현재 광고 래퍼를 보존해 연결하며 비활성 상태의 오래된 래퍼도 트랙 정의를 변경하지 않는다. 양쪽 로드 순서 × 초기 화질 설정 4조합, 반복 토글, SPA 이동, 광고만 끄기 회귀 검증을 통과했다.
- 색상 토큰은 실제 페이지에서 값이 존재하는 이름으로 대응했다. 기본색을 대체하지 않고 현재 토큰 → 기존 토큰 → 정적 기본값 순서를 유지했다. 이미 현재 토큰을 사용하는 멀티뷰·라이브 표시 코드는 그대로 유지했다.
- `vendor-DVDNLy6N.css`의 현재 토큰과 수정된 기능 CSS를 사용하는 392px 로컬 검증 화면에서 라이트(`class=light`, `data-theme=light`)·다크(`class=theme_dark`, `data-theme=theme_dark`), 검색 포커스 대비와 가로 넘침 없음을 확인했다. 실제 방송 데이터가 아닌 명시적인 예시 UI로 검사했다.
- C키는 옵션 정규화와 키 입력 UI에서 거절되고, 과거 저장한 C값은 기본 배속 키로 복원된다. 옵션·설정 관련 22개 테스트 통과.
- 광고 연결 차단은 현재 SDK의 AdsPlayer 메서드와 스케줄/네이티브 플레이어 정체성을 확인한다. `glad:` src는 광고 팩토리 실행 전에 소스를 해제하며 본영상 URL과 다른 플레이어는 통과한다.
- 별도 라이브 중간 광고 경로는 GFP가 `#midAdVideoContainer`를 키로 스케줄러를 WeakMap에 등록하는 지점에서 해당 인스턴스의 `loadWithAdSchedule`만 감싼다. 확인한 두 광고 단위의 adSources를 비우고 네이티브 스케줄 완료 흐름을 유지한다. 입력 객체를 변경하지 않고 옵션 off·라우트 이탈·컨테이너 제거 시 통과한다. 추가 반복 타이머·별도 캐시·네트워크 차단은 없다.
- 추가 확인: 현재 SDK의 실제 `startAdSchedule`/`checkScheduleCompleted` 함수만 분리해 제어된 이벤트·타이머 환경에서 실행했다. 빈 광고 항목에서 재개 요청 → 광고 영역 숨김 → 완료 이벤트 순서와 타이머 해제를 확인했다. SDK 전체나 로그인된 실제 플레이어를 실행한 검증은 아니다.
- WeakMap 등록 100,000회 단일 로컬 측정: 기본 8.49ms, 처리 설치 후 9.55ms. 특정 환경의 참고 측정이며 일반적인 성능 보장은 아니다.
- 전체 테스트 575개 통과, lint 통과. 전체 format:check는 이전부터 있던 README 형식 차이로 실패했다.
- 변경한 코드·테스트·계획/실측 문서의 별도 Prettier 검사와 git diff --check는 통과했다. 커밋과 버전 증가는 하지 않았다.
- 사용자가 확장을 재로드한 뒤, 실제 확장 ID와 새 광고 진단 필드·테마 CSS로 수정본 주입을 확인했다. 다시보기 직접 진입에서 blockedVodSources=1, 라이브 직접 진입에서 blockedLiveSources=1을 확인했고 본영상은 모두 1080p, readyState=4로 재생됐다.
- 다시보기 → 라이브 SPA 이동에서 광고 소스 차단 카운터가 각각 1회 기록됐으며 이전 댓글 패널은 제거됐다. 실제 댓글 패널의 라이트/다크 표시도 확인했다.
- 실제 채널 동영상 탭에서 검색창이 선택된 버튼의 검은 배경을 복사하는 라이트 테마 오류를 추가 발견했다. 글자색 밝기 추정 대신 aria-selected=false인 네이티브 버튼을 선택하도록 수정했다. 실측한 두 테마의 색상 및 선택 상태 변경을 이용한 회귀 테스트가 수정 전 실패하고 수정 후 통과했다.
- 채널 영상·카테고리 검색창의 반전된 hover/focus 배경에 맞춰 placeholder 색상도 함께 바뀌도록 했다. 실브라우저의 카테고리 검색에서 다크 테마는 밝은 배경/어두운 안내 문구, 라이트 테마는 어두운 배경/흰 안내 문구를 확인했다.
- 마지막 수정 후 사용자 재로드를 거쳐 채널 영상 검색도 실브라우저에서 확인했다. 라이트 기본 배경 rgb(225,225,229), 다크 기본 배경 rgb(46,48,51), 두 테마의 포커스 안내 문구 대비가 정상이며 필터 변경 후에도 검색 바는 1개였다. 가로 넘침과 수집된 콘솔 error 로그는 없었다. 원래 다크 테마와 전체 필터로 복원했다.

## 검증 한계

- 브라우저 도구로 확장 관리/옵션 페이지에 접근할 수 없어 실제 옵션 UI 토글과 좁은 확장 팝업 조작은 수행하지 않았다. 광고·화질 옵션의 양쪽 로드 순서, 초기 옵션 지연, 반복 토글, 비활성화 정리는 통합 회귀 테스트로 확인했다. C키 거절과 기존 설정 정규화도 옵션·설정 테스트로 확인했다.
- 별도 라이브 중간 광고 스케줄은 실제 검증 구간에 발생하지 않아 blockedLiveSchedules=0이었다. 해당 경로는 회귀 테스트와 현재 SDK의 실제 함수 분리 검증을 근거로 하며, 자연 발생 광고 차단까지 확인했다고 해석하지 않는다. 장시간 모니터링은 재개하지 않았다.
- 팔로잉 제목 이력 등 매번 표시되지 않는 UI의 두 테마는 현재 배포 CSS와 실제 확장 CSS를 사용하는 로컬 화면에서 검증했다. 실제 페이지에서 확인한 댓글·채널 검색·카테고리 검색 결과와 구분한다.
- 선택적 추가 수동 확인: 확장 팝업에서 광고/자동 화질 옵션을 껐다 켠 뒤 대상 탭을 새로고침하고, 기본 배속 키와 C키 자막 동작을 확인할 수 있다.
