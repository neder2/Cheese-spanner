# 치즈 스패너 유지보수 메모

## 이전 화면의 데이터가 새 화면에 붙는 경우

치지직은 URL을 먼저 바꾸고 제목·카드·영상·채팅을 순차 갱신할 수 있어요. SPA 직후 `document.title`이나 og:title을 읽으면 이전 방송 제목일 수 있어요. 현재 live-detail의 채널·방송 정체성이 확인되기 전 제목은 임시 값으로 두고, 영구 제목 이력과 구분해야 해요. `liveWatchHistory.js`의 `titleVerified`와 저장 스냅샷 경로를 함께 확인해요.

채팅 행도 닉네임만 새 메시지로 바뀌고 역할 배지와 본문은 남아 있을 수 있어요. DOM 노드와 같은 텍스트만으로 재등장을 판별하면 일반 시청자를 운영자로 수집하거나 과거 원문을 섞게 돼요. messageStore의 binding·mutation revision·재사용 신호·철회 경로를 확인하고, 오래 지속된 혼합 상태가 나중에 일반 시청자로 확정되는 회귀를 실행해요.

보관한 원본 댓글·팔로잉 행도 클릭 직전에 식별자를 다시 읽어야 해요. 노드가 연결돼 있다는 사실만으로 저장 당시 대상과 같다고 볼 수 없어요. 카드 재사용·분리·루트 교체 테스트가 서로 다른 결함을 보호해요.

팔로잉 보충 행을 원본 행 전체에서 복제하면 이름을 바꿔도 원본 채널의 파티 인원 링크와 프로필의 파티 SVG가 남을 수 있어요. 두 요소 모두 해당 채널의 파티 상태에 속하므로 확장 소유 복제본에서 함께 정리해요. 이름에 들어 있는 `+숫자`와 구분하고 원본 행의 정상 표시·파티 이동 주소는 보존해요.

## 광고·화질이 같은 페이지 객체를 다루는 경우

광고 MAIN 스크립트는 manifest의 정적 목록이 아니라 동적 등록이에요. 기능을 켰는데 현재 탭에서 마커가 없으면 등록 여부와 새 문서 진입 여부를 구분해요. 옵션을 끈 뒤 기존 문서에서 이미 바뀐 플레이어 상태까지 자동 복원됐다고 가정하지 않아요.

확인된 광고 판단 응답에서 `livePlaybackJson.liveId/chatChannelId`가 boolean으로 쓰인 사례는 일반 방송 메타데이터의 동명 필드와 달라요. 필드명만 보고 모든 응답을 바꾸면 본영상에 영향을 줄 수 있어요. 키·타입·플레이어 소유 관계가 함께 일치하는지 확인하고 알 수 없는 wrapper·source·스케줄 통과 테스트를 유지해요.

명시적 광고 판단의 추가 필드를 구형 응답의 좁은 판별과 섞지 않아요. 명시적 두 boolean만 바꾸고 `postRoll`·media·부가 필드와 구형 필드를 보존하며, 잘못된 명시적 형태를 구형으로 재해석하지 않아요. 문자열 상한은 명시적 65,536·구형 2,048 UTF-16 code unit이에요.

광고 setter 정의 시점에는 영상이 아직 연결되지 않을 수 있어요. 설치와 호출 때의 소유 판정을 구분하고, 지연 후보는 최초 네이티브 `initAd` 직전에 한 번만 판단해요. 소유 검사 실패로 원본 초기화가 시작된 소스를 나중에 재설정하면 광고 client를 끊을 수 있으므로 이미 진입한 소스는 재연결·같은 객체 재할당으로 다시 처리하지 않아요. 반환 Promise와 원래 setter·초기화 예외도 유지해요.

독립 입장·중간 광고의 `contentVideo`는 본영상이 아닌 별도 영상이에요. DOM 이름이나 `.chzzk_player` 포함 관계만으로 소유를 판단하지 않고 네이티브 등록, 현재 채널 props·liveId, 같은 컴포넌트 첫 두 ref를 함께 읽어요. 중간 광고는 공개 표시 정보가 본영상 manager와 공유되기도 하므로 원래 두 ref와 현재 `props.player.adsController/viewSlot`·관측한 manager의 정보 동일성을 따로 확인해요. 약한 참조를 사용하고 변경된 등록·어댑터 video를 다시 읽어요.

React owner/alternate에서 잘못된 서비스·채널 후보만 건너뛰면 같은 ref를 가진 과거의 유효한 props로 현재 광고를 승인할 수 있어요. 어느 쪽이 현재인지 입증할 수 없는 충돌은 전체 원본 통과로 처리하고, 표시 정보를 읽는 사이 후보나 연결이 바뀌는 경우도 적용 직전에 재확인해요. WeakMap의 키만 기록하면 다른 map의 같은 키 쓰기와 실제 SDK 등록의 삭제를 구분하지 못해요. 원래 등록 map·manager를 함께 확인해 네이티브 destroy 뒤의 등록 해제를 반영하며, delete/get 전역 훅은 추가하지 않아요.

네이티브 일정의 빈 `adSources`는 완료로 이어지지만 항목 전체 삭제와 같지 않아요. 항목·순서·시간·원본을 보존하고 네이티브 완료를 호출하는 최소 모델과 실제 Chrome 본영상 진행 검증을 나눠요. JSON 경계를 우회한 입력도 기존 SDK 경계에 오면 처리할 수 있지만, 모든 경계를 우회한 경우까지 지원한다고 추정하지 않아요. 공개 배포 코드·과거 응답·합성 검사의 근거는 구분해요.

탭 주소가 홈·전체 방송이어도 치지직의 라이브 PiP는 본영상과 중간 광고 컴포넌트를 유지해요. 주소를 `/live/`로만 제한하면 PiP의 새 중간 일정은 누락돼요. 현재 player의 영상이 라이브 `pip_mode` 레이아웃에 속하고 광고 wrapper와 같은 부모인지, 광고 컴포넌트·현재 SDK 등록이 그 소유를 뒷받침하는지 확인해요. 중간 광고의 `miniMode`는 스크롤 축소 조건이며 실제 PiP에서는 false일 수 있으므로 PiP 판정으로 사용하지 않아요. 브라우저의 `document.pictureInPictureElement`가 null이어도 페이지 안의 PiP는 켜져 있을 수 있어요.

화질 선택의 첫 `playing` 이전에는 네이티브 초기 재생과 선택 요청이 충돌할 수 있어요. 초기 재생·선택 Promise 대기를 반복 폴링으로 바꾸지 말고 완료 이벤트로 이어지는 경로를 확인해요. 선택 플래그가 먼저 바뀌어도 Promise가 실패하면 적용 성공이 아니에요.

현재 화질 코드는 트랙 변화·DOM 변화·설정 갱신에서 다시 적용을 예약할 수 있어요. 제품의 ‘입장·선호 화질 저장 시 적용’ 범위를 구현하려면 초기 준비 완료와 새로운 사용자 선택을 구별해야 해요. 기존 모든 재시도를 한 번에 지우면 초기 입장 화질 개선도 잃을 수 있어요. 반복 적용 경로의 존재와 현재 사이트에서 실제 재강제가 재현됐다는 주장은 구분해요.

## 위치·미디어 객체의 수명

채팅을 닫으면 `aside#vod-aside`와 한국어 제목이 정상적으로 없어질 수 있어요. 제목 누락에 따른 자동 새로고침과 복구 전용 sessionStorage 위치 전달은 2026-10-03 사용자 요청으로 제거했어요. OFF/ON 실측은 `docs/measurements/vod-chat-ab-2026-10-03.md`, 과거 위치 부작용은 `docs/measurements/vod-resume-2026-10-01.md`에 구분했어요.

복구 위치를 `currentTime` URL에 붙이면 다음 새로고침에도 네이티브 `watchTimeline`보다 먼저 적용돼요. 기존 무표식 `currentTime`은 사용자 링크와 구분할 근거가 없어 일괄 삭제하지 않아요. 명시적 링크의 확장 보정은 안정화 뒤 끝내고 동일 VOD·시간에 대한 화질 요청·BFCache·hash 변경으로 다시 시작하지 않아요.

같은 해상도라는 사실만으로 현재 재생 방식을 판단하지 않아요. 실제 선택 트랙의 kind와 ID를 읽어야 해요. 네이티브의 onLive getter를 읽을 수 없는 경우 임의의 지연 초 기준으로 실시간을 추정하지 않아요.

네이티브 트랙 전환은 정상 처리 중에도 video의 `currentSrc`를 바꿀 수 있어요. 진행 중인 전환을 단순 URL 차이만으로 취소하면 자신의 성공 결과까지 놓쳐요. 같은 player·pane·provider·video 소유권을 검증하고 완료 시 실제 선택 ID·종류를 확인해요. 다른 provider나 라우트로 바뀐 경우의 취소와 구분해요. 같은 pane을 재사용하더라도 이전 네이티브 선택이 끝나기 전에 중복 선택하지 않아요.

같은 video가 미니 플레이어 이동으로 다른 부모에 붙을 수 있어요. 컴프레서는 같은 미디어 객체의 오디오 그래프를 무조건 해제·재생성하면 재생·소리가 끊길 수 있어요. DOM 부모 변경, 실제 영상 교체, BFCache 복귀를 나누고 `playback-media-lifecycle`의 해당 회귀로 확인해요.

확대된 영상의 표시 사각형은 원래 조작 영역과 달라요. 볼륨·홀드·확대 조작의 hit test에서 변환된 영상 rect를 그대로 쓰면 컨트롤을 가로챌 수 있어요. `getVideoViewportRect`와 확대 변환 기록을 함께 확인해요.

MAIN과 isolated에 같은 구현이 필요한 볼륨 판별 코드는 별도 파일 경로를 사용해요. Chrome의 world 간 경로 중복 처리로 한쪽 로드가 누락됐던 경로를 피하기 위한 구성이며, 구현 일치 검사를 확인하고 단순 중복 제거로 한 파일에 합치지 않아요.

멀티뷰 목표 딜레이와 현재 측정 딜레이는 같지 않아요. 네이티브 탐색 경계가 계단식으로 갱신돼 관측값이 변할 수 있으므로, 보정한 시계·오래된 관측·버퍼 가용 범위를 구분해요. 측정 대기에서 저장값을 현재 측정값처럼 표시하거나 목표를 반복 저장해 드리프트를 누적시키지 않아요.

## 스트림 정보의 관측 경계

스트림 정보의 현재 방식은 설정이나 과거 저지연 적용 결과로 알 수 없어요. 읽기 전용 MAIN 조회와 제어 래퍼 설치를 나누고, 같은 pane에 서로 다른 플레이어 후보가 남는 교체 순간에는 진단을 확인 불가로 처리해요. 조회 실패 사이에 새 provider가 나타날 수 있으므로 마지막 확인된 정체성을 잊고 이전 방송 자료를 합치지 않아요.

네이티브 탐색 끝은 계단처럼 갱신돼요. 공용 라이브 끝 계산은 경계의 전진과 갱신 주기를 관측한 뒤 보정하며, 소스 변경·역행·오래된 관측에서는 다시 준비해요. 스트림 정보는 단조 시계로 60초 창을 계산해요. 정기 표본 간격이 3초를 넘으면 그래프와 프레임 기준선을 끊으며, 그 사이 미디어 이벤트로 실제 관측한 시간·대기 상태는 보존해요. 실제 관측이 끊긴 시간은 연속 재생으로 세지 않아요. 현재 위치를 포함하는 버퍼만 사용하며, 읽지 못한 범위와 유효한 빈 버퍼 0을 구분해요.

`playing` 이벤트 자체는 실제 진행 재개의 증거가 아니에요. 스트림 정보는 `waiting` 뒤 미디어 시간의 비진행과 기본 0.5초 기준을 확인하고, 실제 진행 재개 시점까지 이어진 확인 후보도 평가해요. 프레임 차분 기준은 정기 표본에 두어 같은 시각의 미디어 이벤트가 먼저 와도 유효한 차분을 잃지 않게 해요. 제외 구간·카운터 역행·소스 교체를 가로지르는 프레임은 버려요.

메타데이터 도착과 화면 재그리기가 새 측정 표본을 만들면 지연 시계·FPS 기준이 흔들릴 수 있어요. 1초 표본 수집, 미디어 이벤트 입력, 보관된 결과의 표시를 구분해요. 같은 방송의 영상 교체는 새 live-detail 정체성을 확인해 자료를 보존하고, 확인 실패는 패널을 닫는 대신 새 측정으로 처리해요. 영상 전환·광고 직후에는 이전 방식을 현재 값처럼 다시 표시하지 않아요.

## 컴프레서의 기본 선택과 탭 정리

새 탭의 기본 선택과 이미 등록된 탭의 스냅샷은 다른 자료예요. 처음 상속한 값도 탭에 저장하지 않으면 다른 탭의 명시 조작 뒤 새로고침에서 선택이 바뀌어요. get과 자동 재부착은 마지막 선택을 갱신하지 않고, 명시 조작은 현재 탭과 기본 선택을 같은 성공 저장 경계로 확정해요. 구형 배열의 끝은 마지막으로 남아 있는 선택일 뿐 이미 닫힌 탭의 마지막 조작은 아니에요.

get은 읽기와 탭 스냅샷 등록을 함께 수행해요. 문서 시작에 무조건 호출하면 홈·전체 방송·카테고리 목록에서 꺼짐이 미리 고정되고 이후 첫 방송에서 최신 선택을 놓칠 수 있어요. 옵션 준비와 기능 활성화 뒤 첫 재생 경로에서 조회를 시작하고, 진행 중인 조회는 공유해요. 복원 완료 후 목록 왕복·다른 방송 이동은 같은 탭 선택을 유지하며, 문서 종료 뒤 늦은 응답은 UI·오디오 그래프를 다시 연결하지 않아요. 목록 단계 미등록·첫 진입 상속·기존 선택 보존은 실제 worker와 페이지를 연결한 회귀로 확인해요.

브라우저 시작 정리의 대기를 워커 메모리에만 두면 정리 실패 뒤 워커 재생성에서 이전 세션 탭 ID가 다시 읽혀요. 정리 전에 확장 session에 대기를 저장하고, 사용할 수 없거나 저장 실패하면 별도 local 제어값만 남겨요. 구형 선택을 확보한 뒤 탭 ID를 비우고 대기 해제까지 성공한 다음 새 스냅샷을 받아요. 늦은 읽기·쓰기와 시작 신호는 세대와 같은 전용 큐로 확인해요.

확장 session은 일반 워커 재시작에 남지만 브라우저 재시작·확장 재로드·업데이트에는 지워져요. 따라서 session 마커 부재만으로 정상 재로드의 탭 선택을 비우지 않아요. session/local 양쪽에 대기를 저장하지 못한 전체 저장 장애는 실패 응답이며, 그 상태에서 워커가 사라지면 저장하지 못한 대기를 복원할 수 없어요. 일반 worker 재시작과 확장 재로드는 다른 수명 경계예요. 이 구분은 [Chrome storage API](https://developer.chrome.com/docs/extensions/reference/api/storage)의 저장 수명과 맞춰요.

## 옵션 초기화와 늦은 읽기

업데이트에서 새 집계 설정을 초기화할 때 옵션 페이지의 명시 저장과 겹칠 수 있어요. 워커와 옵션 페이지는 같은 확장 origin의 Web Lock을 저장 콜백 완료까지 공유해요. 이 잠금은 사이트 origin에서 실행되는 콘텐츠 스크립트의 저장 직렬화를 뜻하지 않아요. 초기 설정 읽기 도중 저장 변경이 도착하면 해당 키의 변경값을 늦은 읽기 결과보다 우선해요.

옵션 카드를 합칠 때 이전 값이 없는 출처를 모두 접힘으로 보면 당시 기본 펼침 선택이 사라져요. 새 ID의 boolean 선택을 먼저 읽고, 이전 선택이 하나라도 유효할 때만 나머지 출처의 당시 기본값을 함께 해석해요. 이전 값이 전혀 없을 때의 새 설치 기본값과 구분하며 자동 복원값은 저장하지 않아요.

검색으로 임시로 펼친 카드와 직접 고른 상태를 분리해요. 늦은 저장소 응답은 검색 전 상태에 반영하되 검색 중 표시나 이미 처리한 직접 조작을 되돌리지 않아야 해요. 비동기 toggle 이벤트가 오기 전 검색·pagehide가 이어지는 경우도 확인해요. 통합 카드의 정적 소제목은 다음 소제목 전의 입력·도움말과 연결해야 숫자 설정을 검색해도 제목·상위 토글을 함께 찾을 수 있어요.

## 조회 취소·캐시

검색과 집계는 같은 전체 방송 페이지 요청을 공유하므로 한 기능의 OFF를 전체 repository 초기화로 처리하면 다른 기능도 끊겨요. 소비자를 따로 취소하고 마지막 소비자가 없어질 때만 진행 요청을 중단해요. 집계로 읽은 연속 페이지를 검색 메타데이터에 반영하지 않으면 검색 가능한 방송 수가 줄어들 수 있어요. 완료 집계 캐시가 만료됐을 때도 이전 메타데이터를 새 시각으로 재확정하지 말고 유효한 공유 페이지나 새 조회를 사용해요.

캐시 응답은 공유 중인 검색 Promise의 정리보다 먼저 이어질 수 있어요. 검색이 진행 중이라는 이유로 집계 페이지 병합을 모두 건너뛰면 중간 페이지와 이후 검색 결과가 빠져요. 요청이 시작한 페이지 위치로 중복 반영만 막고 연속 자료를 보존해야 해요. 검색을 끌 때도 기존 검색의 비동기 대기를 표시 갱신과 묶으면 집계 진행 안내가 사라지므로, 집계 전용 표시는 응답을 기다리지 않고 유지해요.

공용 DOM 예약 함수의 `cancel()`은 timeout·RAF를 해제하고 예약 세대를 바꿔요. 취소한 콜백을 뒤늦게 실행하는 fixture에서도 새 예약 상태를 건드리지 않아야 해요. 전체 방송 toolbar는 사이트가 확장 요소만 직접 제거할 수도 있으므로, 자체 삽입과 외부 제거의 관찰 조건을 구분해요.

`fetchJson`은 내부 타임아웃과 외부 취소 모두에서 AbortError가 나올 수 있어요. 분할 VOD 보조 상세 조회가 타임아웃 난 경우와 사용자가 라우트를 떠난 경우를 오류 이름만으로 구분하면 정상 시계·달력까지 사라질 수 있어요. 외부 signal 상태를 확인하고, 확인된 현재 상세로 가능한 계산과 전체 작업 취소를 나눠요.

월간 통계의 평균 계산과 달력 계산은 조회 페이지를 공유하지만 종료 날짜·페이지 상한은 달라요. 평균의 범위를 늘려 달력을 맞추거나 달력 비활성화 뒤에도 먼 과거 조회를 계속하면 불필요한 요청이 생겨요. 공유 요청·각 소비자의 취소·부분 조회 표시를 함께 검증해요.

영상 검색 인덱스의 부분 결과와 완료 캐시는 다른 상태예요. 첫 조회가 실패했는데 결과 일부를 완료로 캐시하면 다음 검색에서도 회복하지 못해요. 취소된 댓글 응답이 초기화된 인덱스에 다시 쓰이지 않는지도 확인해요.

VOD 댓글의 prefetch와 사용자가 연 첫 페이지는 같은 진행 중 요청을 공유해요. 숨은 prefetch 실패를 사용자 오류로 즉시 노출하거나 탭을 열 때 중복 조회하지 않아요. VOD·정렬·세대가 바뀐 뒤 이전 응답을 버리는지 확인해요.

## 카테고리 제외의 정체성과 늦은 상태

카테고리 이름은 표시 자료이며 제외의 정체성이 아니에요. 같은 이름의 다른 유형·ID와 이름이 바뀐 같은 유형·ID를 구분해요. 공식 공개 링크는 categoryType을 그대로 사용하고 현재 HTTP 목록에도 `GAME`이 있으므로 이름 정규화나 ID의 소문자 변환을 식별 비교에 재사용하지 않아요. 현재 원본 카드 링크가 오래된 API 값보다 우선하며, 링크가 없거나 충돌하면 이름으로 대신 숨기지 않아요.

확장 추가 카드는 네이티브 템플릿의 카테고리 링크를 복제할 수 있어요. 현재 메타데이터로 링크·이름을 바꾸고 WeakMap의 채널·liveId 결합을 확인해요. 후보 단계부터 id·channelId의 일치와 양의 안전한 정수 liveId를 확인하며, 결측·0·음수·불안전한 값은 카테고리만으로 제외하지 않아요. 원본의 현재 링크 판정은 메타데이터의 liveId 결측과 독립이에요. 원본 `href` 변경은 재판정하되 확장 소유 링크 쓰기가 다시 전체 적용을 예약하지 않아야 해요. 행 순회가 화면에 실행 시간을 양보하는 동안 정체성이 바뀔 수도 있어 최종 표시 직전에 다시 판정해요. 이전에 보이던 시청자 필터 행도 카테고리 제외를 우회하지 않아요.

목록 전체를 콘텐츠에서 저장하면 두 탭의 선택을 덮을 수 있어요. 전용 워커 큐에서 최신 local을 읽어 개별 추가·해제만 수행하고 저장 콜백의 lastError를 즉시 확인해요. 초기 읽기·변경 응답·onChanged의 순서가 뒤집히면 revision으로 오래된 응답을 막아요. 실제 키 삭제는 revision 0 복원과 별개로 이전 저장 요청 세대를 무효화해야 삭제 전 응답이 화면을 되살리지 않아요. 손상·읽기 실패를 빈 상태로 저장하지 않아요.

OFF·다른 경로에서 구독을 쉬는 동안 키가 삭제·재생성되면 새 저장값의 revision은 이전 메모리보다 작을 수 있어요. 마지막 정상 목록은 읽기 오류 대비로 남기되 새 구독의 첫 정상 읽기·통지부터 revision 기준을 다시 세워요. 구독 함수의 정체성을 읽기·변경 응답·통지·finally에서 확인하고 제거한 구독의 콜백을 다시 활성화하지 않아요. 손상 통지도 읽기·변경 세대와 pending 소유를 해제해야 옛 정상 응답이 최신 오류를 지우거나 재시도 버튼을 잠그지 않아요.

DOM 준비는 저장 옵션 확인과 다른 시점이에요. 공용 옵션 변경 callback은 최초 읽기가 진행 중일 때도 기본값과 변경분을 전달할 수 있어요. 카테고리 기능은 별도의 최초 getOptions callback에서 준비 상태를 열고 그 전에는 일반 변경 callback을 적용하지 않아요. 공용 진행 조회를 함께 사용해 실제 옵션 저장소 조회는 한 번만 실행해요. 실제 settings·content 초기화 코드를 연결해 DOM 준비·관련 없는 sync 변경이 먼저 와도 제외 읽기·구독이 없고, 확인 후 집계만 켜거나 기능을 켰을 때의 동작을 검사해요.

카드용 setText는 빈 값을 쓰지 않으므로 상태 안내에 그대로 쓰면 성공·입력 지우기 뒤에도 이전 로딩·오류 문구가 남아요. 카테고리 상태 안내는 빈 문자열도 갱신하되 카드 표시용 동작은 유지해요. 정상 읽기·저장 통지와 검색 성공 후 오류·로딩 문구가 실제 DOM에서 사라지는지 확인해요.

이름 검색의 300ms 입력 대기·한글 조합·입력 변경·메뉴 닫기·SPA·OFF는 검색 세대와 취소를 함께 갱신해요. 실패·타임아웃과 정상 빈 결과를 구분하며 실패 Promise를 완료 캐시로 남기지 않아요. 검색어·결과 캐시는 최대 20개 검색어·5분의 문서 메모리에만 두고 지속 선택 저장과 섞지 않아요. 메뉴가 닫히거나 교체돼도 이미 보낸 개별 변경은 워커에서 끝날 수 있으므로 이전 메뉴를 다시 만들지 않아요.

워커는 sender.url의 정확한 `/lives`를 확인해요. 합성 발신자 검사 통과는 홈에서 SPA로 진입한 실제 Chrome 문서의 발신 URL까지 확인한 결과가 아니에요. 이름 검색의 HTTP 200·허용 Origin·인증 허용 헤더도 실제 콘텐츠 요청의 CORS·기존 로그인 세션 성공을 증명하지 않아요. 실제 주입·카드 링크·키보드 기본 클릭·테마와 재시작 복원은 별도 화면 확인으로 남겨요.

## 팝업·배너·테마

같은 팝업 DOM이 숨겨졌다가 다시 나타나면 ‘이미 처리한 노드’ 캐시만으로 새 표시 주기를 놓칠 수 있어요. 반대로 확장이 잠깐 숨긴 marker 변화를 새 표시로 판단하면 무한 클릭할 수 있어요. 네이티브 숨김 속성과 확장 소유 표시를 분리하고, 닫기 실패 시 다음 프레임에 안내가 복원되는지 확인해요.

같이보기의 숨겨진 상단 배너 높이가 제목의 sticky top에 남으면 검색 헤더와 제목 사이에 빈틈이 생길 수 있어요. 현재 작성 중인 보정은 실제 헤더의 아래쪽 좌표를 사용해요. 과거 관측 51px·60px을 상수로 바꾸지 않아요. JSDOM의 CSS var() 우선순위 검사와 실제 픽셀 렌더링 검증은 별개예요.

검색 UI의 네이티브 색을 복사할 때 선택된 정렬 버튼을 표본으로 잡으면 라이트 모드에서도 검은 바탕이 생길 수 있어요. 비선택 버튼과 실제 테마 상태를 확인하고, 선택 변경·테마 전환·DOM 교체 뒤 다시 동기화해요.

## 패널 너비와 실제 가용 공간

2026-09-28 관측에서 펼친 사이드바는 240px이고 본문 padding-left도 240px이었지만, 1200 CSS px 미만에서는 240px 사이드바가 82px 본문 여백 위를 덮었어요. 너비만 보고 펼침을 판별하면 겹침 배치까지 넓히므로 메뉴의 펼침 상태·같은 부모·대응 여백을 함께 확인하고 좁은 화면에서는 너비 지정을 해제해요. 넓은 화면은 사이드바 노드가 사라져도 본문 padding이 남을 수 있지만 플레이어 행은 x=0에서 시작했어요. 남은 padding만으로 사이드바 공간을 새로 만들지 않아요.

VOD의 영상·채팅 부모 폭은 실제 스크롤바 공간을 제외해요. viewport 폭 전체로 계산하면 오른쪽 영역이 넘칠 수 있으므로 부모 rect·문서 clientWidth·실제 사이드바 점유 폭을 사용해요. 채팅·댓글 외곽만 조절하고 아래 방송 정보 열이나 배너의 transform·top·height는 보정 대상에 포함하지 않아요.

ResizeObserver는 같은 노드를 매번 다시 observe해도 초기 통지를 예약해요. 너비 갱신 뒤 관측 대상을 무조건 재설치하면 스스로 반복되므로 관측 노드 집합이 바뀔 때만 갱신해요. 두 영역이 이미 줄어든 화면에서 한쪽 조작을 확정한 직후 다른 쪽의 저장 희망 너비로 재분배하면 방금 놓은 경계가 튀어요. 같은 기하에서는 확정한 표시 조합을 유지하고, 가용 공간·표시 상태가 바뀔 때 저장 선택으로 다시 계산해요. observer 통지 반복과 확정 직후 표시를 각각 회귀 검사해요.

너비를 프로필 local에 저장해도 열린 문서에 다른 탭의 선택을 즉시 적용하지 않는 정책이에요. BFCache 복귀·OFF/ON에서 다시 읽으면 현재 문서 선택이나 저장 실패 뒤 남긴 조작을 덮으므로 새 문서 초기화에서만 읽어요. 두 패널을 한 객체로 쓰면 오래된 문서가 상대 패널의 최신값을 되돌릴 수 있어 각 키만 저장해요. 현재 화면이 기본 너비여도 더블클릭은 명시 초기화이므로 null을 저장해야 다른 탭의 사용자 지정이 새로고침 뒤 나타나지 않아요.

경계의 ::after 선과 focus outline을 함께 쓰고 드래그 시작 때 focus를 강제하면 강조가 겹칠 수 있어요. 마우스 전용 경계는 focus를 옮기지 않고 hover·drag의 선 하나를 공유해요. 다른 입력의 focus 스타일은 유지해요. 실제 Chrome의 선 개수는 DOM·스타일 회귀만으로 확정하지 않아요.

마우스 전용 드래그가 터치·펜 pointerdown을 거절해도 뒤따르는 호환 dblclick은 button 0일 수 있어요. 초기화는 핸들의 마지막 pointerdown 출처까지 확인하고, 터치·펜이 오면 이전 마우스 이력을 무효화해요. 양쪽 영역에서 거절 입력 뒤 더블클릭이 저장값을 지우지 않는지 검사해요.

저장 실패 뒤 경계를 움직였다 제자리로 놓으면 같은 값의 명시 재저장이 필요해요. 포인터가 RAF 사이에 왕복하면 렌더링 시 좌표만으로는 조작 여부를 놓치므로 pointermove에서 이동 사실을 기억해요. 오래된 저장 성공 콜백이 최신 실패 선택의 재저장 가능 상태를 지우지 않는지도 확인해요.

열린 팔로잉 미리보기는 창 resize가 없어도 사이드바 너비 변경으로 기준 행의 끝이 이동해요. 열린 동안 기준 행 크기를 관찰해 위치만 갱신하고 닫을 때 관찰을 해제해요. 전역 resize 이벤트를 인위적으로 반복하거나 미리보기 재생을 다시 시작할 필요는 없어요.

## 백업의 원본·삭제 범위

시청 화면은 세션을 합치고 구간을 중복 제거해 표시해요. 그 결과를 파일로 저장하면 원본 세션 ID와 과거 잔여 합계를 잃으므로 백업은 writer가 저장한 원본을 허용 필드로 투영해요. 총초의 내림과 일별초의 반올림 차이는 정상일 수 있지만, 같은 세션을 합친 구간이 누적 시청량을 크게 넘으면 충돌이에요. 구형 다시보기 번호·세션 시각·방송 URL의 지원 표현도 내보내기 변환에서 보존해야 해요.

이미 보관된 구간에는 여러 2초 이하의 틈이 합쳐질 수 있고 그 횟수는 저장하지 않아요. 파일 하나의 구간 길이를 누적초와 직접 비교하는 임의의 고정 오차 제한은 정상 원본을 거부할 수 있어요. 시각 범위·날짜·절대 스냅샷의 검증 가능한 관계를 검사하고, 두 스냅샷을 합칠 때 새로 생긴 구간 증가와 원래 있던 틈은 구별해요.

기존 임시 ID 연결 계산은 잔여 합계를 더하므로 백업의 반복 병합에 그대로 쓰지 않아요. 상세로 중복을 증명하지 못한 기존 방송은 보존하고 건너뛰어요. 후원과 채팅의 기존 정리 시점이 공유돼 있었으므로 복원한 채팅의 경계를 후원에 적용하면 늦은 정상 후원을 막을 수 있어요. 별도 채팅 경계를 유지하고 내보내기도 그 값을 읽어요.

방송 전체에 복원 시각 하나를 붙여 삭제 예외로 만들면 파일에 없던 오래된 세션·후원까지 남아요. 명시 복원 범위만 보관하고 일반 삭제 전파 결과에 그 범위만 합쳐야 해요. 일반 자료가 모두 사라진 경우에도 복원된 표시 메타데이터와 대상의 더 높은 퇴역 장벽은 보존해요. 상세가 설명하는 날짜를 자정으로 다시 판정하면 당일 삭제 이후의 새 세션을 복원으로 오표시하므로 실제 시각을 우선해요.

임시·정식 ID를 연결할 때는 각 복원 범위의 시각을 유지해요. 시각을 하나로 합치면 중간 삭제보다 오래된 자료까지 보호하거나 나중에 복원한 자료를 잃을 수 있어요. 백업 불러오기에서 여러 기존 행의 구형 합계는 숫자가 같아도 같은 자료라는 근거가 아니므로 합치지 않아요. 동일 정식 방송을 다시 불러올 때 시청 전체가 포함됐다는 이유로 미포함 채팅의 보호 시각까지 갱신하지 않으며, 반대 방향도 같아요. 시청과 채팅의 범위 갱신을 독립적으로 판단해요.

워커가 검증한 파일 크기는 compact JSON 기준이에요. 다운로드에서 들여쓰기를 추가하면 큰 파일이 입력 상한을 넘어 자기 백업을 다시 읽지 못할 수 있어요. compact 파일을 사용하고 실제 파일 대화상자·다운로드 완료는 자동 DOM 검사와 별도로 확인해요.

## 검증 결과를 해석할 때

기본 `npm.cmd test`는 개발 전용·실측 자료 테스트를 모두 포함하지 않아요. 전체 확인은 `test:all`이에요. JSDOM 통과는 실제 Chrome 확장 주입·네트워크·미디어 디코딩·시각 배치 검증을 대신하지 않아요.

브라우저의 전체 CPU·RAM 표본과 특정 데이터 구조의 Node 힙 벤치마크는 다른 측정이에요. 다른 탭·전경 전환·디코더·GPU 영향이 분리되지 않은 표본으로 확장의 순증 부하나 누수를 확정하지 않아요. 합성 fixture 캐시 정리 결과도 실제 사용자의 검색어 삭제와 같은 동작이 아니에요.

GitHub 인증은 샌드박스 네트워크 차단 때문에 유효한 토큰도 invalid로 표시될 수 있어요. 먼저 네트워크가 허용된 실행에서 `gh auth status --hostname github.com`과 `gh api user --jq .login`을 확인해요. 401 또는 Bad credentials가 확인될 때만 토큰 무효로 판단하며 DNS·소켓·권한 오류만으로 로그인·로그아웃·재발급을 하지 않아요.

## 새 기능 안내의 경쟁과 설정 링크

표시 예약과 표시 승인은 달라요. claim의 token이 있어도 아직 show:false이며 commit에서 소비 기록을 저장한 뒤의 show:true만 UI를 열 수 있어요. 저장 직후 응답을 잃으면 중복 표시를 피하려고 자동 재시도하지 않아요. 이미 예약한 문서가 숨겨졌다면 미소비 토큰만 반환하고 늦은 응답이 새 UI를 만들지 않게 세대를 확인해요.

OFF 억제 저장이 실패한 뒤 ON 또는 워커 재시작이 이어지면 pending이 남을 수 있어요. 현재 워커의 억제 기억과 onChanged의 oldValue:false를 사용해 ON에서도 정상 pending의 억제 저장을 재시도해요. 읽기 실패를 빈 상태로 덮어쓰지 않아요.

options.html에 안내 목적지 hash가 붙으면 문자열 전체로 발신자를 비교하던 광고 등록·방송 등록이 실패해요. 정확한 확장 페이지와 허용한 hash만 확인하는 공용 검증을 사용해요. 대상 그룹을 안내로 펼친 뒤 늦은 저장 상태 읽기가 다시 접지 않게 현재 조작 상태도 표시해요.

뒤로 가기 캐시에 들어가는 persisted pagehide는 일반 종료와 달라요. 안내 UI·타이머·이전 요청 세대만 정리하고 수신·옵션·라우트 구독을 보존해요. persisted pageshow에서 옵션을 다시 읽고 미소비 안내만 재개하며 이미 소비한 자동 알림은 복원하지 않아요. 일반 종료·명시 stop 뒤에는 복귀 신호로 기능을 되살리지 않아요.
