## fixture 수명주기와 대기

- 옵션 페이지의 모든 JSDOM을 `t.after`로 종료한다.
- 확장 페이지 fixture를 추적하여 테스트별 정리를 보장한다. 개별 기능 teardown 후 남은 창을 닫으며, 닫기 전에 생성한 MutationObserver를 disconnect한다.
- follower hydration 테스트는 요청 시작만 확인하고 끝날 수 있어, 기능 비활성화/취소를 먼저 수행한 뒤 창을 닫도록 보완했다. 이 정리가 없으면 닫힌 JSDOM의 location에 접근하는 늦은 작업이 발생하는 것을 확인했다.
- 월간 통계 remount의 120ms 대기와 광고 remount 성공의 200ms 대기를 관측 가능한 상태의 조건 대기로 바꿨다.
- 광고 비활성화 뒤 재연결이 없음을 확인하는 200ms 구간, 채팅의 혼합 DOM 안정화·feedback loop 및 비활성화 같은 부정 검증 구간은 유지했다. 단순히 대기 시간을 줄여 이 검증들을 조기에 통과시키지 않았다.
- 전체 테스트 파일에서 JSDOM 생성과 종료 사용처를 검색했다. 별도 생성자가 있는데 종료 호출이 전혀 없는 테스트 파일은 없었다. 모든 기존 비동기 fixture를 전면 개편한 것은 아니다.

## 실행 명령

- `npm.cmd test`: 기본 `tests/*.test.js`.
- `npm.cmd run test:development`: 미공개 기능 동작 검사.
- `npm.cmd run test:evidence`: 실측 자료 검사.
- `npm.cmd run test:all`: Node의 기존 자동 탐색으로 위 범주를 모두 실행한다. 전체 검증에는 이 명령과 lint/format:check를 사용하도록 AGENTS.md를 갱신했다.

| format      | `npm.cmd run format:check` 통과 | 같은 명령 통과                        |

분리 명령도 각각 실행하여 기본 576/576, 개발용 10/10, 자료용 2/2 통과를 확인했다. 기본 실행 결과에는 분리한 12개가 포함되지 않고, 전체 실행에는 모두 포함된다. 전체 테스트 출력에서 미처리 rejection과 테스트 종료 후 비동기 오류는 없었다. `git diff --check`도 통과했다.

총수는 자체 상수 검사·중복 low-risk 묶음 2개를 제거하고 동작 검사 6개를 추가하여 584 → 588이다. optimization 묶음은 별도의 wildcard 스캔 금지 정책과 위 동작 검사들로 대체했고, 옵션 레이아웃 검사는 이름과 assertion을 교체했다. 전후 성공 테스트 이름도 대조하여 이 외 기존 시나리오가 빠지지 않았음을 확인했다. 개수 유지가 아니라 보호 범위 확인을 기준으로 정리했다.

런타임 파일을 디스크에서 변경하지 않고 임시 Node read hook으로 회귀를 주입한 검사도 수행했다. category의 예약 합치기 제거, 주입 후 카드 재스캔 재도입, 배지 중복 동기화, 용량 이하에서도 pruning 열거, 안정된 VOD의 늦은 트랙 알림 재예약을 각각 넣었을 때 해당 동작 검사가 실패하는 것을 확인했다. 임시 hook은 저장소나 npm 명령에 포함하지 않는다.

브라우저 스모크는 수행하지 않았다. 이번 작업은 테스트 정리이며 JSDOM/CSSOM 검증을 실제 레이아웃·확장 주입 검증으로 간주하지 않는다. 향후 옵션 UI 변경 시에는 실제 팝업에서 좁은 너비, 라이트/다크, 긴 한글 문구, 키보드 탐색·포커스를 별도로 확인한다.
