# 치즈 스패너 실행·배포 절차

## 작업 환경 준비

Chrome과 Node.js·npm이 필요해요. package에 별도 engines 범위는 없으므로 최소 버전을 임의로 약속하지 않아요. 2026-09-28 저장소 검증은 Node 24.18.0, npm 11.16.0에서 실행했어요. 아래 명령은 저장소 루트의 PowerShell 기준이에요.

```powershell
git branch --show-current
git rev-parse HEAD
git status --short
git diff --stat
git diff --cached --stat
node --version
npm.cmd --version
npm.cmd ci
```

의존성을 설치한 뒤 검증·패키징 도구를 실행해요. 런타임 번들 생성 단계는 없어요. PowerShell 실행 정책에 걸릴 수 있는 `npm.ps1` 대신 `npm.cmd`, `npx.cmd`를 사용해요. 환경 변수·개발자 서버·API 키 초기화는 현재 실행에 필요하지 않아요. 사용자 데이터는 Chrome이 제공하는 저장소에서 시작하며 별도 시드 데이터나 계정 생성 작업이 없어요.

## 자동 검증

기능 내부의 작은 변경은 해당 기능과 직접 영향받는 기능의 테스트, 변경한 JS의 lint, 변경 파일의 포맷 검사로 마쳐요. 다음은 화면 확대 변경의 예시이며 테스트·파일 목록은 실제 영향 범위에 맞춰 바꿔요. 문서만 바꿨다면 포맷·내용·링크를 확인하고 런타임 테스트는 실행하지 않아도 돼요.

```powershell
node --test --test-concurrency=2 tests/player-zoom.test.js tests/player-zoom-controls.test.js
npx.cmd --no-install eslint features/playerZoom.js tests/player-zoom.test.js tests/player-zoom-controls.test.js
npx.cmd --no-install prettier --check features/playerZoom.js tests/player-zoom.test.js tests/player-zoom-controls.test.js
git diff --check
```

공용 유틸·테스트 helper 변경은 영향을 받는 소비자 테스트까지 넓혀요. 설정 스키마·저장 형식·쓰기 큐·권한·발신자 검증·world·로딩 순서·manifest·의존성·검사 설정 변경, 영향 범위가 불명확하거나 여러 기능을 넓게 바꾸는 작업, 릴리스 전 또는 전체 검사 요청에는 다음 전체 검증을 수행해요.

```powershell
npm.cmd run test:all -- --test-concurrency=2
npm.cmd run lint
npm.cmd run format:check
git diff --check
```

테스트 동시 실행은 최대 2개로 제한해요. 같은 PC에서 테스트 묶음을 여러 개 동시에 실행하거나 테스트·lint·포맷을 겹쳐 실행하지 않아요. 여러 에이전트의 검사도 순서를 조율해요. 전체 검증은 변경을 모은 시점에 한 번 수행하고, 이후에는 새 변경·실패·미해결 우려의 영향을 받는 검사만 다시 실행해요. 선택한 검사 범위와 전체 생략 이유를 결과에 남겨요.

`npm.cmd test`는 공개 기능·공용 유틸·확장 페이지·배포 안전의 기본 범위예요. `test:development`는 개발 전용 기능, `test:evidence`는 저장한 실측 자료 검증이고 `test:all`은 셋을 함께 탐색해요. 이 명령으로 실행할 때도 `-- --test-concurrency=2`를 붙여요. 실측 자료 테스트는 오늘의 외부 API를 호출해 확인하는 검사가 아니에요.

전체 포맷 실패가 기존 범위 밖 파일 때문이면 실패 원인을 보고하고 변경 파일만 `npx.cmd --no-install prettier --check <변경한 파일들>`로 확인해요. 전체 자동 포맷 명령을 수정 수단으로 먼저 사용하지 않아요.

## Chrome에서 실행

1. Chrome 확장 관리의 개발자 모드를 켜고 저장소 폴더를 압축 해제된 확장으로 로드해요.
2. 기존 확장을 사용 중이면 해당 확장을 다시 로드한 뒤 대상 치지직 탭을 새로고침해요. 광고 동적 스크립트는 새 문서 초기 주입 여부도 확인해요.
3. 실제 확장 ID, 실행 context, 대상 기능의 DOM 마커와 UI가 일치하는지 확인해요. 확장 폴더·버전을 잘못 로드한 상태에서 성공을 기록하지 않아요.
4. 필요한 기능만 켜고 저장해요. 미리보기·멀티뷰의 CDN 선택 권한과 데스크톱 알림 권한은 승인·거부·이미 승인된 경우를 나눠 확인해요.

화면 자동화는 브라우저 도구로 진행해요. 도구가 확장 관리나 확장 페이지를 차단하면 우회하지 말고 사용자가 직접 해야 하는 단계와 미검증 범위를 보고해요. 컴퓨터 사용 도구는 다시 명시적으로 요청받기 전에는 사용하지 않아요.

## 배포 준비

버전 변경·커밋·push·태그·Release·스토어 제출은 사용자가 해당 작업을 명시적으로 요청한 경우에만 진행해요. branch 이름에서 manifest 버전을 자동 추정하지 않아요. 현재 branch가 다음 버전 이름이어도 manifest·package가 이전 배포 버전인 개발 상태일 수 있어요.

버전을 변경했다면 manifest·package 및 lockfile의 루트 버전 정합성을 확인하고, 최종 사용자 동작 차이로 README·업데이트 내역·필요한 개인정보·서드파티·스토어 문구를 준비해요. 검증과 패키지 검사가 끝난 뒤 요청받은 공개 동작을 수행해요.

요청받은 버전으로 값을 정한 뒤 다음 명령을 사용할 수 있어요.

```powershell
$releaseVersion = (Get-Content -Raw manifest.json | ConvertFrom-Json).version
npx.cmd --no-install web-ext build --config web-ext-config.mjs --filename "cheese_spanner-$releaseVersion.zip"
```

같은 이름의 기존 ZIP을 임의로 덮어쓰지 않아요. ZIP 안의 manifest와 실제 파일 목록·바이트를 작업 트리와 대조해요. 정적 참조 파일, 동적 광고 스크립트, 라이선스·폰트가 포함됐는지 확인하고 개발 의존성·테스트·작업 문서·미공개 광고 SKIP 코드·로컬 백업이 들어가지 않았는지 확인해요. build 명령 성공만으로 배포 내용 확인을 대신하지 않아요.

GitHub Release를 요청받은 경우에만 업데이트 내역과 맞춘 본문으로 생성해요. 스토어 업로드·심사 제출 여부는 별도로 보고해요. 새 권한이나 데이터 처리가 바뀌면 설치·업데이트 경고와 고지도 다시 확인해요.

## 버전별 안내 준비와 릴리스 전 필수 점검

1.4.1부터 버전을 올리는 릴리스에는 shared/updateGuide.js에 해당 버전의 제목·요약·주요 기능 카드를 함께 작성해요. 사용법이 없는 수정 릴리스는 빈 cards와 짧은 요약을 사용할 수 있어요. update-guide-catalog 회귀가 현재 릴리스의 자료 누락을 검사해요. manifest·package의 버전 변경은 별도 승인 범위예요.

새 설치·동일 버전 재로드는 자동 안내 발생 시험이 아니에요. 자동 회귀는 가상 설치 이벤트로 1.4.0→1.4.1과 다중 문서를 확인해요. 실제 표시 확인은 분리된 검증 프로필에서 실제 상위 버전 업데이트와 새 치지직 문서로 진행하고 사용자 안내 상태를 임의로 초기화하지 않아요. 1.4.0 개발 manifest에서는 1.4.1 안내가 자동·수동 노출되지 않는 것이 정상이에요.

아래 점검은 **매 버전 릴리스 준비 완료 보고·릴리스 제안·승인 요청 전에 반드시 완료**해요. 이미 릴리스 요청을 받은 경우에도 공개·스토어 제출 전에 먼저 점검해요. 안내 코드를 바꾸지 않았거나 오류 수정만 있는 버전이라는 이유로 생략하지 않아요.

- [ ] **버전과 내용:** 승인된 릴리스 대상 버전과 manifest·package·lockfile 루트 버전, 안내 자료의 버전이 일치해요. 안내의 주요 기능·사용법·설정 위치를 최종 코드와 업데이트 내역에 대조하고 이전 버전 문구·미출시 기능·잘못된 경로를 남기지 않아요. 기능 카드가 필요 없는 버전은 실제 변경의 짧은 요약을 제공해요.
- [ ] **자동 검증:** 안내 자료·컨트롤러·뷰·런타임·옵션·기존 공지 정리의 관련 검사와 전체 test:all·lint·format:check·diff 검사를 통과해요. 새 설치·동일 버전·브라우저 업데이트·다운그레이드의 새 자동 안내 제외, 여러 버전 건너뛰기, 오류·OFF 경합·워커 재시작·페이지 복원 회귀를 확인해요.
- [ ] **실제 업데이트와 최초 1회:** 분리된 Chrome 검증 프로필에서 직전 배포 버전 → 릴리스 대상 버전으로 실제 업데이트해요. 실행 중인 확장 버전·주입·UI를 확인하고 새 치지직 문서에 안내가 나타나는지 확인해요. 여러 탭 중 한 탭에만 표시되고 닫기·시간 종료·새로고침·다음 방문·페이지 복원 뒤 같은 버전 안내가 다시 나타나지 않아요.
- [ ] **20초와 시청 방해 방지:** 작은 안내가 표시 시간 20초 뒤 닫히고 상단의 얇은 게이지가 남은 시간을 보여줘요. 호버·내부 키보드 초점 동안 게이지와 타이머가 함께 멈췄다가 남은 시간만 이어가요. 이미 표시한 안내는 다른 창·탭으로 옮겨도 유지하고 자동 타이머와 게이지는 문서가 다시 보이고 초점을 얻을 때 남은 시간만 이어가요. 자동 안내와 다시보기 모두 같은 20초 게이지를 쓰고, 다시보기 후 옵션 팝업이 닫혀 초점이 돌아오면 타이머가 시작되는지 확인해요. 동작 줄이기에서는 1초 단위 표시를 확인해요. 숨김·비활성 탭·전체화면·입력 중에는 새 자동 안내를 표시하지 않고, 영상 중앙·컨트롤·채팅 입력을 가릴 공간에서는 보류해요. 재생·소리·스크롤·입력 초점을 자동으로 바꾸지 않아요.
- [ ] **한 창 안내와 다시보기:** 현재 버전의 소개 항목이 페이지 넘김 없이 함께 표시되는지, 닫기 버튼 하나와 안내 내부 Escape가 동작하는지 확인해요. 1.4.1은 크기 조절·시청기록 백업 두 항목, 1.4.2는 `카테고리 제외` 한 항목과 `전체 방송 탐색에서 사용. 우측 + 제외 추가. 방송 목록 검색·필터를 켜야 작동.` 한 줄만 표시하고 스트림 정보·이전/다음·별도 상세/설정 이동 버튼·위치 강조는 표시하지 않아요. 자동 안내 OFF에서도 치지직의 확장 팝업에서 다시보기를 누르면 치지직 페이지에 표시되고, 옵션 팝업을 닫아도 안내가 남아야 해요. 연결 실패·다른 사이트·별도 옵션 탭에서 옵션 내부 안내로 대체하지 않아야 해요. 미저장값이 있는 팝업은 자동으로 닫지 않고 선택 탭을 보존해요. 라이트·다크·좁은 폭·긴 한글·키보드와 SPA·뒤로 가기 복귀에서도 확인해요.
- [ ] **배포 파일:** 실제 배포할 ZIP에 대상 버전의 안내 자료·워커 컨트롤러·공용 뷰·콘텐츠 런타임·옵션 연결과 참조 목록이 빠짐없이 들어 있고 검증한 소스와 일치해요. 이전 공지 템플릿이나 개발용 미리보기를 실행 진입점으로 넣지 않아요.
- [ ] **검증 기록:** `docs/release-<version>-verification.md`에 대상 버전·소스 기준·명령과 종료 코드·실제 Chrome 확인 날짜/환경/결과·배포 파일 확인 결과를 기록해요. 사용자 수동 확인을 근거로 삼으면 확인받은 항목과 결과를 구분해 적어요. 과거 버전의 통과 기록을 이번 결과로 복사하지 않아요.

미완료·실패 항목이 하나라도 남으면 릴리스 준비 완료로 보고하거나 공개·제출하지 않아요. 브라우저 접근이나 도구 사용 제한이 있으면 해당 항목을 미검증으로 남기고 필요한 수동 절차를 안내해요. 문서에 체크리스트를 추가한 것, 단순 확장 재로드, 가상 테스트 통과는 실제 릴리스 전 점검 완료를 뜻하지 않아요.
